## 五、明确结论

1. **当前 E2E/集成测试是否正常工作**：核查前**不正常**（挂死 + DI 失败 + 断言与迁移产物脱节，0/6）；本次修复后（`e6df4f30`）**现有 9 个用例全部真实可用**。CI 侧 `integration-tests` job 使用的同一代码路径同样受缺陷 #1/#2/#3 影响——**2026-09-15"全绿"之后该 job 的真实状态存疑，建议人工核对最近几次 run 的 integration-tests job 耗时与结果**（本机无法访问 GitHub API 验证）。
2. **用例是否反映真实用户链路**：现有 9 例为**片段级**跨 BC 验证（事件→建单 / 强删→退款事件 / 归属发货 / 购物车同步），Mock 的仅为跨域 ACL 查询（商品快照等），核心持久化与 MQ 流转真实——定位合理；但**没有任何用例贯穿 F8 定义的四段全链路**，支付→扣库存确认与通知两段完全空白。
3. **前置/清理与环境依赖**：基建（容器随机端口、每测试迁移 + 分布式锁、IAsyncLifetime 清理）设计良好；本次修复的 7 处均为"生产代码演进后测试未跟进"型漂移，建议将 `integration-tests` job 的失败可见性纳入关注（若 CI 长期挂死超时，说明该 job 结果从未被真正消费）。
4. **遗留建议（优先级序）**：① 人工核对 CI integration-tests 最近状态；② 基于 CrossBcIntegrationTestBase 补"支付成功→库存确认→通知"两段跨 BC 用例（F8 收口的最短路径）；③ 前端 Playwright 接入 CI 并补 buyer-app/seller 用例；④ ContainerFixture 镜像 tag 与 compose 全量对齐（含 redis/rabbitmq）。
