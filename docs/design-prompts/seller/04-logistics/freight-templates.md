# 运费模板 - 商家管理后台

## 1. 页面定位
- **所属端**：商家管理后台
- **所属模块**：04-logistics（物流管理）
- **页面类型**：表单页（含列表）
- **目标用户**：卖家（Seller）
- **核心目标**：卖家创建与维护店铺运费模板（计费类型、满额包邮、地区规则），用于下单时自动计算运费。
- **访问入口**：Sider「物流管理 → 运费模板」；URL `/logistics/freight-templates`。
- **实现状态**：✅ 已实现

## 2. 页面布局与信息架构
- **整体布局**：顶部面包屑 + 当前模板摘要卡 + 模板编辑表单（计费类型 + 满额包邮 + 地区规则表格）+ 底部操作栏。
- **关键区域**：
  - 区域 A（面包屑）：首页 / 物流管理 / 运费模板。
  - 区域 B（当前模板摘要卡 `<a-card>`）：展示模板名称、计费类型、状态 StatusTag、最后更新时间；无模板时展示 `<EmptyState>` 引导创建。
  - 区域 C（计费配置 `<a-form>`）：模板名称（1-64 字）、计费类型（`<a-radio-group>`：按重量/按件数/固定运费）、满额包邮阈值（`<a-input-number>` 可空，空表示不包邮）。
  - 区域 D（地区规则表格 `<a-table>`）：可编辑行表格，列含地区编码、首重/首件单位、首价、续单位、续价、操作（编辑/删除）。底部「新增规则」按钮。
  - 区域 E（操作栏）：「启用/停用」开关 + 「保存」主按钮 + 「取消」。
- **响应式断点**：≥1200px 表单与表格全宽；992-1199px 表格横向滚动；<992px 不支持。
- **首屏内容**：模板摘要卡 + 计费配置表单 + 地区规则表格。

## 3. 数据模型与 API 对接
- **主要 API**：

| 方法 | 端点 | 用途 | 鉴权 |
|-|-|-|-|
| GET | `/api/seller/freight-templates/mine` | 查询当前卖家运费模板 | Seller |
| POST | `/api/seller/freight-templates` | 创建运费模板 | Seller |
| PUT | `/api/seller/freight-templates/{id}/rules` | 更新模板区域规则（整体替换） | Seller |
| POST | `/api/seller/freight-templates/{id}/enable` | 启用模板 | Seller |
| POST | `/api/seller/freight-templates/{id}/disable` | 停用模板 | Seller |

- **请求参数**：`CreateFreightTemplateDto` 含 `name`、`type`（Weight/Piece/Fixed）、`freeShippingThreshold?`、`regionRules[]`（地区编码、首重/首件单位、首价、续单位、续价）。`UpdateFreightTemplateRulesDto` 含 `name`、`type`、`freeShippingThreshold?`、`regionRules[]`。
- **响应字段**：`FreightTemplateDto` 含 `id`、`name`、`type`、`freeShippingThreshold?`、`regionRules[]`、`status`（Enabled/Disabled）、`updatedAt`。
- **数据加载策略**：进入页面调用 `GET /api/seller/freight-templates/mine` 加载当前模板；无模板时展示空态引导创建。
- **缓存策略**：不缓存，保证运费规则时效性。

## 4. 交互流程
- **主流程**：
  1. 卖家进入页面 → 调用 `GET /api/seller/freight-templates/mine` → 有模板则回填表单与规则表格，无模板展示空态。
  2. 卖家填写模板名称、选择计费类型、设置满额包邮 → 在地区规则表格中新增/编辑/删除规则行 → 点击「保存」→ 首次创建调用 `POST /api/seller/freight-templates`，已存在调用 `PUT /api/seller/freight-templates/{id}/rules` → `message.success('保存成功')` → 刷新摘要卡。
  3. 卖家切换「启用/停用」开关 → 启用调用 `POST /api/seller/freight-templates/{id}/enable`，停用调用 `POST /api/seller/freight-templates/{id}/disable` → `message.success('已启用/已停用')` → 刷新状态。
  4. 卖家点击「新增规则」→ 表格底部新增空行 → 填写地区编码与计费参数 → 保存时整体提交。
- **分支流程**：
  - 无模板：摘要卡展示 `<EmptyState>`，表单为空可填写，保存时调用创建接口。
  - 计费类型为「固定运费」：地区规则表格隐藏，仅保留满额包邮配置。
  - 停用态模板：买家下单时该模板不参与运费计算，已生成订单不受影响。
- **跨页面流转**：无（单页完成模板配置）。
- **状态机可视化**：模板状态：启用 ↔ 停用（开关切换）；停用态不影响已生成订单。

## 5. 组件清单
- **基础组件**：`<a-card>`、`<a-form>`、`<a-form-item>`、`<a-input>`、`<a-input-number>`、`<a-radio-group>`、`<a-radio>`、`<a-switch>`、`<a-table>`、`<a-button>`、`<a-popconfirm>`。
- **业务组件**：`StatusTag`（见 shared/components.md §1，type="shop"）— 模板状态展示；`IdempotencyButton`（见 shared/components.md §2）— 保存按钮；`EmptyState`（见 shared/components.md §5）— 无模板占位。
- **图表组件**：无。
- **图标使用**：`PlusOutlined`（新增规则）、`EditOutlined`（编辑规则）、`DeleteOutlined`（删除规则）、`SaveOutlined`（保存）。
- **空状态**：`<EmptyState title="暂无运费模板" description="尚未创建运费模板，下方表单可开始配置" />`。

## 6. 视觉规范
- **主色应用**：「保存」主按钮、启用开关激活态使用主色 `#1677FF`。
- **状态色**：启用绿 `#52C41A`、停用灰 `#8C8C8C`（由 StatusTag 映射）；删除规则确认按钮危险红 `#FF4D4F`。
- **间距**：摘要卡与表单间距 `16px`，表单与规则表格间距 `24px`，表格行高 `48px`，操作栏与表格间距 `16px`。
- **字体**：页面标题 `20px` medium，表单标签 `14px` medium，表格 `14px` normal，金额 `14px` semibold。
- **图标尺寸**：操作图标 `16px`，新增规则图标 `16px`。

## 7. 异常处理与边界
- **加载态**：进入页面 `<a-skeleton>` 模拟摘要卡与表格；保存时按钮 loading。
- **空数据**：无模板时摘要卡展示 `<EmptyState>`，表单可用。
- **错误态**：网络错误 `message.error('网络异常')`；403 `message.error('无权限访问')`；保存失败展示后端原因。
- **权限控制**：需卖家登录态；`GET /mine` 后端按当前卖家 ID 过滤，仅返回本店模板。
- **并发与乐观锁**：`PUT /rules` 整体替换区域规则，后端校验模板归属；冲突返回 409，提示「模板已被他人修改，请刷新后重试」。
- **危险操作确认**：删除地区规则使用 `<a-popconfirm>` 确认「确认删除该地区规则？保存后生效。」；停用模板 `Modal.confirm` 提示「停用后新订单将无法使用此模板计算运费，已生成订单不受影响。」

## 8. 验收要点
- [ ] 进入页面正确加载当前卖家运费模板并回填
- [ ] 计费类型切换时表单动态调整（固定运费隐藏地区规则）
- [ ] 地区规则表格支持新增/编辑/删除行
- [ ] 启用/停用开关切换并调用对应端点
- [ ] 保存后刷新摘要卡与状态
- **性能要求**：首屏加载 < 1.5s；保存响应 < 1s；规则表格 >20 行虚拟滚动。
- **可访问性**：表单字段有 `label` 关联；开关有 `aria-label`；删除确认有 `aria-label`；对比度满足 WCAG AA。
