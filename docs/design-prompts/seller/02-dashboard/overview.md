# 工作台概览 - 商家管理后台

## 1. 页面定位
- **所属端**：商家管理后台
- **所属模块**：02-dashboard（工作台）
- **页面类型**：看板页
- **目标用户**：卖家（Seller）
- **核心目标**：卖家进入后台首屏，一眼掌握店铺当日经营核心指标（订单数、销售额、待发货、售后待处理）与近期趋势。
- **访问入口**：登录后默认首页；Sider「工作台 → 经营概览」；Header Logo 点击。
- **实现状态**：✅ 已实现

## 2. 页面布局与信息架构
- **整体布局**：顶部面包屑 + 顶部 4 个统计卡片（`DashboardCard`）+ 中部销售趋势折线图 + 底部待办列表（待发货、售后待处理）双栏。
- **关键区域**：
  - 区域 A（顶部统计卡片区）：4 个 `DashboardCard` 等宽排列 —— 今日订单数、今日销售额、待发货订单、售后待处理。每卡含数值、单位、环比趋势箭头。
  - 区域 B（销售趋势区）：`ChartLine` 折线图展示近 7 日销售额与订单数双 Y 轴趋势，右上角时间范围切换（近 7 天 / 近 30 天）。
  - 区域 C（左下待发货区）：`<a-list>` 展示最近 5 笔待发货订单（订单号、买家、金额、下单时间），底部「查看全部」链接跳转待发货页。
  - 区域 D（右下售后待处理区）：`<a-list>` 展示最近 5 笔待处理售后单（售后单号、类型、申请金额、申请时间），底部「查看全部」跳转售后列表。
- **响应式断点**：≥1200px 4 卡片一行 + 趋势图满宽 + 双栏待办；992-1199px 4 卡片 2×2 网格 + 趋势图满宽 + 单栏待办堆叠；<992px 不支持。
- **首屏内容**：4 个统计卡片 + 趋势图标题。

## 3. 数据模型与 API 对接
- **主要 API**：

| 方法 | 端点 | 用途 | 鉴权 |
|-|-|-|-|
| GET | `/api/seller/dashboard` | 工作台概览（店铺信息 + 当日指标） | Seller |
| GET | `/api/seller/sales-trend?from=&to=` | 销售趋势（按日序列） | Seller |

- **请求参数**：`sales-trend` 端点接收 `from`/`to`（DateOnly，ISO 8601 日期）。近 7 天取 `today-6` 至 `today`，近 30 天取 `today-29` 至 `today`。
- **响应字段**：`SellerDashboardDto` 含 `shopId`、`shopName`、`status`、`productCount`、`totalOrders`、`pendingOrders`、`completedOrders`、`totalRevenue`、`todayOrderCount`、`todaySalesAmount`、`todaySalesCurrency`、`todayAvgRating`、`todayRatingCount`、`todayRefundCount`。`SalesTrendDto[]` 含 `date`、`orderCount`、`salesAmount`。`pendingOrders`/`todayRefundCount` 用于待办徽标。
- **数据加载策略**：进入页面并行调用 dashboard 与 sales-trend（近 7 天）；时间范围切换重新调用 sales-trend。
- **缓存策略**：dashboard 数据缓存 1 分钟（键 `seller:dashboard:{sellerId}`），趋势数据缓存 5 分钟（键 `seller:sales-trend:{sellerId}:{from}:{to}`）。

## 4. 交互流程
- **主流程**：
  1. 卖家进入页面 → 并行调用 dashboard 与 sales-trend → 渲染统计卡片与趋势图。
  2. 卖家点击趋势图「近 30 天」→ 调用 sales-trend（近 30 天）→ 图表重绘。
  3. 卖家点击待发货列表「查看全部」→ 跳转 `/orders/pending-shipment`。
  4. 卖家点击售后列表「查看全部」→ 跳转 `/after-sales`。
- **分支流程**：
  - 新店铺无数据：统计卡片显示 0，趋势图显示 `<EmptyState title="暂无销售数据" />`。
  - ES 读模型无数据回退 DB：后端自动处理，前端无感知。
  - 读模型最终一致窗口：刚支付订单可能短暂未更新，可接受。
- **跨页面流转**：待发货 → `/orders/pending-shipment`；售后 → `/after-sales`；销售趋势详情 → `/dashboard/sales-trend`。
- **状态机可视化**：无状态机；展示店铺当前状态徽标。

## 5. 组件清单
- **基础组件**：`<a-breadcrumb>`、`<a-card>`、`<a-list>`、`<a-empty>`、`<a-spin>`、`<a-skeleton>`、`<a-segmented>`（时间范围切换）。
- **业务组件**：`DashboardCard`（见 shared/components.md §8）— 4 个统计卡片；`ChartLine`（见 shared/components.md §7.1）— 销售趋势折线图；`StatusTag`（见 shared/components.md §1，type="shop"）— 店铺状态；`EmptyState`（见 shared/components.md §5）— 无数据占位。
- **图表组件**：`ChartLine` —— 双 Y 轴（销售额 / 订单数），smooth 曲线，主色 `#1677FF`。
- **图标使用**：`ShoppingOutlined`（订单）、`DollarOutlined`（销售额）、`TruckOutlined`（待发货）、`CustomerServiceOutlined`（售后）、`ArrowUpOutlined`/`ArrowDownOutlined`（趋势）。
- **空状态**：趋势图无数据时 `<EmptyState title="暂无销售数据" description="有订单后将自动生成趋势" />`。

## 6. 视觉规范
- **主色应用**：统计卡片数值、趋势图主线、时间范围切换激活态使用主色 `#1677FF`。
- **状态色**：趋势上升绿 `#52C41A` + ↑，下降红 `#FF4D4F` + ↓；待发货/售后待处理徽标 warning 黄 `#FAAD14`。
- **间距**：统计卡片间距 `16px`，区块间距 `24px`，卡片内边距 `16px`，待办列表项间距 `12px`。
- **字体**：页面标题 `20px` medium，统计卡片标题 `14px` `#8C8C8C`，统计数值 `24px` semibold `#000000D9`，待办列表项 `14px` normal。
- **图标尺寸**：统计卡片图标 `24px`，趋势箭头 `12px`，待办图标 `16px`。

## 7. 异常处理与边界
- **加载态**：进入页面 4 个 `DashboardCard` 显示 `<a-skeleton :active="true" />`，趋势图显示 `<a-skeleton>`；时间范围切换时图表区 `<a-spin>`。
- **空数据**：新店铺统计卡片显示 0，趋势图 `<EmptyState>`，待办列表 `<EmptyState title="暂无待发货订单" />`。
- **错误态**：网络错误 `message.error('网络异常')`；403 `message.error('无权限访问')`；读模型降级由后端处理，前端无感知。
- **权限控制**：需卖家登录态，`SellerId` 取自 JWT 强制过滤，仅可见本店概览。
- **并发与乐观锁**：概览为只读，无并发冲突。
- **危险操作确认**：概览页无危险操作。

- [ ] 4 个统计卡片正确展示今日订单数、今日销售额、待发货、售后待处理
- [ ] 环比趋势箭头方向与颜色正确（上升绿/下降红）
