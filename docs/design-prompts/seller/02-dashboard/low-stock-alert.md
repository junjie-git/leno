# 库存预警 - 商家管理后台

## 1. 页面定位
- **所属端**：商家管理后台
- **所属模块**：02-dashboard（工作台）
- **页面类型**：列表页（看板衍生）
- **目标用户**：卖家（Seller）
- **核心目标**：卖家查看低库存商品列表，及时补货避免断货。
- **访问入口**：Sider「工作台 → 库存预警」；工作台概览低库存提醒卡片。
- **实现状态**：➕ 补充功能

## 2. 页面布局与信息架构
- **整体布局**：顶部面包屑 + 顶部预警统计条 + 筛选栏 + 低库存商品表格 + 右侧补货抽屉。
- **关键区域**：
  - 区域 A（面包屑）：首页 / 工作台 / 库存预警。
  - 区域 B（预警统计条）：`<a-alert type="warning">` 展示「当前有 N 个 SKU 库存低于阈值，建议尽快补货」。
  - 区域 C（筛选栏）：阈值输入（`<a-input-number>` 默认 10，可调 1-999）+ 分类筛选（`<a-tree-select>`）+ 排序方式（库存升序/销量降序）。
  - 区域 D（低库存表格 `<a-table>`）：列含商品名称、SKU 规格、SKU 编码、当前库存、销量（近 30 天）、库存状态（紧急<5/警告<10/偏低<阈值）、操作（补货）。>100 行虚拟滚动。
  - 区域 E（补货抽屉）：右侧 `<a-drawer>` 含补货数量输入（`<a-input-number>`）、补货后预计库存展示、确认补货按钮。
- **响应式断点**：≥1200px 表格全宽；992-1199px 表格横向滚动；<992px 不支持。
- **首屏内容**：预警统计条 + 筛选栏 + 表格前 10 行。

## 3. 数据模型与 API 对接
- **主要 API**：

| 方法 | 端点 | 用途 | 鉴权 |
|-|-|-|-|
| GET | `/api/products?shopId={myShopId}&status=Listed` | 查询本店商品（含 SKU 库存） | Seller |
| GET | `/api/products/{id}` | 查询商品详情（含 SKU 完整信息） | Seller |

- **请求参数**：商品列表 `ProductQueryDto` 含 `shopId`、`status=Listed`、`page`、`pageSize`。前端拉取全量在售商品后，本地筛选 SKU.stock < 阈值的项。
- **响应字段**：`ProductDto` 含 `name`、`skus[]`（每个 SKU 含 `skuId`、`skuCode`、`specAttributes`、`stock`、`price`）。前端聚合所有 SKU 后按库存升序排列。
- **数据加载策略**：进入页面分页拉取本店所有在售商品（每页 50，循环至拉完），本地筛选低库存 SKU。
- **缓存策略**：商品列表缓存 5 分钟（键 `seller:low-stock:{sellerId}`）；补货后失效缓存。

## 4. 交互流程
- **主流程**：
  1. 卖家进入页面 → 分页拉取在售商品 → 本地筛选 SKU.stock < 阈值（默认 10）→ 渲染表格。
  2. 卖家调整阈值 → 防抖 300ms 后重新筛选本地数据。
  3. 卖家选择分类或排序 → 重新筛选与排序。
  4. 卖家点击「补货」→ 右侧抽屉滑出 → 输入补货数量 → 实时计算预计库存 → 点击「确认补货」→ 调用商品库存调整接口（如 `PUT /api/products/{id}` 更新 SKU）→ `message.success('补货成功')` → 刷新列表。
- **分支流程**：
  - 无低库存 SKU：`<EmptyState title="库存充足" description="当前无低库存商品" />`。
  - 补货数量非法（≤0）：前端校验拦截。
- **跨页面流转**：点击商品名称跳转商品编辑页；补货后留在本页刷新。
- **状态机可视化**：库存状态由 stock 值派生：紧急（<5，红）/警告（<10，黄）/偏低（<阈值，蓝）。

## 5. 组件清单
- **基础组件**：`<a-alert>`、`<a-input-number>`、`<a-tree-select>`、`<a-table>`、`<a-drawer>`、`<a-form>`、`<a-statistic>`、`<a-tag>`。
- **业务组件**：`IdempotencyButton`（见 shared/components.md §2）— 补货确认按钮；`StatusTag`（见 shared/components.md §1）— 库存状态；`EmptyState`（见 shared/components.md §5）— 无低库存占位；`DataTable`（见 shared/components.md §6）— 低库存表格。
- **图表组件**：无。
- **图标使用**：`WarningOutlined`（预警）、`StockOutlined`（库存）、`ShoppingOutlined`（补货）、`ExclamationCircleOutlined`（紧急）。
- **空状态**：`<EmptyState title="库存充足" description="当前无低库存商品" icon="check-circle" />`。

## 6. 视觉规范
- **主色应用**：阈值输入框聚焦、补货按钮使用主色 `#1677FF`；偏低状态标签 info 蓝。
- **状态色**：紧急红 `#FF4D4F`、警告黄 `#FAAD14`、偏低蓝 `#1677FF`；预警统计条 warning 黄背景。
- **间距**：预警条与筛选栏间距 `16px`，表格行高 `48px`，抽屉宽度 `420px`，抽屉表单项间距 `16px`。
- **字体**：页面标题 `20px` medium，预警条 `14px` medium，表格 `14px` normal，库存数值 `16px` semibold。
- **图标尺寸**：预警图标 `20px`，状态图标 `16px`，操作图标 `16px`。

## 7. 异常处理与边界
- **加载态**：进入页面 `<a-skeleton>` 模拟表格；补货时按钮 loading。
- **空数据**：`<EmptyState>` 提示库存充足。
- **错误态**：网络错误 `message.error('网络异常')`；403 `message.error('无权限访问')`；补货失败展示后端原因。
- **权限控制**：需卖家登录态，仅可补货本店商品。
- **并发与乐观锁**：补货调用 `PUT /api/products/{id}` 携带 version；冲突返回 409，提示「商品已被他人修改，请刷新后重试」。
- **危险操作确认**：补货非危险操作，无二次确认；补货数量 >1000 时 `Modal.confirm` 提示「确认补货 N 件？请核对数量」。

## 8. 验收要点
- [ ] 预警统计条正确显示低库存 SKU 数量
- [ ] 阈值调整后防抖 300ms 重新筛选
- [ ] 表格按库存升序展示，状态色正确（紧急/警告/偏低）
- [ ] 补货抽屉实时计算预计库存（当前 + 补货数量）
- [ ] 补货成功后刷新列表并失效缓存
- **性能要求**：首屏加载 < 2s（含全量商品拉取）；阈值筛选 ≤ 100ms；表格 >100 行虚拟滚动。
- **可访问性**：阈值输入有 `aria-label`；表格有 `aria-label`；抽屉键盘可关闭；对比度满足 WCAG AA。
