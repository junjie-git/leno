# 入驻申请 - 商家管理后台

## 1. 页面定位
- **所属端**：商家管理后台
- **所属模块**：01-onboarding（入驻与店铺）
- **页面类型**：表单页（流程页）
- **目标用户**：卖家（Seller）
- **核心目标**：卖家填写企业/个人资质信息并上传证照，提交入驻申请等待运营审核。
- **访问入口**：未持有店铺的卖家登录后首屏自动跳转；Sider「店铺设置 → 入驻申请」菜单；已提交但被驳回时再次进入修改重新提交。
- **实现状态**：✅ 已实现

## 2. 页面布局与信息架构
- **整体布局**：顶部面包屑（首页 / 入驻申请）+ 居中单列表单卡片（最大宽度 800px）+ 底部提交操作栏。表单采用垂直布局，label 位于字段上方。
- **关键区域**：
  - 区域 A（顶部步骤条）：`<a-steps :current="0">` 展示「填写资料 → 提交审核 → 审核通过」三步，当前步高亮主色 `#1677FF`。
  - 区域 B（经营主体类型选择）：`<a-radio-group>` 企业 / 个人二选一，切换后表单字段动态变化（企业显示统一社会信用代码，个人显示身份证号）。
  - 区域 C（基础信息区）：店铺名称、营业执照号/证件号、经营范围（`<a-textarea>` 限 500 字）。
  - 区域 D（证照上传区）：`<a-upload>` 营业执照图片（必填，仅 JPG/PNG/WebP，≤5MB），补充资质材料（可选，多文件）。
  - 区域 E（底部操作栏）：取消、提交审核（`IdempotencyButton` primary）。
- **响应式断点**：≥1200px 表单居中 800px；992-1199px 表单宽度自适应满栏；<992px 不支持。
- **首屏内容**：步骤条 + 主体类型选择 + 基础信息前 3 个字段。

## 3. 数据模型与 API 对接
- **主要 API**：

| 方法 | 端点 | 用途 | 鉴权 |
|-|-|-|-|
| POST | `/api/shops/application` | 提交入驻申请 | Seller |
| GET | `/api/shops/me` | 查询是否已持有店铺（前置校验） | Seller |

- **请求参数**：`SubmitShopApplicationDto` 含 `shopName`(2-32 字)、`businessType`(Enterprise/Individual)、`licenseNo`(企业 18 位统一社会信用代码 / 个人身份证号)、`licenseImage`(URL)、`businessScope`(≤500 字)、`qualifications?`(补充资质数组)。
- **响应字段**：`ShopDto` 含 `id`、`shopName`、`status`(PendingReview/Active/Suspended/Closed)、`sellerId`。状态用于提交后跳转与提示。
- **数据加载策略**：进入页面时调用 `GET /api/shops/me` 判断是否已持有店铺——已有店铺跳转店铺资料页，无店铺显示申请表单。
- **缓存策略**：不缓存，每次进入实时查询。

## 4. 交互流程
- **主流程**：
  1. 卖家进入页面 → 调用 `GET /api/shops/me` → 无店铺则显示申请表单。
  2. 卖家选择主体类型 → 表单字段动态切换（企业/个人证件号校验规则不同）。
  3. 卖家上传营业执照图片 → `<a-upload>` 调用文件上传接口获得 URL → 填入 `licenseImage`。
  4. 卖家填写完表单点击「提交审核」→ 前端校验通过 → 调用 `POST /api/shops/application` → 成功 `message.success('申请已提交，请等待审核')` → 跳转工作台。
- **分支流程**：
  - 已持有店铺：跳转 `/shop/profile`，不显示申请表单。
  - 已有待审核申请：提示「您已提交申请，审核中」，禁用表单。
  - 驳回后重新提交：预填上次驳回的申请信息，提示驳回原因，卖家修改后重新提交。
- **跨页面流转**：提交成功后跳转 `/dashboard/overview`；审核通过后通过通知中心引导进入 `/shop/profile`。
- **状态机可视化**：入驻申请状态 待审核(Pending) → 已通过(Approved)/已驳回(Rejected)，已驳回可重新提交新申请。

- **基础组件**：`<a-form>`、`<a-form-item>`、`<a-input>`、`<a-textarea>`、`<a-radio-group>`、`<a-radio>`、`<a-upload>`、`<a-steps>`、`<a-breadcrumb>`、`<a-card>`。
- **业务组件**：`IdempotencyButton`（见 shared/components.md §2）— 提交按钮防抖与幂等；`EmptyState`（见 shared/components.md §5）— 无数据占位。
- **图表组件**：无。
- **图标使用**：`ShopOutlined`（步骤图标）、`IdcardOutlined`（个人主体）、`BankOutlined`（企业主体）、`UploadOutlined`（上传）。
- **空状态**：表单无空状态；驳回后重新进入时展示上次驳回原因卡片。

## 6. 视觉规范
- **主色应用**：步骤条当前步与提交按钮使用主色 `#1677FF`；表单聚焦边框主色。
- **状态色**：驳回原因卡片使用警告色 `#FAAD14` 边框；必填字段星号使用危险色 `#FF4D4F`。
- **间距**：表单项间距 `16px`（spacing/4），区块间距 `24px`（spacing/6），卡片内边距 `24px`。
- **字体**：页面标题 `20px` medium，表单标签 `14px` medium，正文 `14px` normal，辅助提示 `12px`。
- **图标尺寸**：步骤条图标 `32px`，表单前缀图标 `16px`。

## 7. 异常处理与边界
- **加载态**：进入页面 `<a-spin>` 包裹全屏；提交时按钮 loading。
- **空数据**：不适用（表单页）。
- **错误态**：网络错误 `message.error('网络异常，请重试')`；403 `message.error('无权限访问')`；409（重复入驻/店铺名重复）展示后端返回的具体原因。
- **权限控制**：需登录态；申请人只能为自己提交申请，`ApplicantUserId` 取自 JWT。
- **并发与乐观锁**：申请单创建无乐观锁；并发提交相同店铺名称以唯一索引拦截返回 409，前端提示「店铺名称已被占用，请修改后重试」。
- **危险操作确认**：提交审核非危险操作，无二次确认；取消操作若表单已修改，`Modal.confirm` 提示「确认取消？已填写的信息将丢失」。

## 8. 验收要点
- [ ] 主体类型切换时证件号校验规则正确切换（企业 18 位统一社会信用代码 / 个人身份证号）
- [ ] 营业执照图片上传支持 JPG/PNG/WebP，单文件 ≤5MB，超过限制给出明确提示
- [ ] 店铺名称实时校验长度 2-32 字，提交时统一校验
- [ ] 已持有店铺或已有待审核申请时不显示申请表单并给出引导
- [ ] 提交成功后显示 1.5s 成功提示并跳转工作台
- **性能要求**：首屏加载 < 1s；上传图片 5MB 文件 ≤ 3s；提交按钮防抖 300ms。
- **可访问性**：所有表单字段有 `aria-label`；键盘可遍历表单；上传组件支持键盘触发；对比度满足 WCAG AA。
