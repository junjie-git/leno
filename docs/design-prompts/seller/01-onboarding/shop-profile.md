# 店铺资料 - 商家管理后台

## 1. 页面定位
- **所属端**：商家管理后台
- **所属模块**：01-onboarding（入驻与店铺）
- **页面类型**：表单页
- **目标用户**：卖家（Seller）
- **核心目标**：卖家维护店铺基础信息（名称、Logo、描述、客服联系方式），保持店铺资料准确。
- **访问入口**：Sider「店铺设置 → 店铺资料」；入驻审核通过后的通知引导；工作台快捷入口。
- **实现状态**：✅ 已实现

## 2. 页面布局与信息架构
- **整体布局**：顶部面包屑 + 左右两栏。左栏（占 16 栅格）为表单卡片，右栏（占 8 栅格）为店铺状态与预览卡片。
- **关键区域**：
  - 区域 A（面包屑）：首页 / 店铺设置 / 店铺资料。
  - 区域 B（左栏表单卡片）：店铺名称、Logo 上传、店铺描述、客服电话、客服邮箱、在线客服账号。

  - 区域 D（底部操作栏）：保存（`IdempotencyButton` primary）。
- **响应式断点**：≥1200px 左右两栏；992-1199px 单列堆叠，状态卡片下移；<992px 不支持。
- **首屏内容**：表单卡片前 3 个字段 + 状态卡片头部。

## 3. 数据模型与 API 对接
- **主要 API**：

| 方法 | 端点 | 用途 | 鉴权 |
|-|-|-|-|
| GET | `/api/shops/me` | 查询当前卖家店铺资料 | Seller |
| PUT | `/api/shops/me` | 更新店铺基础信息 | Seller |

- **请求参数**：`UpdateShopInfoDto` 含 `shopName?`(2-32 字)、`logo?`(URL，经 `IFileStorageService.ValidateUrl` 校验)、`description?`(≤1000 字)、`customerService?`(`{phone, email?, onlineAccount?}`)。
- **响应字段**：`ShopDto` 含 `id`、`shopName`、`logo`、`description`、`customerService`、`status`、`productCount`、`createdAt`、`updatedAt`、`version`(乐观锁)。`version` 用于并发控制，`status`/`productCount` 用于右栏状态卡片。
- **数据加载策略**：进入页面时调用 `GET /api/shops/me` 一次性加载，预填表单与状态卡片。
- **缓存策略**：不缓存，每次进入实时加载；Logo 上传后 URL 临时存储，提交时随表单一起保存。

## 4. 交互流程
- **主流程**：
  1. 卖家进入页面 → 调用 `GET /api/shops/me` → 表单预填，状态卡片填充。
  2. 卖家修改字段 → 失焦时单字段校验（店铺名称长度、电话格式）。
  3. 卖家点击 Logo 上传 → `<a-upload>` 调用文件上传 → 预览缩略图，临时存储 URL。
  4. 卖家点击「保存」→ 全表单校验通过 → 调用 `PUT /api/shops/me` → 成功 `message.success('保存成功')` → 刷新状态卡片。
- **分支流程**：
  - 店铺名称被他店占用：后端返回 409，`message.error('店铺名称已被占用')`，字段标红。
  - 关闭态店铺：后端返回 409，`message.error('店铺已关闭，不可编辑')`，禁用表单。
  - 乐观锁冲突：后端返回 409（version 不匹配），`message.error('数据已被他人修改，请刷新后重试')`。
- **跨页面流转**：点击「预览店铺前台」跳转 `/shop/preview`；保存成功后留在本页。
- **状态机可视化**：店铺状态 审核中(UnderReview) → 正常(Active) ↔ 暂停(Suspended) → 关闭(Closed)（终态）。本页仅展示状态，不可变更状态（状态变更由运营操作）。

- **基础组件**：`<a-form>`、`<a-form-item>`、`<a-input>`、`<a-textarea>`、`<a-upload>`、`<a-descriptions>`、`<a-card>`、`<a-breadcrumb>`。

## 6. 视觉规范
- **主色应用**：保存按钮、Logo 上传聚焦边框、状态卡片中「预览店铺前台」链接使用主色 `#1677FF`。
- **状态色**：店铺状态使用 `StatusTag` —— 营业中绿 `#52C41A`、暂停黄 `#FAAD14`、关闭灰 `#8C8C8C`、审核中黄 `#FAAD14`、资质过期红 `#FF4D4F`。
- **间距**：表单项间距 `16px`，左右栏间距 `24px`，卡片内边距 `24px`。
- **字体**：页面标题 `20px` medium，表单标签 `14px` medium，描述列表标题 `14px` medium，正文 `14px` normal。
- **图标尺寸**：状态卡片图标 `20px`，表单前缀图标 `16px`，Logo 预览 `96px`。

## 7. 异常处理与边界
- **加载态**：进入页面 `<a-skeleton>` 模拟表单与状态卡片布局。
- **空数据**：新店铺 Logo/描述为空时显示「未设置」灰字，不阻断操作。
- **错误态**：网络错误 `message.error('网络异常')`；403 `message.error('无权限访问')`；404（店铺不存在，理论上不该发生）提示「未找到店铺，请先提交入驻申请」并提供跳转入驻申请按钮。
- **权限控制**：仅店铺所属卖家可编辑，`SellerId` 须与当前登录用户一致，否则 403；运营不可直接编辑卖家店铺信息。
- **并发与乐观锁**：`PUT` 请求携带 `version` 字段；冲突返回 409，提示「数据已被他人修改，请刷新后重试」，点击刷新重新加载最新数据。
- **危险操作确认**：保存非危险操作，无二次确认；Logo 替换时若已有旧 Logo，直接覆盖无确认（可逆，可重新上传）。

## 8. 验收要点
- [ ] 进入页面正确预填店铺资料与状态
- [ ] 店铺名称实时校验长度 2-32 字，保存时统一校验
- [ ] Logo 上传支持 JPG/PNG/WebP，≤5MB，上传后显示缩略图预览
- [ ] 客服电话格式校验（E.164 或国内座机格式）
- [ ] 乐观锁冲突时提示并支持刷新重试
- [ ] 暂停态店铺可编辑信息（商品可售由状态事件驱动，与信息编辑解耦）
- **性能要求**：首屏加载 < 1s；Logo 上传 ≤ 3s；保存按钮防抖 300ms。
- **可访问性**：表单字段有 `aria-label`；Logo 上传有 `aria-describedby` 提示；键盘可保存；对比度满足 WCAG AA。
