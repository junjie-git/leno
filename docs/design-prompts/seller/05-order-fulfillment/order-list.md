# 全部订单 - 商家管理后台

## 1. 页面定位
- **所属端**：商家管理后台
- **所属模块**：05-order-fulfillment（订单履约）
- **页面类型**：列表页
- **目标用户**：卖家（Seller）
- **核心目标**：卖家查看本店全部订单（含各状态），按状态/时间/订单号筛选，查看订单详情与物流轨迹。
- **访问入口**：Sider「订单履约 → 全部订单」；URL `/orders`。
- **实现状态**：➕ 补充功能

## 2. 页面布局与信息架构
- **整体布局**：顶部面包屑 + 状态标签页 + 筛选栏 + 订单表格 + 底部分页。
- **关键区域**：
  - 区域 A（面包屑）：首页 / 订单履约 / 全部订单。
  - 区域 B（状态标签页 `<a-tabs>`）：全部 / 待支付 / 待发货 / 已发货 / 已完成 / 已取消，每个标签显示对应数量 Badge。
  - 区域 C（筛选栏）：订单号搜索（`<a-input-search>`）+ 下单时间范围（`<a-range-picker>`）+ 买家手机号（脱敏搜索）。
  - 区域 D（订单表格 `<a-table>`）：列含订单编号、商品摘要（首图 + 标题 + 数量，多品显示「等 N 件商品」）、订单金额、支付方式、订单状态（StatusTag）、下单时间、操作（查看详情/物流轨迹/发货）。可展开行查看订单明细列表。
  - 区域 E（分页）：`<a-pagination>` 右对齐，默认 20 条/页，可切换 10/20/50。
- **响应式断点**：≥1200px 表格全宽；992-1199px 表格横向滚动；<992px 不支持。
- **首屏内容**：状态标签页 + 筛选栏 + 表格前 20 行。

## 3. 数据模型与 API 对接
- **主要 API**：

| 方法 | 端点 | 用途 | 鉴权 |
|-|-|-|-|
| GET | `/api/seller/orders` | 卖家查询本店订单（补充端点） | Seller（补充） |

- **请求参数**：`OrderListQuery` 含 `sellerId`（后端从 JWT 注入，前端不传）、`status`（订单状态名，如 "Paid"、"Shipped"）、`startDate?`、`endDate?`、`pageIndex`（0-based）、`pageSize`。订单号搜索需扩展 Query 支持 `orderNo` 字段。
- **响应字段**：`OrderListResult` 含 `items[]`（每个订单含 `id`、`orderNo`、`status`、`itemsAmount`、`totalAmount`、`paymentMethod`、`createdAt`、`paidAt?`、`shippedAt?`、`items[]`（含 `skuId`、`productName`、`quantity`、`mainImage`、`unitPrice`））、`total`、`pageIndex`、`pageSize`。
- **数据加载策略**：进入页面加载第一页（全部状态）；状态标签切换重新查询带 `status` 参数；筛选条件变更重新查询。
- **缓存策略**：不缓存，订单数据时效性要求高。

## 4. 交互流程
- **主流程**：
  1. 卖家进入页面 → 调用 `GET /api/seller/orders?pageIndex=0&pageSize=20` → 渲染标签页数量 Badge 与表格。
  2. 卖家切换状态标签 → 带 `status` 参数重新查询 → 刷新表格。
  3. 卖家输入订单号 / 选择时间范围 / 输入买家手机 → 重新查询。
  4. 卖家点击「查看详情」→ 展开行查看订单明细（商品列表、金额构成、收货地址脱敏）。
  5. 卖家点击「发货」（待发货态）→ 跳转待发货订单页或弹出快捷发货 Modal。
  6. 卖家点击「物流轨迹」（已发货态）→ 跳转 `/orders/:id/trace`。
- **分支流程**：
  - 待支付态：操作列仅显示「查看详情」，无发货/轨迹按钮。
  - 已发货态：操作列显示「查看详情」「物流轨迹」。
  - 已取消态：操作列仅显示「查看详情」，展示取消原因。
- **跨页面流转**：发货跳转待发货订单页；物流轨迹跳转轨迹页；订单号点击跳转详情展开。
- **状态机可视化**：订单状态流转：待支付 →（支付）→ 待发货 →（发货）→ 已发货 →（确认收货）→ 已完成；待支付 →（取消/超时）→ 已取消。

## 5. 组件清单
- **基础组件**：`<a-tabs>`、`<a-tab-pane>`、`<a-badge>`、`<a-input-search>`、`<a-range-picker>`、`<a-table>`、`<a-pagination>`、`<a-image>`、`<a-tooltip>`。
- **业务组件**：`StatusTag`（见 shared/components.md §1，type="order"）— 订单状态展示；`DataTable`（见 shared/components.md §6）— 订单表格；`EmptyState`（见 shared/components.md §5）— 无订单占位；`DateTimeRangePicker`（见 shared/components.md §4）— 下单时间筛选。
- **图表组件**：无。
- **图标使用**：`EyeOutlined`（查看详情）、`TruckOutlined`（发货/轨迹）、`EnvironmentOutlined`（收货地址）。
- **空状态**：`<EmptyState title="暂无订单" description="当前筛选条件下没有订单" />`。

## 6. 视觉规范
- **主色应用**：状态标签页激活态、订单号链接使用主色 `#1677FF`。
- **状态色**：待支付黄 `#FAAD14`、待发货黄 `#FAAD14`、已发货蓝 `#1677FF`、已完成绿 `#52C41A`、已取消灰 `#8C8C8C`（由 StatusTag 映射）。
- **间距**：标签页与筛选栏间距 `16px`，筛选栏与表格间距 `16px`，表格行高 `56px`（含商品缩略图），单元格内边距 `12px`。
- **字体**：页面标题 `20px` medium，表格 `14px` normal，订单金额 `14px` semibold，订单号 `14px` semibold（等宽字体优先）。
- **图标尺寸**：操作图标 `16px`，商品缩略图 `40×40px` 圆角 `4px`。

## 7. 异常处理与边界
- **加载态**：进入页面 `<a-skeleton>` 模拟表格 5 行；标签切换时表格 `<a-spin>`。
- **空数据**：`<EmptyState>` 展示无订单。
- **错误态**：网络错误 `message.error('网络异常')`；403 `message.error('无权限访问')`；查询失败展示后端原因。
- **权限控制**：需卖家登录态；后端按 SellerId 过滤，卖家仅查看本店订单。
- **并发与乐观锁**：列表页无编辑操作，无乐观锁冲突。
- **危险操作确认**：无危险操作（查看页）；发货操作在待发货订单页处理。

## 8. 验收要点
- [ ] 状态标签页正确显示各状态数量 Badge
- [ ] 切换标签按状态筛选并刷新表格
- [ ] 订单号/时间范围/买家手机筛选生效
- [ ] 表格展示订单号、商品摘要、金额、支付方式、状态、下单时间
- [ ] 展开行正确展示订单明细（商品列表、金额构成）
- [ ] 操作列按状态动态显示按钮
- **性能要求**：首屏加载 < 1.5s；表格 >100 行虚拟滚动；标签切换响应 < 500ms。
- **可访问性**：表格有 `aria-label="订单列表"`；标签页有 `aria-label`；操作按钮有 `aria-label`；对比度满足 WCAG AA。

> **补充功能说明**：当前后端 `OrdersController` 仅有买家端 `GET /api/orders`（Buyer）与运营端 `GET /api/admin/orders`（Operator/Admin），无卖家端订单列表端点。本页面需后端新增 `GET /api/seller/orders` 端点，复用 `OrderListQuery`（已支持 `SellerId`、`Status`、`StartDate`、`EndDate` 字段）与现有 `OrderListQueryHandler`，仅需在 Controller 层新增 Seller 角色端点，后端从 JWT 注入 SellerId 过滤本店订单。
