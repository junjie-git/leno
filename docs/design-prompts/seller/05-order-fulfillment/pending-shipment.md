# 待发货订单 - 商家管理后台

## 1. 页面定位
- **所属端**：商家管理后台
- **所属模块**：05-order-fulfillment（订单履约）
- **页面类型**：列表页（含发货弹窗）
- **目标用户**：卖家（Seller）
- **核心目标**：卖家查看已支付待发货订单，录入物流单号与公司编码完成发货，加速履约。
- **访问入口**：Sider「订单履约 → 待发货订单」；Header「待发货 N 单」红色 Badge 快捷入口；工作台待办卡片。
- **实现状态**：➕ 补充功能

## 2. 页面布局与信息架构
- **整体布局**：顶部面包屑 + 待办统计条 + 筛选栏 + 待发货订单表格 + 发货弹窗。
- **关键区域**：
  - 区域 A（面包屑）：首页 / 订单履约 / 待发货订单。
  - 区域 B（待办统计条）：`<a-alert type="warning">` 展示「当前有 N 单待发货，其中 X 单已超 24 小时未发货」。
  - 区域 C（筛选栏）：订单号搜索（`<a-input-search>`）+ 下单时间范围（`<a-range-picker>`）+ 排序（下单时间/支付时间）。
  - 区域 D（订单表格 `<a-table>`）：列含订单编号、买家信息（脱敏）、商品摘要（首图 + 标题 + 数量）、订单金额、支付时间、等待时长（派生颜色：>24h 红、>12h 黄、正常绿）、操作（发货/查看详情）。可展开行查看订单明细。
  - 区域 E（发货弹窗 `<a-modal>`）：物流公司选择（`<a-select>` 从物流公司查询页数据源）+ 物流单号输入（`<a-input>`）+ 确认发货按钮。
- **响应式断点**：≥1200px 表格全宽；992-1199px 表格横向滚动；<992px 不支持。
- **首屏内容**：统计条 + 筛选栏 + 表格前 20 行。

## 3. 数据模型与 API 对接
- **主要 API**：

| 方法 | 端点 | 用途 | 鉴权 |
|-|-|-|-|
| POST | `/api/seller/orders/{id}/ship` | 卖家发货（录入物流单号与公司编码） | Seller |

- **请求参数**：`ShipOrderDto` 含 `logisticsNo`（物流单号）、`logisticsCompanyCode`（物流公司编码）。
- **响应字段**：发货成功返回 `ApiResponse`（无数据体）。订单列表数据需补充查询端点（见下方说明）。
- **数据加载策略**：**补充功能说明**：当前后端 `OrdersController` 仅有买家端 `GET /api/orders`（按 UserId 过滤）与运营端 `GET /api/admin/orders`（Operator/Admin），无卖家端订单列表端点。本页面需后端新增 `GET /api/seller/orders?status=Paid&page=1&pageSize=20` 端点，按当前卖家 SellerId 过滤、按状态筛选待发货（Paid）订单。发货成功后从列表移除该行并刷新统计条。
- **缓存策略**：不缓存，订单状态时效性要求高；待办统计条每 60 秒轮询刷新未发货数量。

## 4. 交互流程
- **主流程**：
  1. 卖家进入页面 → 调用卖家订单列表端点（status=Paid）→ 渲染统计条与表格。
  2. 卖家搜索订单号 / 选择时间范围 / 切换排序 → 重新查询。
  3. 卖家点击「发货」→ 弹出发货 Modal → 选择物流公司（数据源来自物流公司查询页缓存）→ 输入物流单号 → 点击「确认发货」→ 调用 `POST /api/seller/orders/{id}/ship` → `message.success('发货成功')` → 关闭 Modal → 从列表移除该行 → 刷新统计条。
  4. 卖家点击「查看详情」→ 跳转订单详情或展开行查看明细。
- **分支流程**：
  - 等待时长 >24 小时：等待列红色高亮，提示优先处理。
  - 物流单号为空或格式错误：前端校验拦截。
  - 发货失败（订单状态已变更）：后端返回 409，提示「订单状态已变更，请刷新后重试」。
- **跨页面流转**：发货后留在本页刷新；查看详情跳转订单列表对应详情。
- **状态机可视化**：订单状态：已支付（Paid，待发货）→（卖家发货）→ 已发货（Shipped）。

## 6. 视觉规范
- **主色应用**：「发货」主按钮、订单号链接使用主色 `#1677FF`。
- **状态色**：等待时长 >24h 红 `#FF4D4F`、>12h 黄 `#FAAD14`、正常绿 `#52C41A`；统计条 warning 黄背景。
- **间距**：统计条与筛选栏间距 `12px`，筛选栏与表格间距 `16px`，表格行高 `56px`（含商品缩略图），发货 Modal 宽度 `480px`。
- **字体**：页面标题 `20px` medium，统计条 `14px` medium，表格 `14px` normal，订单金额 `14px` semibold，等待时长 `14px` semibold。
- **图标尺寸**：操作图标 `16px`，商品缩略图 `40×40px` 圆角 `4px`，警告图标 `20px`。

## 7. 异常处理与边界
- **加载态**：进入页面 `<a-skeleton>` 模拟表格 5 行；发货时按钮 loading。
- **空数据**：`<EmptyState>` 展示暂无待发货。
- **错误态**：网络错误 `message.error('网络异常')`；403 `message.error('无权限访问')`；发货失败展示后端原因。
- **权限控制**：需卖家登录态；发货端点后端校验订单 SellerId 与当前卖家一致，非本店订单返回 403。
- **并发与乐观锁**：发货操作后端校验订单状态为 Paid，非法状态返回 409，提示「订单状态已变更，请刷新后重试」。
- **危险操作确认**：发货为常规操作，无二次确认；物流单号提交后不可修改，发货成功后如需修改需联系运营。

## 8. 验收要点
- [ ] 统计条正确显示待发货数量与超时数量
- [ ] 表格展示订单号、买家脱敏、商品摘要、金额、支付时间、等待时长
- [ ] 等待时长按阈值显示红/黄/绿色
- [ ] 发货 Modal 物流公司选择 + 物流单号输入校验非空
- [ ] 发货成功后从列表移除并刷新统计条
- [ ] 待办统计条 60 秒轮询刷新
- **性能要求**：首屏加载 < 1.5s；表格 >100 行虚拟滚动；发货响应 < 1s。
- **可访问性**：表格有 `aria-label="待发货订单列表"`；发货按钮有 `aria-label`；等待时长有 `aria-label`；对比度满足 WCAG AA。

> **补充功能说明**：当前后端 `OrdersController` 卖家端仅有 `POST /api/seller/orders/{id}/ship` 发货端点，无卖家订单列表查询端点。本页面需后端新增 `GET /api/seller/orders?status=Paid&page=1&pageSize=20` 端点，按当前卖家 SellerId 过滤、支持状态与时间范围筛选。`OrderListQuery` 已支持 `SellerId` 与 `Status` 字段，仅需在 Controller 层新增 Seller 角色端点复用现有 QueryHandler。
