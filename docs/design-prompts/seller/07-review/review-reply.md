# 评价回复 - 商家管理后台

## 1. 页面定位
- **所属端**：商家管理后台
- **所属模块**：07-review（评价管理）
- **页面类型**：列表页 + 抽屉表单（含回复编辑）
- **目标用户**：卖家（Seller）
- **核心目标**：卖家查看本店铺商品收到的评价，按状态/评分/回复情况筛选，对未回复评价进行回复，对已回复评价查看或编辑回复。
- **访问入口**：Sider「评价管理 → 评价回复」；URL `/reviews`；工作台「待回复评价 N 条」快捷入口。
- **实现状态**：➕ 补充功能（列表端点待补充，回复端点已实现）

- **整体布局**：顶部面包屑 + 筛选栏 + 评价列表（卡片瀑布流）+ 右侧回复抽屉。

## 3. 数据模型与 API 对接
- **服务归属**：Review 域（旧域 ReviewAfterSales 双轨兜底，端点路径不变；列表由 `SellerReviewsController` 接管，回复由 `ReviewsController` 接管）
- **主要 API**：

| 方法 | 端点 | 用途 | 鉴权 |
|-|-|-|-|
| GET | `/api/seller/reviews` | 卖家查询本店铺商品评价（按评分/回复状态/时间过滤、分页）（补充端点） | Seller（补充） |
| POST | `/api/reviews/{id}/reply` | 卖家回复评价，附 `content` | Seller |

- **请求参数**：
  - 列表查询：`int? rating`（1-5 评分过滤，不传则全部）、`bool? replied`（true=已回复 / false=待回复 / null=全部）、`string? productName`（商品名称模糊搜索）、`DateTime? startDate?`、`DateTime? endDate?`、`int page`（1-based，默认 1）、`int pageSize`（默认 20）。后端从 JWT 注入 `sellerId`，仅返回本店铺商品评价，且仅返回 `status=Approved`（已通过）的评价（`Hidden` 状态对卖家不可见）。
  - 回复：`SellerReplyDto { content: string }`，必填，长度 1-500。
- **响应字段**：列表返回 `ReviewListResultDto` 含 `items[]`（每个 `ReviewDto` 含 `reviewId`、`orderId`、`orderLineId`、`spuId`、`skuId`、`userId`、`rating`（1-5）、`content`、`images[]`、`status`（仅返回 Approved=1）、`sellerReplyContent?`、`sellerReplyBy?`、`sellerReplyAt?`、`submittedAt`、`auditedAt?`）、`total`、`page`、`pageSize`。回复操作返回 `ApiResponse`（无 data）。
- **数据加载策略**：进入页面加载第一页（全部评分、全部回复状态）；筛选条件变更立即重新查询；商品名称搜索 300ms 防抖。
- **缓存策略**：不缓存，评价数据需实时反映回复状态。

## 4. 交互流程
- **主流程**：
  1. 卖家进入页面 → 调用 `GET /api/seller/reviews?page=1&pageSize=20` → 渲染筛选栏统计与评价卡片列表。
  2. 卖家选择评分/回复状态/输入商品名/选择时间范围 → 重新查询（商品名 300ms 防抖）。
  3. 卖家点击未回复评价的「回复」按钮 → 右侧抽屉滑出，展示评价摘要 + 回复表单 → 输入回复内容（必填，1-500 字，实时字数统计）→ 点击「提交」→ 调用 `POST /api/reviews/{id}/reply` → 成功 `message.success('回复成功')` → 关闭抽屉，刷新当前页。
  4. 卖家点击已回复评价的「编辑回复」按钮 → 右侧抽屉滑出，回复表单回填原 `sellerReplyContent` → 修改后提交 → 调用 `POST /api/reviews/{id}/reply`（覆盖原回复）→ 成功 `message.success('回复已更新')` → 关闭抽屉，刷新当前页。
- **分支流程**：
  - 评价正文超 3 行：折叠显示，点击「展开」查看全文，点击「收起」折叠。
  - 凭证图片组：缩略图 80×80px，点击调起 `<a-image-preview-group>` 全屏预览，支持左右切换。
  - 商品快照点击：跳转 `/products/:spuId/edit`（商品编辑页）。
  - 回复内容超长：表单字数统计超 500 字时红色提示并禁用提交按钮。
- **跨页面流转**：商品快照点击跳商品编辑页；回复操作停留在列表页刷新。
- **状态机可视化**：评价状态仅 `Approved` 对卖家可见（`Hidden` 状态卖家侧不展示）；回复状态机：未回复 →（卖家回复）→ 已回复 →（卖家编辑）→ 已回复（覆盖）。

## 7. 异常处理与边界
- **加载态**：进入页面 `<a-skeleton>` 模拟 3 张评价卡；筛选时列表 `<a-spin>`；凭证图片 `<a-skeleton-image>`。
- **空数据**：`<EmptyState>` 展示无评价。
- **错误态**：网络错误 `message.error('网络异常')`；403 `message.error('无权限访问')`；回复失败展示后端 `response.data.message`（如「评价不存在」「当前状态不可回复」「非本店铺评价」）。
- **权限控制**：需卖家登录态；后端按 JWT `sellerId` 关联店铺商品过滤，卖家仅查看与回复本店铺商品评价；非本店铺评价回复返回 403。
- **并发与乐观锁**：回复操作后端校验评价归属与状态，已隐藏评价不可回复（返回错误提示「该评价已不可回复」）；编辑回复为覆盖式，无乐观锁冲突。
- **危险操作确认**：回复操作非危险操作无需二次确认；编辑回复时若内容有改动，关闭抽屉前 `Modal.confirm` 提示「确认放弃当前编辑内容？」避免误关丢失输入。

> **补充功能说明**：当前后端 `ReviewsController` 卖家端仅有回复端点（`POST /api/reviews/{id}/reply`），无卖家侧评价列表查询端点。本页面需后端新增 `GET /api/seller/reviews` 端点，新增 `IReviewAppService.GetBySellerAsync(sellerId, rating?, replied?, productName?, startDate?, endDate?, page, pageSize)` 方法，通过 Review 聚合关联 SPU 的 `sellerId` 过滤本店铺评价，且仅返回 `status=Approved` 的评价（`Hidden` 状态对卖家不可见）。回复端点已实现，可直接对接；编辑回复为覆盖式调用同一端点。
