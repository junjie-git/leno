# 售后详情 - 商家管理后台

## 1. 页面定位
- **所属端**：商家管理后台
- **所属模块**：06-after-sales（售后处理）
- **页面类型**：详情页 + 表单页（含审核/驳回/确认收货操作）
- **目标用户**：卖家（Seller）
- **核心目标**：卖家查看单条售后单完整信息（申请原因、凭证、退款金额、状态轨迹），并执行审核同意、驳回、确认收货等处理动作。
- **访问入口**：售后列表「查看」按钮跳转 `/after-sales/:id`；Header 待办 Badge 跳转列表后进入；URL `/after-sales/:id`。
- **实现状态**：➕ 补充功能（详情查询端点待补充，操作端点已实现）

## 2. 页面布局与信息架构
- **整体布局**：顶部面包屑 + 状态摘要卡 + 左右两栏（左侧主信息 + 右侧操作面板）+ 底部状态时间线。
- **关键区域**：
  - 区域 A（面包屑）：首页 / 售后处理 / 售后列表 / 售后详情 AS2026072601。
  - 区域 B（状态摘要卡 `<a-card>`）：售后单号、当前状态（StatusTag 大号）、售后类型 Tag、申请金额、已同意金额、已退款金额、申请时间、买家标识（脱敏）。
  - 区域 C（左侧主信息，`<a-descriptions>` + 卡片组合）：
    - C1 申请信息：原因分类、详细原因、凭证图片组（`<a-image-preview-group>` 可放大）。
    - C2 订单信息：订单编号、订单行编号（如适用）、商品快照（图 + 标题 + SKU + 数量 + 单价）。
    - C3 退货物流（退货退款类型且已退货态显示）：物流单号、买家退货时间。
    - C4 退款信息（已进入退款流程显示）：渠道退款单号、退款金额、退款时间、失败原因（如适用）。
  - 区域 D（右侧操作面板 `<a-card>` sticky）：根据当前状态动态显示操作按钮组：
    - 待审核态：同意审核（主按钮）+ 驳回（危险按钮）。
    - 已退货态（退货退款）：确认收货（主按钮）。
    - 其他态：仅显示「当前无待处理操作」提示。
  - 区域 E（状态时间线 `<a-timeline>`）：按时间倒序展示状态流转节点（申请、审核、退货、确认收货、退款、完成/失败/驳回/撤销），每节点含时间、操作人、状态文案。
- **响应式断点**：≥1200px 左右两栏（左 16 / 右 8 栅格）；992-1199px 单栏堆叠，操作面板置顶 sticky；<992px 不支持。
- **首屏内容**：状态摘要卡 + 申请信息 + 操作面板。

## 3. 数据模型与 API 对接
- **主要 API**：

| 方法 | 端点 | 用途 | 鉴权 |
|-|-|-|-|
| GET | `/api/seller/after-sales/{id}` | 卖家查询售后单详情（补充端点） | Seller（补充） |
| POST | `/api/seller/after-sales/{id}/approve` | 卖家审核同意售后，录入 `approvedAmount` | Seller |
| POST | `/api/seller/after-sales/{id}/reject` | 卖家驳回售后，附 `reason` | Seller |
| POST | `/api/seller/after-sales/{id}/confirm-return` | 卖家确认收到退货 | Seller |

- **请求参数**：
  - 详情查询：路径参数 `id`（售后单 ID），后端校验 `sellerId` 归属。
  - 同意：`ApproveAfterSalesDto { approvedAmount: decimal }`，须 > 0 且 ≤ `requestedAmount`。
  - 驳回：`RejectAfterSalesDto { reason: string }`，必填，长度 1-200。
  - 确认收货：无请求体。
- **响应字段**：详情返回 `AfterSalesDto`（同列表项字段全集）；操作类返回 `ApiResponse`（无 data）。
- **数据加载策略**：进入页面按路径 `id` 加载详情；操作成功后重新加载详情刷新状态与时间线。
- **缓存策略**：不缓存，售后单状态多变需实时获取。

## 4. 交互流程
- **主流程**：
  1. 卖家从列表/待办进入详情 → 调用 `GET /api/seller/after-sales/{id}` → 渲染状态摘要、申请信息、订单信息、操作面板、状态时间线。
  2. 待审核态：卖家在操作面板填写「同意金额」（默认填 `requestedAmount`，可下调）→ 点击「同意审核」→ `Modal.confirm` 二次确认 → 调用 `POST /api/seller/after-sales/{id}/approve` → 成功 `message.success('审核已同意')` → 重新加载详情。
  3. 待审核态：卖家点击「驳回」→ 弹出驳回原因输入框（`<a-textarea>` 必填）→ `Modal.confirm` 二次确认 → 调用 `POST /api/seller/after-sales/{id}/reject` → 成功 `message.success('已驳回')` → 重新加载详情。
  4. 已退货态（退货退款）：卖家点击「确认收货」→ `Modal.confirm` 二次确认（说明后果）→ 调用 `POST /api/seller/after-sales/{id}/confirm-return` → 成功 `message.success('已确认收货')` → 重新加载详情。
- **分支流程**：
  - 仅退款类型（`type=1`）：审核同意后不经过「已退货」「已确认收货」态，直接进入「退款中」，操作面板不显示确认收货按钮。
  - 退货退款类型（`type=0`）：审核同意后等待买家退货，买家填写物流单号后状态变为「已退货」，操作面板显示「确认收货」按钮。
  - 退款失败态：状态摘要卡显示 `failReason`，操作面板提示「请联系运营处理」。
  - 已驳回/已撤销/已完成态：操作面板仅显示「当前售后单已结束」。
- **跨页面流转**：操作完成后停留在详情页刷新；面包屑「售后列表」点击返回列表（携带 `from=detail` 触发列表刷新当前页）。
- **状态机可视化**：同售后列表，时间线组件按时间倒序展示节点，当前节点高亮主色 `#1677FF`，已发生节点为绿色 `#52C41A`，未发生节点为灰色 `#D9D9D9`。

## 7. 异常处理与边界
- **加载态**：进入页面 `<a-skeleton>` 模拟状态摘要卡 + 主信息布局；操作按钮提交时 `<a-spin>` 内嵌按钮 loading。
- **空数据**：售后单不存在（404）或无权访问（403）时展示 `EmptyState` 并提供返回列表 CTA。
- **错误态**：网络错误 `message.error('网络异常')`；403 `message.error('无权访问该售后单')`；404 `message.error('售后单不存在')`；操作失败展示后端 `response.data.message`（如「当前状态不允许此操作」「同意金额超出申请金额」）。
- **权限控制**：需卖家登录态；后端按 JWT `sellerId` 校验售后单归属，非本店售后单返回 403。
- **并发与乐观锁**：操作前重新加载详情确认当前状态（避免基于过期状态操作）；后端聚合根状态机校验防止并发操作（如买家撤销与卖家同意并发，后端返回状态冲突错误，前端提示并刷新）。
- **危险操作确认**：
  - 同意审核：`Modal.confirm` 标题「确认同意售后」，内容「同意后买家将收到通知，{仅退款类型：退款将进入处理流程}/{退货退款类型：买家需寄回商品后卖家确认收货再退款}，此操作不可撤销。」，确认按钮主色。
  - 驳回：`Modal.confirm` 标题「确认驳回售后」，内容「驳回后买家可重新发起售后或撤销申请，此操作不可撤销。」，确认按钮危险色 `#FF4D4F`。
  - 确认收货：`Modal.confirm` 标题「确认收到退货」，内容「确认收货后售后单将进入退款流程，不可撤销。请确认已实际收到买家退回的商品。」，确认按钮主色。

## 8. 验收要点
- [ ] 详情页正确展示售后单号、状态、类型、金额、申请时间、买家标识（脱敏）
- [ ] 申请信息（原因分类、详细原因、凭证图片）完整展示，凭证可点击放大预览
- [ ] 订单信息展示订单号与商品快照（图、标题、SKU、数量、单价）
- [ ] 退货退款类型且已退货态显示退货物流单号与退货时间
- [ ] 退款信息（渠道退款单号、退款金额、退款时间、失败原因）按状态显示
- [ ] 操作面板按状态动态显示按钮，待审核显示同意+驳回，已退货显示确认收货
- [ ] 同意金额默认填 `requestedAmount`，可下调但不超过申请金额
- [ ] 驳回原因必填且长度 1-200，提交前二次确认
- [ ] 状态时间线按时间倒序展示节点，当前节点高亮
- [ ] 操作成功后重新加载详情刷新状态与时间线
- **性能要求**：首屏加载 < 1.5s；凭证图片懒加载；操作响应 < 1s。
- **可访问性**：表单字段有 `label` 与 `aria-label`；按钮有 `aria-label`；图片有 `alt` 文本；时间线节点有 `aria-label`；对比度满足 WCAG AA。

> **补充功能说明**：当前后端 `AfterSalesController` 卖家端仅有列表查询（`GET /api/seller/after-sales`）与三个操作端点（approve / reject / confirm-return），无单条详情查询端点。本页面需后端新增 `GET /api/seller/after-sales/{id}` 端点，复用 `IAfterSalesAppService` 现有聚合根加载逻辑，新增按 `afterSalesId` + `sellerId` 归属校验的查询方法，返回 `AfterSalesDto`。操作端点已实现，可直接对接。
