# 售后列表 - 商家管理后台

## 1. 页面定位
- **所属端**：商家管理后台
- **所属模块**：06-after-sales（售后处理）
- **页面类型**：列表页
- **目标用户**：卖家（Seller）
- **核心目标**：卖家查看买家发起的全部售后单，按状态/类型筛选，快速进入详情完成审核、确认收货等处理动作。
- **访问入口**：Sider「售后处理 → 售后列表」；URL `/after-sales`；Header 顶部「售后待处理 N 单」红色 Badge 点击直达且默认筛选「待审核」。
- **实现状态**：✅ 已实现

## 2. 页面布局与信息架构
- **整体布局**：顶部面包屑 + 状态标签页 + 筛选栏 + 售后表格 + 底部分页。
- **关键区域**：
  - 区域 A（面包屑）：首页 / 售后处理 / 售后列表。
  - 区域 B（状态标签页 `<a-tabs>`）：全部 / 待审核 / 已同意 / 已退货 / 已确认收货 / 退款中 / 已完成 / 已驳回 / 已撤销，每个标签显示对应数量 Badge。其中「待审核」「已退货」为卖家待办高优先级标签，前置并加红点提示。
  - 区域 C（筛选栏）：售后单号搜索（`<a-input-search>`，支持模糊匹配）+ 售后类型（`<a-select>`：全部 / 退货退款 / 仅退款）+ 订单编号搜索 + 申请时间范围（`<a-range-picker>`）。
  - 区域 D（售后表格 `<a-table>`）：列含售后单号、订单编号、售后类型、申请原因分类、申请金额、状态（StatusTag）、买家标识（脱敏）、申请时间、操作。可展开行查看明细（商品快照、原因描述、凭证图片缩略图）。
  - 区域 E（分页）：`<a-pagination>` 右对齐，默认 20 条/页，可切换 10/20/50。
- **响应式断点**：≥1200px 表格全宽；992-1199px 表格横向滚动 `:scroll="{ x: 1280 }"`；<992px 不支持。
- **首屏内容**：状态标签页 + 筛选栏 + 表格前 20 行。

## 3. 数据模型与 API 对接
- **主要 API**：

| 方法 | 端点 | 用途 | 鉴权 |
|-|-|-|-|
| GET | `/api/seller/after-sales` | 卖家查询收到的售后单（按状态过滤、分页） | Seller |

- **请求参数**：`AfterSalesStatus? status`（可选状态过滤，不传则查全部）、`int page`（1-based，默认 1）、`int pageSize`（默认 20）。后端从 JWT 注入 `sellerId`，仅返回本店铺售后单。
- **响应字段**：`AfterSalesListResultDto` 含 `items[]`（每个 `AfterSalesDto` 含 `afterSalesId`、`orderId`、`orderLineId?`、`userId`、`sellerId`、`type`（0=ReturnRefund / 1=RefundOnly）、`reasonCategory`、`reason`、`images[]`、`requestedAmount`、`currency`、`approvedAmount?`、`refundedAmount?`、`status`（0-8 枚举）、`appliedAt`、`approvedAt?`、`rejectedAt?`、`refundedAt?`、`rejectReason?`、`failReason?`、`cancelledAt?`、`cancelReason?`、`returnedAt?`、`trackingNo?`、`returnConfirmedAt?`）、`total`、`page`、`pageSize`。
- **数据加载策略**：进入页面加载第一页（全部状态）；状态标签切换带 `status` 参数重新查询；筛选条件变更（除单号搜索外）立即重新查询；单号搜索 300ms 防抖。
- **缓存策略**：不缓存，售后数据时效性高。状态标签数量 Badge 随列表查询结果 `total` 实时更新（不单独发请求）。

## 4. 交互流程
- **主流程**：
  1. 卖家进入页面 → 调用 `GET /api/seller/after-sales?page=1&pageSize=20` → 渲染表格与状态标签数量。
  2. 卖家切换状态标签（如「待审核」）→ 带 `status=0` 参数重新查询 → 刷新表格。
  3. 卖家输入售后单号/订单号、选择类型、选择申请时间范围 → 重新查询（单号 300ms 防抖）。
  4. 卖家点击「查看」→ 跳转 `/after-sales/:id` 进入详情页处理。
  5. 卖家点击展开行 → 查看售后明细（原因描述、凭证图片缩略图、退款金额构成）。
- **分支流程**：
  - 待审核态（`status=0`）：操作列高亮「立即处理」按钮，引导进入详情审核。
  - 已退货态（`status=7`，退货退款类型）：操作列高亮「确认收货」按钮，可在此直接触发或跳详情处理。
  - 已驳回/已撤销/已完成/退款失败态：操作列仅「查看」。
- **跨页面流转**：点击「查看」跳转 `/after-sales/:id` 携带 `from=list` 参数；处理完成后返回列表自动刷新当前页。
- **状态机可视化**：售后状态流转：待审核 →（卖家同意）→ 已同意 →（买家退货，仅退货退款）→ 已退货 →（卖家确认收货）→ 已确认收货 → 退款中 →（退款成功）→ 已完成 /（退款失败）→ 退款失败；待审核 →（卖家驳回）→ 已驳回；待审核 →（买家撤销）→ 已撤销。终态：已完成、退款失败、已驳回、已撤销。

## 6. 视觉规范
- **主色应用**：状态标签页激活态、售后单号链接、操作按钮主色 `#1677FF`；待办红点使用危险色 `#FF4D4F`。
- **状态色**：待审核/已同意/已退货/已确认收货/退款中黄 `#FAAD14`、已完成绿 `#52C41A`、已驳回/退款失败红 `#FF4D4F`、已撤销灰 `#8C8C8C`（由 StatusTag 按 `AfterSalesStatus` 枚举映射，未匹配降级灰）。
- **间距**：标签页与筛选栏 `16px`，筛选栏与表格 `16px`，表格行高 `56px`，单元格内边距 `12px`，凭证缩略图组间距 `8px`。
- **字体**：页面标题 `20px` medium，表格 `14px` normal，金额 `14px` semibold，售后单号 `14px` semibold（等宽字体优先），原因分类 `12px` `#8C8C8C`。
- **图标尺寸**：操作图标 `16px`，凭证缩略图 `40×40px` 圆角 `4px`，待办红点 `8px`。

## 7. 异常处理与边界
- **加载态**：进入页面 `<a-skeleton>` 模拟表格 5 行；标签切换/筛选时表格 `<a-spin>`；凭证缩略图 `<a-skeleton-image>`。
- **空数据**：`<EmptyState>` 展示无售后单。
- **错误态**：网络错误 `message.error('网络异常')`；403 `message.error('无权限访问')`；查询失败展示后端 `response.data.message`。
- **权限控制**：需卖家登录态；后端按 JWT `sellerId` 过滤，卖家仅查看本店铺售后单；非本店售后单 404 处理为「售后单不存在」。
- **并发与乐观锁**：列表页无编辑操作，无乐观锁冲突；审核/确认收货在详情页处理。
- **危险操作确认**：列表页仅查看与跳转，无危险操作；快捷「确认收货」按钮触发前 `Modal.confirm` 二次确认（后果：确认收货后将进入退款流程，不可撤销）。
