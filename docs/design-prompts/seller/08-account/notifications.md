# 通知中心 - 商家管理后台

## 1. 页面定位
- **所属端**：商家管理后台
- **所属模块**：08-account（个人账号）
- **页面类型**：列表页（站内信管理）
- **目标用户**：卖家（Seller）
- **核心目标**：卖家查看站内通知（订单、售后、评价、系统公告等），按已读/未读筛选，单条或批量标记已读，跳转关联业务页面。
- **访问入口**：Header 右上角铃铛图标点击 → 抽屉模式快速预览 → 「查看全部」跳转本页；Sider「个人中心 → 通知中心」；URL `/account/notifications`。
- **实现状态**：✅ 已实现

## 2. 页面布局与信息架构
- **整体布局**：顶部面包屑 + 状态标签页 + 操作工具栏 + 通知列表 + 底部分页。
- **关键区域**：
  - 区域 A（面包屑）：首页 / 个人中心 / 通知中心。
  - 区域 B（状态标签页 `<a-tabs>`）：全部 / 未读 / 已读，每个标签显示对应数量 Badge，未读标签红色高亮 + 数量 Badge。
  - 区域 C（操作工具栏）：左侧「全部标记已读」按钮（仅未读 > 0 时显示）+ 批量选择checkbox；右侧通知类型筛选（`<a-select>`：全部 / 订单 / 售后 / 评价 / 系统）。
  - 区域 D（通知列表 `<a-list>` + `<a-list-item>`）：每条通知含：
    - D1 左侧状态指示：未读蓝点 `#1677FF` 8px / 已读无标记。
    - D2 通知图标：按 `templateCode` 映射业务图标（订单 ShoppingCartOutlined、售后 SolutionOutlined、评价 StarOutlined、系统 NotificationOutlined）。
    - D3 通知内容：标题（`<a-typography-text>` strong）+ 摘要正文（超 2 行折叠）+ 关联业务链接（如「查看订单 NO2026072601」点击跳转）。
    - D4 时间：相对时间（如「5 分钟前」「昨天 14:00」），hover 显示绝对时间 tooltip。
    - D5 操作：单条「标记已读」（未读态显示）/ 「跳转处理」（有关联业务时显示）。
  - 区域 E（分页）：`<a-pagination>` 右对齐，默认 20 条/页，可切换 10/20/50。
- **响应式断点**：≥1200px 列表全宽；992-1199px 列表全宽，操作图标文字隐藏；<992px 不支持。
- **首屏内容**：状态标签页 + 工具栏 + 通知列表前 20 条。

## 3. 数据模型与 API 对接
- **主要 API**：

| 方法 | 端点 | 用途 | 鉴权 |
|-|-|-|-|
| GET | `/api/notifications` | 分页查询站内信，支持 `isRead` 过滤 | Seller |
| GET | `/api/notifications/unread-count` | 获取未读通知计数（Header 铃铛 Badge 用） | Seller |
| POST | `/api/notifications/read` | 按 `recordIds` 批量标记已读 | Seller |
| POST | `/api/notifications/read-all` | 全部标记已读 | Seller |

- **请求参数**：
  - 列表查询：`bool? isRead`（true=已读 / false=未读 / null=全部）、`int page`（1-based，默认 1）、`int pageSize`（默认 20）。
  - 未读计数：无参数。
  - 批量已读：`MarkAsReadDto { recordIds: Guid[] }`。
  - 全部已读：无请求体。
- **响应字段**：列表返回 `NotificationListResultDto { items[]: NotificationRecordDto { recordId, userId, templateCode, channel, title, content, status, isRead, sentAt?, createdAt }, total, unreadCount, page, pageSize }`；未读计数返回 `int`；标记已读返回 `ApiResponse`（无 data）。
- **数据加载策略**：进入页面加载第一页（全部状态）；状态标签切换带 `isRead` 参数重新查询；标记已读后刷新当前页与未读计数。
- **缓存策略**：不缓存，通知数据需实时反映已读状态；Header 铃铛未读计数通过独立接口 `GET /api/notifications/unread-count` 每 60 秒轮询刷新。

## 4. 交互流程
- **主流程**：
  1. 卖家进入页面 → 调用 `GET /api/notifications?page=1&pageSize=20` → 渲染标签页数量 Badge 与通知列表。
  2. 卖家切换状态标签（如「未读」）→ 带 `isRead=false` 参数重新查询 → 刷新列表。
  3. 卖家点击单条「标记已读」→ 调用 `POST /api/notifications/read` 携带 `recordIds: [当前记录ID]` → 成功后该条蓝点消失，更新未读 Badge。
  4. 卖家勾选多条通知 + 点击「批量标记已读」→ 调用 `POST /api/notifications/read` 携带 `recordIds: [选中记录ID数组]` → 成功 `message.success('已标记 N 条为已读')` → 刷新列表。
  5. 卖家点击「全部标记已读」→ `Modal.confirm` 二次确认 → 调用 `POST /api/notifications/read-all` → 成功 `message.success('全部已标记为已读')` → 刷新列表与未读计数。
  6. 卖家点击「查看订单」/「处理售后」/「回复评价」→ 跳转对应业务页面（携带订单号/售后单号/评价 ID）。
- **分支流程**：
  - 通知正文超 2 行：折叠显示，点击「展开」查看全文。
  - 无关联业务的通知（如系统公告）：仅显示「标记已读」，无跳转按钮。
  - 未读数为 0：「全部标记已读」按钮隐藏。
- **跨页面流转**：点击业务跳转按钮跳转对应页面（订单详情、售后详情、评价回复）；标记已读停留在本页。
- **状态机可视化**：通知已读状态机：未读 →（单条标记/批量标记/全部标记）→ 已读；不可逆。

## 6. 视觉规范
- **主色应用**：未读蓝点、跳转链接、分页激活态主色 `#1677FF`；通知图标背景主色浅 `#E6F4FF`，图标主色 `#1677FF`。
- **状态色**：未读蓝点 `#1677FF`；已读无标记；未读标签 Badge 红色 `#FF4D4F`（数量 > 0 时）。
- **间距**：标签页与工具栏 `16px`，工具栏与列表 `16px`，列表项间距 `12px`，列表项内边距 `16px`，图标与内容间距 `12px`，蓝点与图标间距 `8px`。
- **字体**：页面标题 `20px` medium，通知标题 `14px` medium `#000000D9`，通知正文 `14px` normal `#595959`，时间 `12px` `#8C8C8C`，跳转链接 `14px` 主色。
- **图标尺寸**：通知图标 `32×32px` 圆形背景，图标 `16px`；未读蓝点 `8px`；业务跳转图标 `14px`。

## 7. 异常处理与边界
- **加载态**：进入页面 `<a-skeleton>` 模拟 5 条通知布局；标签切换时列表 `<a-spin>`；标记已读按钮 loading。
- **空数据**：`<EmptyState>` 展示无通知（按状态显示「暂无未读通知」/「暂无已读通知」/「暂无通知」）。
- **错误态**：网络错误 `message.error('网络异常')`；401 跳转登录页；403 `message.error('无权限访问')`；标记已读失败展示后端 `response.data.message`。
- **权限控制**：需登录态；后端按 JWT `userId` 过滤，仅返回当前用户的通知。
- **并发与乐观锁**：标记已读为幂等操作，重复标记无副作用；批量标记已读后端逐条处理，部分失败不影响其他。
- **危险操作确认**：全部标记已读 `Modal.confirm` 标题「确认全部标记已读」，内容「将把所有未读通知标记为已读，此操作不可撤销。」，确认按钮主色（非危险操作，但量大时确认）。

- [ ] 切换标签按 `isRead` 过滤并刷新列表
- [ ] 通知列表展示图标、标题、摘要正文、时间、跳转链接
- [ ] 未读通知左侧显示蓝点，已读无标记
- [ ] 通知正文超 2 行折叠，可展开/收起
- [ ] 单条「标记已读」生效，蓝点消失，未读 Badge 更新
- [ ] 批量勾选 + 批量标记已读生效
- [ ] 「全部标记已读」二次确认后生效
- [ ] 业务跳转链接跳转对应页面（订单/售后/评价）
- [ ] Header 铃铛未读计数与本页未读数同步
- **性能要求**：首屏加载 < 1.5s；通知列表 >50 条可启用虚拟滚动；标记已读响应 < 500ms；Header 未读计数 60 秒轮询。
- **可访问性**：列表有 `aria-label="通知列表"`；标签页有 `aria-label`；未读蓝点有 `aria-label="未读"`；按钮有 `aria-label`；对比度满足 WCAG AA；支持 Tab 键导航。
