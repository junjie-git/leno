# 个人资料 - 商家管理后台

## 1. 页面定位
- **所属端**：商家管理后台
- **所属模块**：08-account（个人账号）
- **页面类型**：表单页（含资料编辑与密码修改两个区块）
- **目标用户**：卖家（Seller）
- **核心目标**：卖家查看与编辑个人资料（昵称、头像），修改登录密码，管理账号安全。
- **访问入口**：Header 用户头像下拉菜单「个人中心」；Sider「个人中心 → 个人资料」；URL `/account/profile`。
- **实现状态**：✅ 已实现

## 2. 页面布局与信息架构
- **整体布局**：顶部面包屑 + 左右两栏（左侧资料编辑表单 + 右侧账号信息与安全设置）。
- **关键区域**：
  - 区域 A（面包屑）：首页 / 个人中心 / 个人资料。
  - 区域 B（左侧资料编辑 `<a-card>` 标题「基本资料」）：头像上传（圆形头像 + 「更换头像」按钮，点击调起上传）+ 昵称输入框（`<a-input>` 1-32 字符）+ 用户名（只读）+ 邮箱（只读，脱敏）+ 手机号（只读，脱敏）+ 保存按钮。
  - 区域 C（右侧账号信息与安全 `<a-card>` 标题「账号安全」）：
    - C1 账号信息：账号状态（StatusTag）、角色（Seller Tag）、注册时间、最后更新时间。
    - C2 密码修改：旧密码 + 新密码 + 确认新密码 + 修改密码按钮，密码强度提示（弱/中/强）。
    - C3 双因子认证：状态开关（已启用/未启用），启用/禁用按钮（已启用显示「禁用」，未启用显示「启用」）。
- **响应式断点**：≥1200px 左右两栏（左 14 / 右 10 栅格）；992-1199px 单栏堆叠；<992px 不支持。
- **首屏内容**：基本资料卡（含头像、昵称、只读字段）+ 账号安全卡（账号信息 + 密码修改 + 双因子）。

## 3. 数据模型与 API 对接
- **服务归属**：Identity 域（旧域 UserAuth 双轨兜底，端点路径不变；由 `UsersController` 接管 `/api/users/me`、密码与双因子流程）
- **主要 API**：

| 方法 | 端点 | 用途 | 鉴权 |
|-|-|-|-|
| GET | `/api/users/me` | 查询当前用户资料 | 已认证 |
| PUT | `/api/users/me` | 修改当前用户资料（昵称、头像） | 已认证 |
| PUT | `/api/users/me/password` | 修改当前用户密码 | 已认证 |
| POST | `/api/users/me/two-factor/enable` | 启用双因子认证，生成密钥与 QR 码 | 已认证 |
| POST | `/api/users/me/two-factor/confirm` | 确认启用双因子，验证 TOTP 码 | 已认证 |
| POST | `/api/users/me/two-factor/disable` | 禁用双因子认证 | 已认证 |

- **请求参数**：
  - 修改资料：`UpdateProfileDto { nickname: string (1-32), avatarUrl?: string (HTTPS) }`。
  - 修改密码：`ChangePasswordDto { oldPassword: string, newPassword: string (8-64，至少含字母与数字) }`。
  - 启用双因子：无请求体，返回 `TwoFactorEnableResponseDto`（含 QR 码 URI 与密钥）。
  - 确认双因子：`TwoFactorConfirmDto { code: string }`（6 位 TOTP 码）。
  - 禁用双因子：无请求体。
- **响应字段**：资料查询返回 `UserDto { id, username, email?, phoneNumber?, nickname, avatarUrl?, status, roles[], defaultAddressId?, createdAt, updatedAt }`；资料修改返回更新后的 `UserDto`；密码修改与双因子操作返回 `ApiResponse`（无 data 或含成功消息）；双因子启用返回 `TwoFactorEnableResponseDto`。
- **数据加载策略**：进入页面调用 `GET /api/users/me` 加载资料；表单回填昵称与头像；账号信息展示状态、角色、时间。
- **缓存策略**：资料缓存于 Pinia `useAuthStore`（与 Header 用户菜单共享），修改后同步更新 Store。

## 4. 交互流程
- **主流程**：
  1. 卖家进入页面 → 调用 `GET /api/users/me` → 回填昵称、头像、用户名、邮箱（脱敏）、手机号（脱敏）、账号信息。
  2. 卖家修改昵称 → 失焦校验长度 1-32 → 点击「保存」→ 调用 `PUT /api/users/me` → 成功 `message.success('资料保存成功')` → 同步更新 `useAuthStore` 与 Header 显示。
  3. 卖家点击「更换头像」→ 调起文件选择 → 上传图片（调用文件上传服务，返回 URL）→ 预览头像 → 点击「保存」→ 调用 `PUT /api/users/me` 携带新 `avatarUrl`。
  4. 卖家修改密码 → 输入旧密码、新密码、确认新密码 → 实时密码强度提示 → 点击「修改密码」→ `Modal.confirm` 二次确认 → 调用 `PUT /api/users/me/password` → 成功 `message.success('密码修改成功，请重新登录')` → 清除令牌跳转登录页。
  5. 卖家点击「启用」双因子 → 调用 `POST /api/users/me/two-factor/enable` → 弹窗展示 QR 码与密钥 → 卖家用 Authenticator App 扫码 → 输入 6 位 TOTP 码 → 调用 `POST /api/users/me/two-factor/confirm` → 成功 `message.success('双因子认证已启用')` → 更新状态。
  6. 卖家点击「禁用」双因子 → `Modal.confirm` 二次确认（危险操作）→ 调用 `POST /api/users/me/two-factor/disable` → 成功 `message.success('双因子认证已禁用')` → 更新状态。
- **分支流程**：
  - 昵称校验失败：输入框下方红色提示「昵称长度需在 1-32 字符之间」，禁用保存按钮。
  - 新密码与确认密码不一致：确认密码框红色提示「两次输入的密码不一致」。
  - 密码强度弱：新密码框下方黄色提示「密码强度弱，建议包含大小写字母与数字」。
  - 旧密码错误：`message.error('旧密码错误')`，旧密码框清空聚焦。
- **跨页面流转**：修改密码成功后跳转登录页重新登录；其他操作停留在本页。
- **状态机可视化**：双因子状态机：未启用 →（启用，扫码+验证）→ 已启用；已启用 →（禁用，二次确认）→ 未启用。

## 7. 异常处理与边界
- **加载态**：进入页面 `<a-skeleton>` 模拟资料卡与安全卡布局；头像上传时按钮 `<a-spin>`；保存/修改密码/双因子操作按钮 loading。
- **空数据**：头像为空时显示默认占位图标；邮箱/手机号字段为空时显示「未绑定」。
- **错误态**：网络错误 `message.error('网络异常')`；401 跳转登录页；403 `message.error('无权限访问')`；旧密码错误 `message.error('旧密码错误')`；新密码不符合规则 `message.error('密码需 8-64 位且至少含字母与数字')`；双因子验证码错误 `message.error('验证码错误')`。
- **权限控制**：需登录态；用户只能查看与修改自己的资料。
- **并发与乐观锁**：资料修改无乐观锁（最后写入胜出）；密码修改后端校验旧密码正确性；双因子操作后端校验当前状态防止并发冲突。
- **危险操作确认**：
  - 修改密码：`Modal.confirm` 标题「确认修改密码」，内容「修改密码后将退出当前登录，需使用新密码重新登录。」，确认按钮主色。
  - 禁用双因子：`Modal.confirm` 标题「确认禁用双因子认证」，内容「禁用后账号安全性将降低，建议保持启用。此操作可逆，可随时重新启用。」，确认按钮危险色 `#FF4D4F`。

## 8. 验收要点
- [ ] 资料卡正确展示头像、昵称（可编辑）、用户名、邮箱（脱敏）、手机号（脱敏）
- [ ] 头像上传支持图片选择与预览，保存后同步更新
- [ ] 昵称校验长度 1-32，失焦校验，保存按钮按校验状态禁用
- [ ] 账号信息卡展示状态、角色、注册时间、最后更新时间
- [ ] 密码修改表单含旧密码、新密码、确认新密码，实时密码强度提示
- [ ] 新密码校验规则（8-64 位，至少含字母与数字），两次密码一致校验
- [ ] 修改密码成功后清除令牌跳转登录页
- [ ] 双因子认证状态正确展示，启用流程含 QR 码展示与 TOTP 验证
- [ ] 禁用双因子需二次确认
- [ ] 资料修改后同步更新 Header 用户菜单显示
- **性能要求**：首屏加载 < 1.5s；头像上传 < 3s；保存响应 < 1s。
- **可访问性**：表单字段有 `label` 与 `aria-label`；头像上传按钮有 `aria-label`；密码强度有 `aria-label`；对比度满足 WCAG AA；支持 Tab 键导航。
