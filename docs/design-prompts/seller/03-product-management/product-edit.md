# 商品编辑 - 商家管理后台

## 1. 页面定位
- **所属端**：商家管理后台
- **所属模块**：03-product-management（商品管理）
- **页面类型**：表单页
- **目标用户**：卖家（Seller）
- **核心目标**：卖家新增或编辑商品基础信息（标题、副标题、分类、品牌、图文详情、主图），完成后保存为草稿或提交审核。
- **访问入口**：商品列表「新增商品」/「编辑」按钮；URL `/products/new` 或 `/products/:id/edit`。
- **实现状态**：✅ 已实现

## 2. 页面布局与信息架构
- **整体布局**：顶部面包屑 + 顶部操作栏（保存草稿/提交审核/取消）+ 左侧主表单 + 右侧主图与预览。
- **关键区域**：
  - 区域 A（面包屑）：首页 / 商品管理 / 商品列表 / 新增商品（或编辑商品）。
  - 区域 B（操作栏）：「保存草稿」次按钮 + 「提交审核」主按钮 + 「取消」链接。编辑态额外显示商品状态 StatusTag。
  - 区域 C（主表单 `<a-form layout="vertical">`）：商品标题（2-100 字）、副标题（≤200 字）、分类（`<a-tree-select>` 仅叶子分类）、品牌（`<a-select>` 可搜索）、图文详情（富文本编辑器，≤50000 字）。
  - 区域 D（主图上传 `<a-upload>`）：拖拽排序主图列表（1-9 张，首张为主图），支持 JPG/PNG/WebP，单张 ≤5MB。
  - 区域 E（规格预览）：只读展示已有 SKU 规格组合，附「管理 SKU」链接跳转 SKU 管理页。
- **响应式断点**：≥1200px 左右两栏（16:8 栅格）；992-1199px 单栏堆叠；<992px 不支持。
- **首屏内容**：操作栏 + 主表单前 4 项 + 主图上传区。

## 3. 数据模型与 API 对接
- **主要 API**：

| 方法 | 端点 | 用途 | 鉴权 |
|-|-|-|-|
| POST | `/api/products` | 新增草稿商品 | Seller |
| PUT | `/api/products/{id}` | 更新商品基础信息 | Seller |
| GET | `/api/products/{id}` | 查询商品详情（编辑回填） | Seller |
| POST | `/api/products/{id}/submit` | 提交审核（保存后） | Seller |

- **请求参数**：`CreateProductDto` 含 `title`、`subtitle?`、`categoryId`、`brandId?`、`description`、`mainImages[]`、`detailImages?`、`specs[]`。`UpdateProductDto` 字段同上，用于编辑态。
- **响应字段**：`ProductDto` 含 `id`、`title`、`subtitle`、`categoryId`、`brandId`、`status`、`images[]`、`skus[]`、`specs[]`、`auditHistory[]`。编辑态回填表单。
- **数据加载策略**：编辑态进入页面调用 `GET /api/products/{id}` 回填表单；新增态无需加载。
- **缓存策略**：不缓存；表单未保存离开页面时 `Modal.confirm` 提示「有未保存的修改，确认离开？」。

## 4. 交互流程
- **主流程**：
  1. 卖家进入新增页 → 空表单 → 填写标题、分类、图文、上传主图 → 点击「保存草稿」→ 调用 `POST /api/products` → `message.success('已保存草稿')` → 跳转商品列表。
  2. 卖家进入编辑页 → 调用 `GET /api/products/{id}` 回填 → 修改字段 → 点击「保存草稿」→ 调用 `PUT /api/products/{id}` → `message.success('已保存')` → 留在本页。
  3. 卖家点击「提交审核」→ 先保存（POST 或 PUT）→ 再调用 `POST /api/products/{id}/submit` → `message.success('已提交审核')` → 跳转商品列表。
  4. 卖家上传主图 → `<a-upload>` 调用文件存储端点上传 → 返回 URL 填入 `mainImages[]` → 支持拖拽排序与删除。
- **分支流程**：
  - 待审核态商品：表单只读，操作栏仅显示「取消」，提示「商品审核中，暂不可编辑」。
  - 已上架态商品：可编辑，保存后产生 `ProductUpdatedEvent`，不影响已上架状态。
  - 表单校验失败：第一个错误字段滚动定位并红色高亮。
- **跨页面流转**：「管理 SKU」跳转 `/products/:id/skus`；保存成功跳转商品列表。
- **状态机可视化**：草稿 →（保存）→ 草稿；草稿 →（提交审核）→ 待审核；已驳回 →（编辑保存）→ 已驳回 →（提交审核）→ 待审核。

## 6. 视觉规范
- **主色应用**：「提交审核」主按钮、上传组件边框聚焦态使用主色 `#1677FF`。
- **状态色**：必填字段标签前红星 `#FF4D4F`；校验错误文字 `#FF4D4F`；审核中提示条 warning `#FAAD14`。
- **间距**：表单项间距 `16px`，左右栏间距 `24px`，主图缩略图间距 `8px`，操作栏与表单间距 `16px`。

## 7. 异常处理与边界
- **加载态**：编辑态进入页面 `<a-skeleton>` 模拟表单；保存时按钮 loading。
- **空数据**：不适用（表单页）。
- **错误态**：网络错误 `message.error('网络异常')`；403 `message.error('无权限访问')`；404（商品不存在）`message.error('商品不存在')` 并跳回列表；校验失败定位首字段。
- **权限控制**：需卖家登录态；后端校验商品 SellerId 与当前卖家一致，非本店商品返回 403。
- **并发与乐观锁**：`PUT /api/products/{id}` 携带 version 字段；冲突返回 409，提示「商品已被他人修改，请刷新后重试」。
- **危险操作确认**：未保存离开页面 `Modal.confirm` 提示「有未保存的修改，确认离开？此操作不可恢复。」；提交审核非危险操作，无二次确认。
