# 商品列表 - 商家管理后台

## 1. 页面定位
- **所属端**：商家管理后台
- **所属模块**：03-product-management（商品管理）
- **页面类型**：列表页
- **目标用户**：卖家（Seller）
- **核心目标**：卖家查看本店全部商品，按状态/分类/关键词筛选，并快速进入编辑、上架、下架等操作。
- **访问入口**：Sider「商品管理 → 商品列表」；工作台快捷入口「我的商品」。
- **实现状态**：✅ 已实现

## 2. 页面布局与信息架构
- **整体布局**：顶部面包屑 + 筛选栏 + 商品表格 + 底部分页。
- **关键区域**：
  - 区域 A（面包屑）：首页 / 商品管理 / 商品列表。
  - 区域 B（筛选栏）：关键词输入（`<a-input-search>` 防抖 300ms）+ 状态筛选（`<a-select>`：全部/草稿/待审核/已上架/已下架/已驳回）+ 分类筛选（`<a-tree-select>`）+ 「新增商品」主按钮。
  - 区域 C（商品表格 `<a-table>`）：列含主图（缩略图 48×48）、商品标题、价格区间（由 SKU 价格聚合）、库存合计、销量、状态（StatusTag）、更新时间、操作（编辑/提交审核/下架/重新上架）。>100 行虚拟滚动。
  - 区域 D（分页）：`<a-pagination>` 右对齐，默认 20 条/页，可切换 10/20/50。
- **响应式断点**：≥1200px 表格全宽；992-1199px 表格横向滚动；<992px 不支持。
- **首屏内容**：筛选栏 + 表格前 20 行。

## 3. 数据模型与 API 对接
- **主要 API**：

| 方法 | 端点 | 用途 | 鉴权 |
|-|-|-|-|
| GET | `/api/products` | 分页查询本店商品（后端按 ShopId 过滤） | Seller |
| POST | `/api/products/{id}/submit` | 提交审核 | Seller |
| POST | `/api/products/{id}/take-down` | 下架商品 | Seller |
| POST | `/api/products/{id}/republish` | 重新上架（进入待审核） | Seller |

- **请求参数**：`ProductQueryDto` 含 `keyword`、`status`、`categoryId`、`page`、`pageSize`。后端 `ApplyShopScope` 自动注入当前卖家 ShopId，仅返回本店商品。
- **响应字段**：`PageResult<ProductDto>` 含 `items[]`（每个商品含 `id`、`title`、`mainImageUrl`、`status`、`skus[]`（含 `price`、`stockQty`）、`createdAt`、`updatedAt`）。前端聚合 SKU 价格得出 `priceRange`（最小-最大），聚合 `stockQty` 得出库存合计。
- **数据加载策略**：进入页面加载第一页（20 条）；筛选条件变更重新加载；分页切换加载对应页。
- **缓存策略**：不缓存，每次查询实时拉取，保证状态时效性。

## 4. 交互流程
- **主流程**：
  1. 卖家进入页面 → 调用 `GET /api/products?page=1&pageSize=20` → 渲染表格。
  2. 卖家输入关键词 → 防抖 300ms 后带 `keyword` 重新查询。
  3. 卖家选择状态/分类筛选 → 重新查询。
  4. 卖家点击「新增商品」→ 跳转 `/products/new`。
  5. 卖家点击「编辑」→ 跳转 `/products/:id/edit`。
  6. 卖家点击「提交审核」（草稿/已驳回态）→ `Modal.confirm` 确认 → 调用 `POST /api/products/{id}/submit` → `message.success('已提交审核')` → 刷新当前行。
  7. 卖家点击「下架」（已上架态）→ `Modal.confirm` 确认（危险操作）→ 输入下架原因 → 调用 `POST /api/products/{id}/take-down` → `message.success('已下架')` → 刷新。
  8. 卖家点击「重新上架」（已下架态）→ 调用 `POST /api/products/{id}/republish` → `message.success('已重新提交审核')` → 刷新。
- **分支流程**：
  - 草稿/待审核/已驳回态：操作列仅显示「编辑」，无下架/上架按钮。
  - 已上架态：操作列显示「编辑」「下架」。
  - 已下架态：操作列显示「编辑」「重新上架」。
- **跨页面流转**：新增/编辑跳转商品编辑页；点击标题跳转商品编辑页。
- **状态机可视化**：商品状态流转：草稿 →（提交审核）→ 待审核 →（运营通过）→ 已上架 →（下架）→ 已下架 →（重新上架）→ 待审核；待审核 →（运营驳回）→ 已驳回 →（提交审核）→ 待审核。

- **主色应用**：「新增商品」主按钮、提交审核链接使用主色 `#1677FF`。
- **状态色**：草稿灰 `#8C8C8C`、待审核黄 `#FAAD14`、已上架绿 `#52C41A`、已下架灰 `#8C8C8C`、已驳回红 `#FF4D4F`（由 StatusTag 内部映射）。
- **间距**：筛选栏与表格间距 `16px`，表格行高 `56px`（含缩略图），单元格内边距 `12px`。
- **字体**：页面标题 `20px` medium，表格 `14px` normal，价格区间 `14px` semibold，销量辅助文字 `12px` `#8C8C8C`。

## 7. 异常处理与边界
- **加载态**：进入页面 `<a-skeleton>` 模拟表格 5 行；操作时按钮 loading。
- **空数据**：`<EmptyState>` 引导新增商品。
- **错误态**：网络错误 `message.error('网络异常')`；403 `message.error('无权限访问')`；查询失败展示后端原因。
- **权限控制**：需卖家登录态，后端自动按 ShopId 过滤，卖家无法查看他店商品。
- **并发与乐观锁**：列表页无编辑操作，无乐观锁冲突；下架/上架操作后端校验状态机合法性，非法状态返回 409，提示「商品状态已变更，请刷新后重试」。
- **危险操作确认**：下架操作使用 `ConfirmDialog`（danger=true），内容「下架后商品将不再对买家可见，已生成订单不受影响。此操作可逆，可重新上架。」；提交审核与重新上架为常规操作，无二次确认。

## 8. 验收要点
- [ ] 表格正确展示主图、标题、价格区间、库存合计、销量、状态
- [ ] 关键词搜索防抖 300ms 后触发查询
- [ ] 状态/分类筛选生效，URL 同步 query 参数支持刷新恢复
- [ ] 操作列按商品状态动态显示按钮（草稿仅编辑、已上架含下架、已下架含重新上架）
- [ ] 下架操作二次确认并输入原因
- **性能要求**：首屏加载 < 1.5s；表格 >100 行虚拟滚动；关键词搜索防抖 300ms。
- **可访问性**：表格有 `aria-label="商品列表"`；操作按钮有 `aria-label`；状态标签有 `aria-label`；对比度满足 WCAG AA。
