# 通知限流 - 运营管理后台

## 1. 页面定位
- **所属端**：运营管理后台
- **所属模块**：07-notification-ops 通知运营
- **页面类型**：配置管理页（频率限制规则）
- **目标用户**：运营管理员（Operator）
- **核心目标**：维护各通知渠道的频率限制规则（用户级/全局限流），防止通知轰炸与渠道成本失控，保障用户体验。
- **访问入口**：左侧菜单「通知运营 → 通知限流」；通知记录页失败（限流）记录跳转。
- **实现状态**：✅ 已实现

## 2. 页面布局与信息架构
- **整体布局**：左侧渠道列表 + 右侧限流配置详情/编辑面板。
- **关键区域**：
  - 区域 A（渠道列表）：左侧 280px 宽，列出全部通知渠道卡片（短信/邮件/站内信/推送），每卡片含渠道图标、名称、限流状态点
  - 区域 B（详情面板）：右侧展示选中渠道的限流规则（用户级/全局级）、时间窗口、阈值、当前用量、最后更新人与时间
  - 区域 C（编辑表单）：右侧切换为编辑模式，含用户级限流（每用户每日/每小时上限）、全局级限流（全平台每分钟/每小时上限）、状态开关
- **响应式断点**：≥1200px 左右分栏；992-1199px 渠道列表折叠为下拉选择。
- **首屏内容**：渠道列表 + 默认选中短信渠道的限流配置。
- **线框图描述**：

```
┌─────────────────┬────────────────────────────┐
│ 渠道列表         │ 短信限流配置                │
├─────────────────┤ 状态: 启用 / 更新: 2026-07  │
│ ● 短信      启用 ├────────────────────────────┤
│ ● 邮件      启用 │ 用户级: 每用户每日 10 条    │
│ ● 站内信    启用 │          每用户每小时 3 条 │
│ ● 推送      启用 │ 全局级: 全平台每分钟 100 条│
│                 │          全平台每小时 1000 条│

│                 ├────────────────────────────┤
│                 │ [编辑]                     │
└─────────────────┴────────────────────────────┘
```

## 3. 数据模型与 API 对接
- **主要 API**：

| 方法 | 端点 | 用途 | 鉴权 |
|-|-|-|-|
| GET | `/api/admin/notification-rate-limits` | 获取指定渠道频率限制配置 | Operator, Admin |
| PUT | `/api/admin/notification-rate-limits` | 更新指定渠道频率限制配置 | Operator, Admin |

- **请求参数**：`channel`（NotificationChannel，query）；更新请求体 `SaveRateLimitConfigDto` 含 `UserDailyLimit`、`UserHourlyLimit`、`GlobalPerMinuteLimit`、`GlobalHourlyLimit`。
- **响应字段**：`RateLimitConfigDto`，含 `Channel`、`UserDailyLimit`、`UserHourlyLimit`、`GlobalPerMinuteLimit`、`GlobalHourlyLimit`、`CurrentUsage`（当前周期用量）、`Status`（Active/Inactive）、`UpdatedBy`、`UpdatedAt`。
- **数据加载策略**：进入页面加载全部渠道限流配置；选中渠道过滤展示；更新后局部刷新。
- **缓存策略**：不缓存，限流配置变更需实时生效。

## 4. 交互流程
- **主流程**：
  1. 进入页面 → 加载全部渠道限流配置 → 渠道列表渲染 → 默认选中短信渠道
  2. 点击渠道卡片 → 右侧展示该渠道限流规则与当前用量
  3. 点击「编辑」→ 切换为编辑模式 → 修改限流阈值 → `<IdempotencyButton>` 提交 → 局部刷新
- **分支流程**：
  - 阈值校验：用户级不超全局级、每小时不超每日、所有阈值须为正整数
  - 当前用量接近阈值：详情面板用量进度条标黄 `#FAAD14`，超阈值标红 `#FF4D4F`
  - 关闭限流：状态开关置为禁用，该渠道不受限流约束（高危，需二次确认）
- **跨页面流转**：点击「当前用量」跳转通知记录页（按渠道筛选今日记录）。
- **状态机可视化**：限流配置状态 Active ↔ Inactive（启用/禁用双向切换）。

- **状态色**：启用 `#52C41A` 绿点、禁用 `#FF4D4F` 红点（关闭限流为高危状态）。
- **渠道色**：短信 `#52C41A`、邮件 `#1677FF`、站内信 `#722ED1`、推送 `#FAAD14`。
- **用量进度条**：用量 <80% `#52C41A` 绿、80-95% `#FAAD14` 橙、>95% `#FF4D4F` 红。

## 7. 异常处理与边界
- **加载态**：渠道列表与详情面板 `<a-spin>` 包裹。
- **空数据**：渠道列表空显示「暂无通知限流配置」。
- **错误态**：阈值校验失败 `message.error('用户级限流不可超过全局级')`；更新失败 `message.error('配置更新失败，请重试')`。
- **权限控制**：Operator/Admin 可访问；编辑/关闭限流需 `notification:rate-limit` 权限。
- **并发与乐观锁**：编辑提交基于聚合版本校验，冲突提示刷新。
- **危险操作确认**：关闭限流为高危操作，强制 `<ConfirmDialog>`，说明该渠道将不受限流约束可能导致轰炸。
- **阈值边界**：用户每日上限 1-100、每小时上限 1-20、全局每分钟上限 10-10000、全局每小时上限 100-100000。
