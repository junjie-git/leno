# 支付统计 - 运营管理后台

## 1. 页面定位
- **所属端**：运营管理后台
- **所属模块**：01-dashboard 数据看板
- **页面类型**：看板页
- **目标用户**：运营管理员（Operator）
- **核心目标**：监控全平台支付成功率、按渠道分布与失败原因，定位支付链路异常。
- **访问入口**：左侧菜单「数据看板 → 支付统计」；运营总览页 GMV 卡片跳转。
- **实现状态**：✅ 已实现

## 2. 页面布局与信息架构
- **整体布局**：顶部时间筛选条 + 中部 3 张指标卡片（支付成功率/支付笔数/失败笔数）+ 中下支付渠道分布柱状图 + 右下失败原因 Top5 饼图 + 底部渠道明细表格。
- **关键区域**：
  - 区域 A（筛选条）：`<DateTimeRangePicker>` 预设今日/昨日/近7天/近30天/本月
  - 区域 B（指标卡片）：3 列 `<DashboardCard>`，支付成功率附 `<ChartGauge>` 仪表盘
  - 区域 C（渠道分布）：`<ChartBar>` 横向柱状图，按渠道（微信/支付宝/其他）展示支付笔数与金额
  - 区域 D（失败原因）：`<ChartPie>` 环形图，展示失败原因分类（余额不足/超时/风控等）
  - 区域 E（明细表格）：`<a-table>` 展示渠道、笔数、金额、成功率、环比
- **响应式断点**：≥1200px 全展开；992-1199px 图表上下堆叠，表格横向滚动。
- **首屏内容**：时间筛选 + 3 张指标卡片 + 渠道分布柱状图。
- **线框图描述**：

```
┌─────────────────────────────────────────────┐
│ [今日][昨日][近7天][近30天][本月]            │
├──────────┬──────────┬──────────────────┤
│ 支付成功率 │ 支付笔数  │ 失败笔数          │
│ 98.5%    │ 1,268    │ 18               │
│ (仪表盘)  │ ↑10.2%   │ ↓5.1%            │
├────────────────────────┬────────────────────┤
│ 渠道分布(柱状图)        │ 失败原因Top5(饼图) │
├─────────────────────────────────────────────┤
│ 渠道明细表格                                  │
└─────────────────────────────────────────────┘
```

## 3. 数据模型与 API 对接
- **主要 API**：

| 方法 | 端点 | 用途 | 鉴权 |
|-|-|-|-|
| GET | `/api/admin/dashboard/payment-stats` | 查询支付成功率统计（按渠道） | Operator, Admin |

- **请求参数**：`start`（DateTime?）、`end`（DateTime?），默认近7天。
- **响应字段**：`DashboardReportDto`，`ReportType` 为 `PaymentSuccessRate`，Metrics 含 `success_rate`、`payment_count`、`failed_count`、`channel_distribution`（按渠道的笔数/金额/成功率）、`failure_reasons`（失败原因计数）。
- **数据加载策略**：进入页面加载默认时间范围数据；表格与图表从同一响应解析。
- **缓存策略**：Pinia 缓存键 `payment_stats_{start}_{end}`，过期 5 分钟。

## 4. 交互流程
- **主流程**：
  1. 进入页面 → 加载近7天支付统计数据 → 渲染卡片、图表、表格
  2. 切换时间预设 → 重新请求 → 图表过渡动画
  3. 点击表格某行渠道 → 弹出该渠道失败明细 `<a-drawer>`
- **分支流程**：
  - 成功率 < 95%：指标卡片数值标红 `#FF4D4F`，并显示告警图标
  - 某渠道无数据：表格行显示 `--`
- **跨页面流转**：点击「失败笔数」卡片跳转退款记录页；点击表格行跳转支付记录页（携带渠道筛选）。
- **状态机可视化**：无状态字段。

## 5. 组件清单
- **基础组件**：`<a-card>`、`<a-table>`、`<a-drawer>`、`<a-tag>`
- **业务组件**：
  - `DashboardCard`（见 shared/components.md §8）— 指标卡片
  - `DateTimeRangePicker`（见 shared/components.md §4）— 时间筛选
  - `StatusTag`（见 shared/components.md §1）— 渠道状态展示
- **图表组件**：
  - `ChartGauge`（见 shared/components.md §7.4）— 支付成功率仪表盘，阈值 [95, 99]
  - `ChartBar`（见 shared/components.md §7.3）— 渠道分布横向柱状图
  - `ChartPie`（见 shared/components.md §7.2）— 失败原因环形图
- **图标使用**：`WarningOutlined` 告警图标
- **空状态**：`EmptyState` title="暂无支付数据"

## 6. 视觉规范
- **主色应用**：柱状图主色 `#1677FF`，仪表盘 >99% 绿、95-99% 黄、<95% 红。
- **状态色**：成功率达标 `#52C41A`，低于阈值 `#FF4D4F`，失败笔数 `#FAAD14`。
- **间距**：卡片间距 `24px`，表格行高 `48px`，图表高度 `300px`。
- **字体**：卡片数值 24px semibold，表格正文 14px，辅助文字 12px `#8C8C8C`。
- **图标尺寸**：告警图标 16px。

## 7. 异常处理与边界
- **加载态**：首屏 Skeleton 模拟卡片与图表；表格 `<a-spin>` 包裹。
- **空数据**：卡片显示 `--`，图表 EmptyState，表格显示「暂无支付数据」。
- **错误态**：网络错误 `message.error('加载支付统计失败')` + 重试；403 提示无权限。
- **权限控制**：Operator/Admin 可访问；渠道明细含金额字段，运营可见全量。
- **并发与乐观锁**：只读页面无并发。
- **危险操作确认**：无危险操作。
