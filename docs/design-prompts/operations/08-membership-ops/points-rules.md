# 积分规则 - 运营管理后台

## 1. 页面定位
- **所属端**：运营管理后台
- **所属模块**：08-membership-ops 会员运营
- **页面类型**：配置管理页（积分规则 CRUD + 手动发放）
- **目标用户**：运营管理员（Operator）
- **核心目标**：维护积分发放规则（签到/下单/评价/分享等行为积分），支持规则启停与手动发放积分，调控积分体系平衡。
- **访问入口**：左侧菜单「会员运营 → 积分规则」；积分统计页发放明细跳转。
- **实现状态**：🚧 规划中（规则 CRUD 端点待补充，当前手动发放端点已实现）

## 2. 页面布局与信息架构
- **整体布局**：顶部选项卡（积分规则 / 手动发放）+ 规则列表表格 + 新增/编辑模态框 + 手动发放表单。
- **关键区域**：
  - 区域 A（选项卡）：`<a-tabs>` 切换「积分规则」与「手动发放」
  - 区域 B（规则表格）：`<a-table>` 列含规则编码、规则名称、行为类型（签到/下单/评价/分享/首单）、积分值、每日上限、状态、操作列
  - 区域 C（新增/编辑模态框）：`<a-modal width="520">` 含规则编码（必填唯一）、规则名称、行为类型、积分值、每日上限、状态开关
  - 区域 D（手动发放表单）：用户 ID、发放积分值、发放原因（必填）、`<IdempotencyButton>` 提交
- **响应式断点**：≥1200px 表格全展开；992-1199px 模态框宽度自适应。
- **首屏内容**：选项卡 + 积分规则列表全部（按行为类型分组）。
- **线框图描述**：

## 3. 数据模型与 API 对接
- **主要 API**（已实现）：

| 方法 | 端点 | 用途 | 鉴权 |
|-|-|-|-|
| POST | `/api/admin/points/award` | 运营手动发放积分 | Operator, Admin |

- **规划补充端点**（🚧）：

| 方法 | 端点 | 用途 | 鉴权 |
|-|-|-|-|
| GET | `/api/admin/points/rules` | 查询全部积分规则 | Operator, Admin |
| POST | `/api/admin/points/rules` | 创建积分规则 | Operator, Admin |
| PUT | `/api/admin/points/rules/{ruleId}` | 更新积分规则 | Operator, Admin |
| POST | `/api/admin/points/rules/{ruleId}/enable` | 启用积分规则 | Operator, Admin |
| POST | `/api/admin/points/rules/{ruleId}/disable` | 停用积分规则 | Operator, Admin |

- **请求参数**：`AwardPointsDto`（已实现）含 `UserId`、`Points`、`Reason`；`CreatePointsRuleDto`（🚧）含 `Code`、`Name`、`ActionType`、`Points`、`DailyLimit`、`Status`。
- **响应字段**：手动发放返回 `ApiResponse`；规则查询返回 `List<PointsRuleDto>`，每项含 `Id`、`Code`、`Name`、`ActionType`、`Points`、`DailyLimit`、`Status`、`UpdatedAt`。
- **数据加载策略**：进入页面加载全部规则；手动发放提交后展示成功提示。
- **缓存策略**：规则配置常驻 Pinia，30 分钟过期，供积分发放链路共享。

## 4. 交互流程
- **主流程**：
  1. 进入页面 → 加载积分规则列表 → 渲染表格
  2. 点击「新增规则」→ 打开模态框 → 配置规则 → `<IdempotencyButton>` 提交 → 列表新增行
  3. 点击「编辑」→ 回填表单 → 提交更新 → 局部刷新
  4. 切换到「手动发放」选项卡 → 填写用户 ID、积分值、原因 → 提交 → 展示成功提示
- **分支流程**：
  - 规则编码唯一校验：后端返回 409，提示「规则编码已存在」
  - 积分值校验：须为整数，-1000 到 1000 之间（支持扣减）
  - 每日上限校验：须为正整数，1-100 之间
  - 手动发放校验：用户 ID 须存在、积分值须为非零整数、原因必填
- **跨页面流转**：点击「用户 ID」跳转用户管理（系统管理后台）；手动发放成功后可跳转积分统计页。
- **状态机可视化**：规则状态 Inactive ↔ Active（启用/停用双向切换）。

## 7. 异常处理与边界
- **加载态**：表格 `<a-spin>` 包裹；模态框与发放表单提交 loading。
- **空数据**：列表空显示「暂无积分规则」+ 新增 CTA。
- **错误态**：编码重复 `message.error('规则编码已存在')`；手动发放用户不存在 `message.error('用户不存在')`。
- **权限控制**：Operator/Admin 可访问；规则增删改需 `points:rule` 权限，手动发放需 `points:award` 权限。
- **并发与乐观锁**：编辑提交基于聚合版本校验，冲突提示刷新。
- **危险操作确认**：停用规则、手动发放为危险操作，强制 `<ConfirmDialog>`，手动发放说明不可撤销。
- **规划说明**：规则 CRUD 端点上线前，规则列表展示固定内置规则（签到/下单/评价），手动发放可正常使用。
