# 个人资料 - 运营管理后台

## 1. 页面定位
- **所属端**：运营管理后台
- **所属模块**：09-account 个人中心
- **页面类型**：表单页（资料编辑 + 密码修改 + 双因子管理 + 外部登录绑定）
- **目标用户**：运营管理员（Operator）
- **核心目标**：维护当前运营账号的个人资料、修改密码、管理双因子认证与外部登录绑定，保障账号安全。
- **访问入口**：Header 用户头像下拉「个人资料」；左侧菜单「个人中心 → 个人资料」。
- **实现状态**：✅ 已实现

## 2. 页面布局与信息架构
- **整体布局**：左侧导航 + 右侧内容面板，含四个分区（基础资料/修改密码/双因子认证/外部登录）。
- **关键区域**：
  - 区域 A（左侧导航）：`<a-menu>` 垂直菜单，含基础资料、修改密码、双因子认证、外部登录四个项
  - 区域 B（基础资料）：`<a-form>` 含头像上传、用户名（只读）、姓名、邮箱、手机号、保存按钮
  - 区域 C（修改密码）：`<a-form>` 含原密码、新密码、确认新密码、强度提示、提交
  - 区域 D（双因子认证）：展示当前状态（启用/未启用），启用流程（生成二维码 → 扫码 → 输入 TOTP 码确认），禁用按钮
  - 区域 E（外部登录）：展示已绑定的第三方账号（Google/GitHub 等），绑定/解绑按钮
- **响应式断点**：≥1200px 左右分栏；992-1199px 左侧导航折叠为顶部水平菜单。
- **首屏内容**：左侧导航 + 基础资料表单。

## 3. 数据模型与 API 对接
- **服务归属**：Identity 域（旧域 UserAuth 双轨兜底，端点路径不变）
- **主要 API**：

| 方法 | 端点 | 用途 | 鉴权 |
|-|-|-|-|
| GET | `/api/users/me` | 查询当前用户资料 | 已认证 |
| PUT | `/api/users/me` | 修改当前用户资料 | 已认证 |
| PUT | `/api/users/me/password` | 修改当前用户密码 | 已认证 |
| POST | `/api/users/me/two-factor/enable` | 启用双因子认证（生成密钥与 QR 码） | 已认证 |
| POST | `/api/users/me/two-factor/confirm` | 确认双因子认证（验证 TOTP 码） | 已认证 |
| POST | `/api/users/me/two-factor/disable` | 禁用双因子认证 | 已认证 |
| POST | `/api/account/external-logins` | 绑定外部登录 | 已认证 |
| DELETE | `/api/account/external-logins/{provider}` | 解绑外部登录 | 已认证 |

- **请求参数**：`UpdateProfileDto` 含 `FullName`、`Email`、`Phone`、`AvatarUrl`；`ChangePasswordDto` 含 `OldPassword`、`NewPassword`；`BindExternalLoginDto` 含 `Provider`、`AuthorizationCode`。
- **响应字段**：`UserDto` 含 `Id`、`Username`、`FullName`、`Email`、`Phone`、`AvatarUrl`、`Roles`、`TwoFactorEnabled`、`ExternalLogins`（`ExternalLoginDto[]`）；双因子启用返回 `TwoFactorEnableResponseDto` 含 `QrCodeUri`、`ManualEntryKey`。
- **数据加载策略**：进入页面加载当前用户资料；各分区独立加载；修改后局部刷新。
- **缓存策略**：用户资料缓存于 Pinia `useUserStore`，修改后同步更新。

## 4. 交互流程
- **主流程**：
  1. 进入页面 → 加载用户资料 → 渲染基础资料表单
  2. 修改基础资料 → 点击保存 → 调用 update → 局部刷新 + Header 头像同步
  3. 切换「修改密码」→ 输入原密码/新密码/确认 → 提交 → 提示成功并清空表单
  4. 切换「双因子认证」→ 点击启用 → 生成二维码 → 扫码后输入 TOTP 码 → 确认 → 状态变更为已启用
  5. 切换「外部登录」→ 点击绑定 → 跳转 OAuth → 回调绑定 → 列表新增
- **分支流程**：
  - 密码强度校验：至少 8 位含大小写字母数字特殊字符，强度条实时显示
  - 原密码错误：`message.error('原密码错误')`，表单不清空
  - 双因子确认失败：`message.error('TOTP 码错误')`
  - 解绑最后一个外部登录：若密码未设置则禁止解绑（防止无法登录）
- **跨页面流转**：无（账号内闭环）。
- **状态机可视化**：双因子状态 Disabled → Enabling（生成密钥）→ Enabled；外部登录 Unbound → Bound。

## 7. 异常处理与边界
- **加载态**：各分区表单 `<a-spin>` 包裹；按钮 loading。
- **空数据**：外部登录无绑定显示「未绑定外部登录」。
- **错误态**：原密码错误 `message.error('原密码错误')`；邮箱格式错误前端校验；TOTP 码错误按业务提示。
- **权限控制**：已认证用户可访问个人资料（自身数据）。
- **并发与乐观锁**：资料修改基于聚合版本校验，冲突提示刷新。
- **危险操作确认**：禁用双因子、解绑外部登录为危险操作，强制 `<ConfirmDialog>`，说明账号安全影响。
- **安全边界**：密码修改后强制重新登录；双因子启用需扫码确认；外部登录绑定走 OAuth 标准流程。
