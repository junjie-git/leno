# 分类管理 - 运营管理后台

## 1. 页面定位
- **所属端**：运营管理后台
- **所属模块**：02-product-ops 商品运营
- **页面类型**：树形管理页（CRUD）
- **目标用户**：运营管理员（Operator）
- **核心目标**：维护商品分类树（多级层级），支持分类的创建、编辑、启停与树形展示，为商品发布与搜索筛选提供分类基础。
- **访问入口**：左侧菜单「商品运营 → 分类管理」；商品审核页分类列点击跳转。
- **实现状态**：✅ 已实现

## 2. 页面布局与信息架构
- **整体布局**：左侧分类树 + 右侧分类详情/编辑面板。
- **关键区域**：
  - 区域 A（分类树）：`<a-tree>` 左侧 320px 宽，展示多级分类，节点含名称、状态点（绿/灰）、操作悬浮按钮（新增子分类/编辑/启停）
  - 区域 B（工具栏）：树顶部含「新增顶级分类」「展开全部/折叠全部」「关键词搜索」
  - 区域 C（详情面板）：右侧展示选中分类的详情，含基本信息、子分类列表、关联商品数
  - 区域 D（新增/编辑表单）：右侧面板切换为表单模式，含父分类（select tree）、名称（必填）、图标、排序值、状态开关
- **响应式断点**：≥1200px 左右分栏；992-1199px 分类树折叠为下拉选择。
- **首屏内容**：分类树首层展开 + 默认选中第一个顶级分类的详情。
- **线框图描述**：


## 3. 数据模型与 API 对接
- **主要 API**：

| 方法 | 端点 | 用途 | 鉴权 |
|-|-|-|-|
| GET | `/api/categories/tree` | 查询分类树（仅启用，按层级与排序组装） | 已认证用户 |
| GET | `/api/categories/{id}` | 查询分类详情 | 已认证用户 |
| POST | `/api/admin/categories` | 创建分类 | Admin, Operator |
| PUT | `/api/admin/categories/{id}` | 更新分类 | Admin, Operator |
| POST | `/api/admin/categories/{id}/enable` | 启用分类 | Admin, Operator |
| POST | `/api/admin/categories/{id}/disable` | 停用分类 | Admin, Operator |

- **请求参数**：`CreateCategoryDto` 含 `ParentId`（可空，空为顶级）、`Name`（必填，1-30 字）、`Icon`、`SortOrder`、`Status`；`UpdateCategoryDto` 同构。
- **响应字段**：`CategoryDto[]` 树形结构，每节点含 `Id`、`Name`、`ParentId`、`Level`、`Icon`、`SortOrder`、`Status`（Active/Inactive）、`Children`（`CategoryDto[]`）、`ProductCount`。
- **数据加载策略**：进入页面加载完整分类树；选中节点加载详情（含 ProductCount）；编辑保存后局部更新树节点。
- **缓存策略**：分类树缓存于 Pinia，10 分钟过期，供商品发布、搜索筛选、商品审核共享。

## 4. 交互流程
- **主流程**：
  1. 进入页面 → 加载分类树 → 首层展开 → 选中第一个顶级分类展示详情
  2. 点击树节点 → 右侧面板展示该分类详情与子分类列表
  3. 点击「新增子分类」→ 右侧切换为表单 → 父分类预填当前节点 → 提交 → 树新增子节点
  4. 点击「编辑」→ 表单回填 → 提交更新 → 树节点名称更新
- **分支流程**：
  - 停用含子分类的节点：后端返回 409，提示「请先停用或删除子分类」
  - 停用被商品引用的节点：后端返回 409，提示「该分类被 N 个商品引用，无法停用」
  - 搜索分类：输入关键词高亮匹配节点并自动展开父链
- **跨页面流转**：详情面板「关联商品数」点击跳转商品审核页（携带分类筛选）。
- **状态机可视化**：分类状态 Inactive ↔ Active；停用后该节点及其子节点对买家端隐藏。

## 6. 视觉规范
- **主色应用**：树选中节点背景 `#E6F4FF`，边框 `#1677FF`；新增按钮主色。
- **状态色**：启用绿点 `#52C41A`、停用灰点 `#8C8C8C`，6px 圆点置于节点名称后。
- **间距**：树节点行高 32px，左右分栏间距 16px，表单项间距 16px。
- **字体**：分类名称 14px `#000000D9`，子分类计数 12px `#8C8C8C`，层级缩进每级 24px。
- **图标尺寸**：分类图标 16px，操作图标 14px。

## 7. 异常处理与边界
- **加载态**：分类树 `<a-spin>` 包裹；详情面板加载 Skeleton。
- **空数据**：树空显示「暂无分类」+ 新增顶级分类 CTA。
- **错误态**：名称同级重复 `message.error('同级下已存在同名分类')`；停用冲突按 409 业务提示。
- **权限控制**：Operator/Admin 可访问；新增/编辑/启停需 `category:manage` 权限。
- **并发与乐观锁**：编辑提交后端基于聚合版本校验，冲突时提示刷新。
- **危险操作确认**：停用分类需 `<ConfirmDialog>` 二次确认，说明子分类与商品引用限制。
- **层级限制**：前端限制最多 3 级分类，第 3 级节点不展示「新增子分类」按钮。

## 8. 验收要点
- [ ] 分类树支持多级展示与展开/折叠
- [ ] 新增子分类时父分类自动预填且不可改
- [ ] 同级分类名称唯一校验
- [ ] 停用含子分类或被引用分类时返回 409 并提示
- [ ] 搜索关键词高亮匹配节点并展开父链
- [ ] 最多 3 级层级，第 3 级禁用新增子分类入口
- **性能要求**：分类树加载 < 800ms，节点数 >200 启用虚拟树 `virtual`。
- **可访问性**：树节点支持键盘上下左右导航，节点 aria-label 含名称与状态。
