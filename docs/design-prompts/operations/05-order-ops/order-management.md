# 订单管理 - 运营管理后台

## 1. 页面定位
- **所属端**：运营管理后台
- **所属模块**：05-order-ops 订单运营
- **页面类型**：列表管理页（全量查询 + 强制取消）
- **目标用户**：运营管理员（Operator）/ 系统管理员（Admin）
- **核心目标**：全平台订单查询（按用户/卖家/状态过滤），处置异常订单（强制取消），保障订单链路合规。
- **访问入口**：左侧菜单「订单运营 → 订单管理」；运营总览页订单卡片跳转。
- **实现状态**：✅ 已实现

## 2. 页面布局与信息架构
- **整体布局**：顶部筛选条 + 操作工具栏 + 订单列表表格 + 订单详情抽屉（含订单行与物流）+ 强制取消对话框。
- **关键区域**：
  - 区域 A（筛选条）：`<a-form inline>` 含订单号、买家 ID、卖家 ID、订单状态（待支付/已支付/已发货/已完成/已取消）、时间范围、查询/重置
  - 区域 B（工具栏）：导出列表、刷新、统计概览（各状态计数）
  - 区域 C（订单表格）：`<a-table>` 列含订单号、商品摘要、买家、卖家、金额、支付方式、状态、下单时间、操作列
  - 区域 D（详情抽屉）：`<a-drawer width="800">` 展示订单基础信息、订单行列表、收货地址、支付信息、物流轨迹、状态变更历史
  - 区域 E（强制取消对话框）：`<a-modal>` 含取消原因（必填）、影响说明（退款/库存回写）
- **响应式断点**：≥1200px 抽屉 800px；992-1199px 抽屉 600px。
- **首屏内容**：筛选条 + 全状态订单列表前 20 条。

## 3. 数据模型与 API 对接
- **主要 API**：

| 方法 | 端点 | 用途 | 鉴权 |
|-|-|-|-|
| GET | `/api/admin/orders` | 分页查询全部订单（按用户/卖家/订单号/状态/下单时间范围过滤，走 ES 读模型） | Operator, Admin |
| POST | `/api/admin/orders/{id}/force-cancel` | 运营强制取消订单（待支付/已支付/已发货态） | Admin |

- **请求参数**：查询参数 `userId`（Guid?）、`sellerId`（Guid?）、`status`（OrderStatus?）、`orderNo`（string?，订单号模糊匹配）、`startDate`（DateTime?，下单时间下界）、`endDate`（DateTime?，下单时间上界）、`page`（int，默认 0）、`pageSize`（int，默认 20）；强制取消请求体 `ForceCancelOrderDto` 含 `Reason`（必填）。
- **响应字段**：`OrderListResult`，含 `Items`（`OrderListItemDto[]`，每项含 `Id`、`OrderNo`、`UserId`、`SellerId`、`TotalAmount`、`Status`、`PaymentMethod`、`CreatedAt`、`ItemSummary`）、`Total`。
- **数据加载策略**：进入页面加载全状态订单；切换筛选重新请求（走 ES 读模型）；强制取消后局部更新状态列。
- **缓存策略**：不缓存，订单状态实时性强。

## 4. 交互流程
- **主流程**：
  1. 进入页面 → 加载订单列表 → 渲染表格与统计概览
  2. 点击「详情」→ 打开抽屉展示订单行、地址、支付、物流、状态历史
  3. 点击「强制取消」→ 弹出对话框 → 填写原因 → `<IdempotencyButton>` 提交 → 状态变更为已取消
- **分支流程**：
  - 强制取消前置：仅待支付/已支付/已发货态可取消，已完成/已取消隐藏按钮
  - 已支付订单强制取消触发自动退款流程
  - 已发货订单强制取消需额外确认「库存回写」影响
- **跨页面流转**：点击「买家」跳转用户管理（系统管理）；点击「卖家」跳转店铺治理；点击「物流」跳转物流单查询。
- **状态机可视化**：PendingPayment（待支付）→ Paid（已支付）→ Shipped（已发货）→ Completed（已完成）/ Cancelled（已取消）。强制取消可跨多态直达 Cancelled。

## 7. 异常处理与边界
- **加载态**：表格 `<a-spin>` 包裹；抽屉加载 Skeleton。
- **空数据**：列表空显示「暂无订单」，按状态筛选提示「该状态下暂无订单」。
- **错误态**：强制取消失败 `message.error('取消失败，请重试')`；并发冲突提示「订单状态已变更，请刷新」。
- **权限控制**：Operator/Admin 可查询；强制取消需 `order:force-cancel` 权限且建议 Admin 角色。
- **并发与乐观锁**：强制取消基于聚合版本校验，冲突提示刷新。
- **危险操作确认**：强制取消为危险操作，强制 `<ConfirmDialog>`，说明退款与库存回写影响且不可逆。
