# 注册 - 用户 APP

## 1. 页面定位
- **所属端**：用户 APP
- **所属模块**：01-auth 认证
- **页面类型**：表单页
- **目标用户**：买家（Buyer）
- **核心目标**：买家填写账号、密码完成注册并自动登录，进入首页。
- **访问入口**：登录页「注册账号」链接；启动引导页「立即注册」。
- **实现状态**：✅ 已实现

## 2. 页面布局与信息架构
- **整体布局**：顶部 NavBar（返回+标题「注册」）+ 滚动表单区 + 底部协议确认与提交按钮，无 Tabbar。
- **关键区域**：
  - 区域 A（NavBar）：左侧返回箭头，标题「注册」。
  - 区域 B（表单区）：`van-form` 含用户名、手机号、验证码（带「获取验证码」按钮）、密码、确认密码 5 个 `van-field`。
  - 区域 C（协议区）：`van-checkbox`「我已阅读并同意《用户协议》《隐私政策》」。
  - 区域 D（提交区）：`van-button type="primary" block`「注册」按钮。
- **响应式断点**：375px 基准；≥768px 表单最大宽 480px 居中。
- **首屏内容**：用户名、手机号、验证码输入框及协议复选框。
- **线框图描述**：
```
┌──────────────────┐
│ ← 注册           │
├──────────────────┤
│ [用户名______]   │
│ [手机号______]   │
│ [验证码__][获取] │
│ [密码______👁] │
│ [确认密码__👁] │
│ ☐ 同意协议       │
│ [   注册   ]     │
└──────────────────┘
```

## 3. 数据模型与 API 对接
- **主要 API**：

| 方法 | 端点 | 用途 | 鉴权 |
|-|-|-|-|
| POST | `/api/auth/register` | 注册账号并签发令牌 | 匿名 |
| POST | `/api/auth/forgot-password` | 复用发送验证码能力（手机号校验） | 匿名 |

- **请求参数**：`RegisterDto` 含 `userName`（4-20 字符）、`phone`（11 位手机号）、`password`（6-32 字符）、`verificationCode`（6 位）。
- **响应字段**：`TokenDto`（同登录），注册成功直接返回 token，前端无需二次登录。
- **数据加载策略**：进入页面无加载；点击「获取验证码」调用短信发送；提交时调用注册端点。
- **缓存策略**：注册成功后 token 持久化规则同登录页；验证码倒计时状态存 sessionStorage 防刷新丢失。

## 4. 交互流程
- **主流程**：
  1. 输入用户名 → 失焦校验 4-20 字符、不与手机号重复。
  2. 输入手机号 → 失焦校验 11 位手机号正则。
  3. 点击「获取验证码」→ 按钮变 60s 倒计时 disabled → 调用验证码发送 → `showToast('验证码已发送')`。
  4. 输入验证码、密码、确认密码 → 失焦校验密码长度 6-32、两次密码一致。
  5. 勾选协议 → 点击「注册」→ 按钮 loading → 调用 `POST /api/auth/register` → 成功存 token → `showToast('注册成功')` → 跳 `/`。
- **分支流程**：
  - 用户名已存在：显示「用户名已被占用」。
  - 手机号已注册：显示「该手机号已注册，请直接登录」。
  - 验证码错误：显示「验证码错误或已过期」。
  - 未勾选协议：提交按钮 disabled，提示「请先阅读并同意协议」。
- **跨页面流转**：注册成功跳首页；点击协议链接在 `van-popup` 内展示协议全文。
- **状态机可视化**：未填 → 填写中 → 校验通过 → 注册中(loading) → 已注册 / 注册失败。

## 5. 组件清单
- **基础组件**：`van-form`、`van-field`、`van-button`、`van-checkbox`、`van-popup`、`van-toast`。
- **业务组件**：`IdempotencyButton`（见 shared/components.md §2）— 注册提交按钮；`CountdownButton` 自研倒计时按钮（60s）。
- **图表组件**：无。
- **图标使用**：密码明文切换 `eye-o`/`closed-eye`；返回箭头 `arrow-left`。
- **空状态**：不涉及。

## 6. 视觉规范
- **主色应用**：注册按钮、获取验证码按钮（未倒计时时）使用主色 `#1677FF`；协议链接「《用户协议》」主色。
- **状态色**：校验错误 `#FF4D4F` 12px；倒计时中按钮文字 `#8C8C8C` 禁用态。
- **间距**：表单项间距 12px；协议区距表单 16px；按钮距协议 24px。
- **字体**：标题 16px medium；输入框 16px；协议文案 12px `#8C8C8C`。
- **图标尺寸**：明文切换 20px；返回 20px。

## 7. 异常处理与边界
- **加载态**：注册按钮 loading；获取验证码按钮倒计时期间 disabled。
- **空数据**：不涉及。
- **错误态**：网络异常 toast 3s；字段错误逐字段展示；验证码发送失败恢复按钮可点击。
- **权限控制**：匿名页；已登录访问跳首页。
- **并发与乐观锁**：`IdempotencyButton` 防重复注册；获取验证码按钮 60s 内只能点击一次。
- **危险操作确认**：不涉及。

## 8. 验收要点
- [ ] 所有字段失焦校验，错误红字位于字段下方。
- [ ] 获取验证码按钮 60s 倒计时，期间 disabled。
- [ ] 两次密码不一致时提交校验拦截。
- [ ] 未勾选协议时提交按钮 disabled。
- [ ] 注册成功直接返回 token 并跳首页。
- **性能要求**：首屏 < 1s；注册响应 < 1s；倒计时精度 1s。
- **可访问性**：输入框 `aria-label`；协议复选框可键盘操作；表单支持 Enter 提交。
