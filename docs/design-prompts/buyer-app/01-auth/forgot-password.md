# 忘记密码 - 用户 APP

## 1. 页面定位
- **所属端**：用户 APP
- **所属模块**：01-auth 认证
- **页面类型**：流程页
- **目标用户**：买家（Buyer）
- **核心目标**：买家通过手机号验证码重置登录密码，完成两步流程（发送验证码 → 重置密码）。
- **访问入口**：登录页「忘记密码」链接。
- **实现状态**：✅ 已实现

## 2. 页面布局与信息架构
- **整体布局**：NavBar（返回+标题「忘记密码」）+ `van-steps`（2 步：验证身份 / 重置密码）+ 步骤对应内容区 + 底部操作按钮，无 Tabbar。
- **关键区域**：
  - 区域 A（步骤条）：`van-steps :active="current"` 显示当前步骤。
  - 区域 B（验证身份区，step 0）：手机号 `van-field`、验证码 `van-field` + 「获取验证码」按钮。
  - 区域 C（重置密码区，step 1）：新密码 `van-field`、确认密码 `van-field`。
  - 区域 D（操作按钮）：step 0「下一步」、step 1「提交」+「返回上一步」。
- **响应式断点**：375px 基准；≥768px 内容最大宽 480px 居中。
- **首屏内容**：步骤条、手机号输入框、验证码输入框、下一步按钮。
- **线框图描述**：
```
┌──────────────────┐
│ ← 忘记密码       │
├──────────────────┤
│ ①验证  ②重置     │
│                  │
│ step0:           │
│ [手机号______]   │
│ [验证码][获取]   │
│ [   下一步   ]   │

│ [新密码____👁] │
```

## 3. 数据模型与 API 对接
- **主要 API**：

| 方法 | 端点 | 用途 | 鉴权 |
|-|-|-|-|
| POST | `/api/auth/forgot-password` | 发送重置验证码/链接 | 匿名 |
| POST | `/api/auth/reset-password` | 重置密码 | 匿名 |

- **请求参数**：`ForgotPasswordDto` 含 `phone`/`email`；`ResetPasswordDto` 含 `phone`/`email`、`verificationCode`、`newPassword`。
- **响应字段**：两接口均返回 `ApiResponse`（无 data），forgot-password 返回 message「若账号存在，重置链接已发送」。
- **数据加载策略**：进入页面无加载；点击「获取验证码」与「提交」时分别调用对应端点。
- **缓存策略**：步骤状态（current step）存 sessionStorage 防刷新丢失；手机号验证通过后暂存内存，重置时携带。

## 4. 交互流程
- **主流程**：
  1. 输入手机号 → 失焦校验 11 位 → 点击「获取验证码」→ 60s 倒计时 → 调用 `POST /api/auth/forgot-password` → `showToast('验证码已发送')`。
  2. 输入验证码 → 点击「下一步」→ 校验非空 → 步骤推进到 1（前端不校验验证码正确性，由重置端点校验）。
  3. 输入新密码、确认密码 → 失焦校验长度 6-32、两次一致 → 点击「提交」→ 调用 `POST /api/auth/reset-password` → 成功 `showToast('密码重置成功')` → 跳 `/login`。
- **分支流程**：
  - 验证码错误：重置端点返回错误，`showToast('验证码错误或已过期')`，停留 step 1。
  - 手机号不存在：forgot-password 仍返回成功（防探测），但短信不实际发送。
  - 点击「返回上一步」：步骤回退到 0，保留手机号输入。
- **跨页面流转**：重置成功跳登录页，并预填手机号/用户名。
- **状态机可视化**：step0 待验证 → step0 已发送验证码 → step1 重置中 → 重置成功（跳登录）/ 重置失败（停留）。

## 5. 组件清单
- **基础组件**：`van-form`、`van-field`、`van-button`、`van-steps`、`van-toast`。
- **业务组件**：`IdempotencyButton`（见 shared/components.md §2）— 下一步/提交按钮；`CountdownButton` 自研倒计时按钮。
- **图表组件**：无。
- **图标使用**：密码明文切换 `eye-o`/`closed-eye`；返回 `arrow-left`。
- **空状态**：不涉及。

## 6. 视觉规范
- **主色应用**：步骤条激活态、按钮主色 `#1677FF`。
- **状态色**：校验错误 `#FF4D4F` 12px；倒计时禁用 `#8C8C8C`。
- **间距**：步骤条距 NavBar 16px；表单项间距 12px；按钮距表单 24px。
- **字体**：标题 16px medium；输入框 16px；步骤描述 14px。
- **图标尺寸**：明文切换 20px；返回 20px。

## 7. 异常处理与边界
- **加载态**：按钮 loading；获取验证码倒计时 disabled。
- **空数据**：不涉及。
- **错误态**：网络异常 toast 3s；验证码错误停留在重置步骤；重置失败按钮恢复。
- **权限控制**：匿名页；已登录访问提示「请先登出后再重置密码」。
- **并发与乐观锁**：`IdempotencyButton` 防重复提交；倒计时按钮 60s 内单次。
- **危险操作确认**：不涉及删除，但密码重置属敏感操作，提交按钮注入 `Idempotency-Key`。

## 8. 验收要点
- [ ] 步骤条正确显示当前步骤，可前进不可跳步。
- [ ] 获取验证码 60s 倒计时，期间 disabled。
- [ ] 两次密码不一致时提交校验拦截。
- [ ] 重置成功跳登录页并预填账号。
- [ ] 验证码错误时停留在重置步骤并提示。
- **性能要求**：首屏 < 1s；重置响应 < 1s；步骤切换 < 100ms。
- **可访问性**：步骤条 `aria-current`；输入框 `aria-label`；按钮支持键盘操作。
