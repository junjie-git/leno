# 物流轨迹 - 用户 APP

## 1. 页面定位
- **所属端**：用户 APP
- **所属模块**：06-order 订单交易
- **页面类型**：详情页
- **目标用户**：买家（Buyer）
- **核心目标**：买家查看已发货订单的物流轨迹节点（时间轴形式），了解当前物流状态与历史节点。
- **访问入口**：订单详情页点击「查看物流」；订单列表待收货订单点击「查看物流」。
- **实现状态**：✅ 已实现

## 2. 页面布局与信息架构
- **整体布局**：顶部 `van-nav-bar`（返回+标题「物流轨迹」）+ 可滚动主体（物流公司信息+物流单号+时间轴节点列表），无 Tabbar。
- **关键区域**：
  - 区域 A（物流公司卡）：`van-cell-group` 展示物流公司名称+客服电话（可点击拨打）+物流单号（可复制）。
  - 区域 B（时间轴）：`van-steps` 竖向时间轴，倒序展示物流节点（最新在上），每节点含描述+时间+地点；最新节点高亮主色。
  - 区域 C（缓存提示）：`HasWarning` 为 true 时顶部 `van-notice-bar` 提示「物流查询异常，展示缓存数据」。
- **响应式断点**：375px 基准；≥768px 居中最大 480px。
- **首屏内容**：导航栏、物流公司卡、最新物流节点。

## 3. 数据模型与 API 对接
- **主要 API**：

| 方法 | 端点 | 用途 | 鉴权 |
|-|-|-|-|
| GET | `/api/orders/{id}` | 查询订单详情（含物流单号与公司编码） | Buyer |
| GET | `/api/orders/{id}/logistics` | 查询物流轨迹节点 | Buyer |

- **请求参数**：`id` 路径参数（订单标识）。
- **响应字段**：`LogisticsTrackingDto` 含 `logisticsNo`、`companyCode`、`nodes`（LogisticsTrackingNode: description、occurredAt、location）、`isFromCache`、`hasWarning`；订单详情含 `logisticsNo`、`logisticsCompanyCode`。
- **数据加载策略**：进入页面调用 `GET /api/orders/{id}/logistics` 获取轨迹；订单详情已缓存时复用物流单号与公司信息。
- **缓存策略**：轨迹缓存 10 分钟（服务端 `IsFromCache` 标记），前端不主动缓存；下拉刷新强制重新拉取。

## 4. 交互流程
- **主流程**：
  1. 进入页面读取 `id` → `GET /api/orders/{id}/logistics` → 渲染物流公司卡与时间轴。
  2. 最新节点高亮主色，其余节点灰色。
  3. 点击物流单号「复制」→ 复制到剪贴板 → `showToast` 「已复制」。
  4. 点击客服电话 → 调起拨号 `tel:` 链接。
  5. 下拉刷新 → 重新拉取轨迹。
- **分支流程**：
  - 物流查询失败：`HasWarning` 为 true，顶部 `van-notice-bar` 提示，展示缓存数据。
  - 暂无轨迹：`van-empty`「暂无物流信息」+ 提示「请稍后查询」。
  - 订单未发货：提示「订单尚未发货」+ 「返回订单详情」CTA。
- **跨页面流转**：返回订单详情页。
- **状态机可视化**：加载中(skeleton) → 有轨迹(时间轴) / 无轨迹(空状态) / 查询失败(缓存+警告)。

- **业务组件**：`LogisticsCompanyCard` 物流公司卡；`LogisticsTimeline` 时间轴；`EmptyState`（见 shared/components.md §5）。

## 6. 视觉规范
- **主色应用**：最新节点圆点与文字主色 `#1677FF`；复制按钮主色。
- **状态色**：最新节点 `#1677FF`；历史节点 `#8C8C8C`；警告条 `#FAAD14`。
- **间距**：区域间距 12px；时间轴节点间距 16px；卡片内边距 12px。
- **字体**：物流公司名 16px medium `#000000D9`；运单号 14px `#595959`；节点描述 14px `#000000D9`；节点时间 12px `#8C8C8C`；节点地点 12px `#8C8C8C`。
- **图标尺寸**：返回 20px；客服 20px；复制 16px。

## 7. 异常处理与边界
- **加载态**：首屏 `van-skeleton` 模拟物流公司卡+3 个时间轴节点。
- **空数据**：`van-empty`「暂无物流信息」+ 提示「请稍后查询」。
- **错误态**：查询失败展示缓存数据 + `van-notice-bar` 警告；无缓存时 `showToast` 「查询失败」+ 重试按钮。
- **权限控制**：Buyer 可见；订单归属校验由服务端完成。
- **并发与乐观锁**：不涉及（只读页面）。
- **危险操作确认**：不涉及。
