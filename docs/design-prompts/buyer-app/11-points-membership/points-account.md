# 积分账户 - 用户 APP

## 1. 页面定位
- **所属端**：用户 APP
- **所属模块**：11-points-membership 积分会员
- **页面类型**：详情页（聚合页）
- **目标用户**：买家（Buyer）
- **核心目标**：买家查看积分账户余额、累计获取/消耗统计、近期流水预览，并提供签到、任务中心、积分兑换、积分流水等模块快捷入口。
- **访问入口**：「我的」页积分卡入口；签到成功后跳转；底部 Tabbar「我的」→ 积分。
- **实现状态**：✅ 已实现

## 3. 数据模型与 API 对接
- **主要 API**：

| 方法 | 端点 | 用途 | 鉴权 |
|-|-|-|-|
| GET | `/api/points/account` | 查询积分账户余额与累计统计 | Buyer |
| GET | `/api/points/ledger` | 查询积分流水（取近 3 条预览） | Buyer |
| POST | `/api/points/check-in` | 每日签到 | Buyer |

- **请求参数**：`GET /api/points/account` 无参数；`GET /api/points/ledger?page=1&pageSize=3` 取近 3 条；签到无 body。
- **响应字段**：账户 `PointsAccountDto` 含 `balance`（当前余额）、`monthEarned`、`monthSpent`、`totalEarned`、`lastCheckInDate`、`consecutiveDays`；流水 `PointsLedgerDto` 含 `ledgerId`、`type`（Earn/Spend）、`source`（订单/签到/兑换/任务）、`amount`、`balanceAfter`、`description`、`createdAt`。
- **数据加载策略**：进入页面并行调用 `GET /api/points/account` 与 `GET /api/points/ledger?pageSize=3`；下拉刷新。
- **缓存策略**：账户信息缓存 30s（基于 userId）；流水不缓存。

## 4. 交互流程
- **主流程**：
  1. 进入页面 → 并行调用账户与流水接口 → 渲染余额卡、统计、快捷入口、近期流水。
  2. 点击「签到」→ `POST /api/points/check-in` → 成功 `showToast` 「签到成功，获得 X 积分」→ 更新余额与签到按钮置灰。
  3. 点击快捷入口「每日签到」→ 跳签到页（或直接签到）。
  4. 点击快捷入口「任务中心」→ 跳任务中心页。
  5. 点击快捷入口「积分兑换」→ 跳积分兑换页。
  6. 点击快捷入口「流水明细」→ 跳积分流水页。
  7. 点击近期流水「查看全部」→ 跳积分流水页。
- **分支流程**：
  - 已签到：签到按钮置灰显示「已签到」，点击无响应。
  - 签到失败：`showToast` 「签到失败」+ 重试。
  - 余额为 0：流水区显示「暂无流水」+ 「去赚积分」CTA 跳任务中心。
- **跨页面流转**：跳签到页、任务中心页、积分兑换页、积分流水页。
- **状态机可视化**：未签到 → 签到中(loading) → 已签到(置灰) / 签到失败(提示)。

## 6. 视觉规范
- **主色应用**：余额卡渐变背景 `linear-gradient(135deg, #1677FF, #0958D9)`；余额数字 `#FFFFFF`；快捷入口图标主色；统计「获取」`#52C41A`。

## 7. 异常处理与边界
- **加载态**：首屏 `van-skeleton` 模拟余额卡 + 统计 + 快捷入口 + 流水预览。
- **空数据**：流水区为空显示「暂无流水」+ 「去赚积分」CTA 跳任务中心。
- **错误态**：接口失败 `showToast` 「加载失败」+ 重试按钮；`van-pull-refresh` 下拉刷新。
- **权限控制**：Buyer 可见；未登录跳 `/login?redirect=/points/account`。
- **并发与乐观锁**：签到按钮点击后立即 disabled + loading 直至响应返回；`Idempotency-Key` 头防重复签到。
- **危险操作确认**：不涉及。
