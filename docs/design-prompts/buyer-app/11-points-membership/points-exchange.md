# 积分兑换 - 用户 APP

## 1. 页面定位
- **所属端**：用户 APP
- **所属模块**：11-points-membership 积分会员
- **页面类型**：列表页
- **目标用户**：买家（Buyer）
- **核心目标**：买家使用积分兑换优惠券，展示当前余额与可兑换优惠券列表，兑换后优惠券进入「我的优惠券」。
- **访问入口**：积分账户页「积分兑换」入口；任务中心「去兑换」；「我的」页优惠券入口提示。
- **实现状态**：✅ 已实现

## 2. 页面布局与信息架构
- **整体布局**：顶部 `van-nav-bar`（返回 + 标题「积分兑换」）+ 余额条 + `van-list` 优惠券卡片无限滚动，无 Tabbar。
- **关键区域**：
  - 区域 A（余额条）：固定顶部，展示当前可用积分「2,860 积分」+ 「≈ ¥28.60」换算提示。

- **首屏内容**：导航栏、余额条、优惠券卡片首屏。

## 3. 数据模型与 API 对接
- **主要 API**：

| 方法 | 端点 | 用途 | 鉴权 |
|-|-|-|-|
| GET | `/api/points/account` | 查询积分账户余额 | Buyer |
| POST | `/api/points/exchange-coupon` | 积分兑换优惠券 | Buyer |
| GET | `/api/coupons/claimable` | 查询可领取优惠券（含积分兑换券） | Buyer |

- **请求参数**：账户查询无参数；兑换 body `{ couponTemplateId, pointsCost }`；可领取优惠券查询无参数。
- **响应字段**：账户 `PointsAccountDto` 含 `balance`；兑换结果 `ExchangeCouponResultDto` 含 `couponId`、`couponTemplateId`、`couponName`、`pointsCost`、`newBalance`、`expireAt`；优惠券 `CouponTemplateDto` 含 `couponTemplateId`、`name`、`type`、`faceValue`、`threshold`、`pointsCost`（积分兑换价，>0 表示可兑换）、`validityDays`、`scope`。
- **数据加载策略**：进入页面并行调用账户与可领取优惠券接口；前端过滤 `pointsCost > 0` 的可兑换券；`van-list` 分页；下拉刷新。
- **缓存策略**：账户缓存 30s；优惠券列表缓存 60s。

## 4. 交互流程
- **主流程**：
  1. 进入页面 → 并行调用 `GET /api/points/account` 与 `GET /api/coupons/claimable` → 渲染余额条 + 优惠券卡片（前端过滤可兑换）。
  2. 滚动到底部 → `van-list` load → 追加下一页。
  3. 积分充足时点击「兑换」→ `van-dialog` 二次确认「确认消耗 X 积分兑换此优惠券？」→ 按钮 disabled + loading → `POST /api/points/exchange-coupon` → 成功 `showToast` 「兑换成功」→ 更新余额条 + 卡片状态。
  4. 积分不足时兑换按钮置灰，显示「积分不足」。
  5. 点击优惠券卡片 → `van-popup` 展示优惠券详情（面额、门槛、有效期、适用范围、使用说明）。
- **分支流程**：
  - 积分不足：兑换按钮置灰，点击无响应。
  - 兑换失败（库存不足）：`showToast` 「优惠券已抢光」+ 刷新列表。
  - 兑换失败（已达领取上限）：`showToast` 「已达到领取上限」。
  - 空列表：`van-empty`「暂无可兑换优惠券」+ 「去赚积分」CTA 跳任务中心。
- **跨页面流转**：兑换成功提示「去查看」跳我的优惠券页；无其他跳转。
- **状态机可视化**：未兑换 → 兑换中(loading) → 已兑换(置灰) / 兑换失败(提示)。

## 7. 异常处理与边界
- **加载态**：首屏 `van-skeleton` 模拟余额条 + 4 张优惠券卡片。
- **空数据**：`van-empty`「暂无可兑换优惠券」+ 「去赚积分」CTA 跳任务中心。
- **错误态**：接口失败 `showToast` 「加载失败」+ 重试按钮；`van-pull-refresh` 下拉刷新。
- **权限控制**：Buyer 可见；未登录跳 `/login?redirect=/points/exchange`。
- **并发与乐观锁**：兑换按钮点击后立即 disabled + loading 直至响应返回；`Idempotency-Key` 头防重复兑换。
- **危险操作确认**：兑换需 `van-dialog` 二次确认，文案「确认消耗 X 积分兑换此优惠券？」，确认按钮主色（消耗积分非危险操作，但需确认积分消耗）。
