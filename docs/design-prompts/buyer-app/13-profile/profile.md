# 个人资料 - 用户 APP

## 1. 页面定位
- **所属端**：用户 APP
- **所属模块**：13-profile 我的
- **页面类型**：表单页
- **目标用户**：买家（Buyer）
- **核心目标**：买家查看与编辑个人资料（头像、昵称），展示用户名/邮箱/手机号等只读账号信息，提供收货地址、账号安全、收藏与历史等模块入口聚合。
- **访问入口**：底部 Tabbar「我的」→ 头像区「查看资料」；设置页「个人资料」；URL `/profile`。
- **实现状态**：✅ 已实现

## 2. 页面布局与信息架构
- **整体布局**：顶部 `van-nav-bar`（返回 + 标题「个人资料」+ 右侧「保存」）+ 可滚动主体（头像卡 + 资料表单 + 账号信息 + 模块入口聚合），无 Tabbar。
- **关键区域**：
  - 区域 A（头像卡）：圆形头像（80×80px）+ 右下角相机角标，点击调起 `van-uploader` 选图；下方昵称输入框（`van-field` 1-32 字符）。
  - 区域 B（账号信息只读）：`van-cell-group` 展示用户名（只读）、邮箱（脱敏，未绑定显示「去绑定」）、手机号（脱敏，未绑定显示「去绑定」）、注册时间、最后更新时间。
  - 区域 C（模块入口聚合）：`van-cell-group` 列表入口「收货地址」「账号安全」「商品收藏」「浏览历史」「通知偏好」，每项右侧箭头与角标（地址数/未读数等）。

- **首屏内容**：导航栏、头像卡、账号信息只读区、模块入口聚合首屏可见。

## 3. 数据模型与 API 对接
- **主要 API**：

| 方法 | 端点 | 用途 | 鉴权 |
|-|-|-|-|
| GET | `/api/users/me` | 查询当前用户资料 | Buyer |
| PUT | `/api/users/me` | 修改当前用户资料（昵称、头像） | Buyer |

- **请求参数**：查询无参数；修改 body `{ nickname: string (1-32), avatarUrl?: string (HTTPS URL) }`。
- **响应字段**：`UserDto` 含 `id`、`username`、`email?`、`phoneNumber?`、`nickname`、`avatarUrl?`、`status`（Active/Locked/Closed）、`roles[]`、`defaultAddressId?`、`createdAt`、`updatedAt`；修改返回更新后的 `UserDto`。
- **数据加载策略**：进入页面调 `GET /api/users/me` 渲染头像、昵称、账号信息、状态徽章；下拉刷新。
- **缓存策略**：资料缓存于 Pinia `useAuthStore`（与 Tabbar「我的」共享），修改后同步更新 Store。

## 4. 交互流程
- **主流程**：
  1. 进入页面 → `GET /api/users/me` → 渲染头像卡、账号信息、状态徽章、模块入口。
  2. 点击头像 → 调起 `van-uploader` 选图 → 客户端裁剪为正方形 → 上传至对象存储返回 URL → 预览头像。
  3. 修改昵称 → `van-field` 失焦校验长度 1-32 → 启用「保存」按钮。
  4. 点击「保存」→ `PUT /api/users/me`（带 `Idempotency-Key`）→ 成功 `showToast` 「资料保存成功」→ 同步更新 `useAuthStore` 与 Tabbar「我的」头像昵称。
  5. 点击模块入口「收货地址」→ 跳 `/profile/addresses`。
  6. 点击模块入口「账号安全」→ 跳 `/profile/security`。
  7. 点击模块入口「商品收藏」→ 跳 `/profile/favorites`。
  8. 点击模块入口「浏览历史」→ 跳 `/profile/history`。
  9. 点击模块入口「通知偏好」→ 跳 `/notifications/preferences`。
- **分支流程**：
  - 邮箱/手机号未绑定：右侧显示「去绑定」红色文字，点击跳账号安全页绑定区。
  - 昵称校验失败：输入框下方红色提示「昵称长度需在 1-32 字符之间」，禁用「保存」按钮。
  - 头像上传失败：`showToast` 「头像上传失败」+ 重试。
- **跨页面流转**：跳收货地址、账号安全、商品收藏、浏览历史、通知偏好页；保存成功停留在本页。
- **状态机可视化**：未修改（保存置灰）→ 修改中 → 已修改（保存可点击）→ 保存中(loading) → 保存成功/失败。

## 5. 组件清单
- **基础组件**：`van-nav-bar`、`van-cell`、`van-cell-group`、`van-field`、`van-image`、`van-uploader`、`van-tag`、`van-button`、`van-skeleton`、`van-toast`（showToast）、`van-icon`、`van-pull-refresh`。
- **业务组件**：`AvatarUploader` 头像上传器（含选图、裁剪、上传、预览）；`AccountInfoCell` 账号信息只读项；`ProfileEntryCell` 模块入口项（含图标、标题、角标、箭头）；`StatusBadge` 状态徽章组合（账号状态 + 角色 + 会员等级）。
- **图表组件**：无。
- **图标使用**：返回 `arrow-left`；相机 `photograph`；保存 `success`；地址 `location-o`；安全 `shield-o`；收藏 `like-o`；历史 `clock-o`；通知 `bell`；箭头 `arrow`。
- **空状态**：头像为空显示默认占位 `user-o` 图标。

## 7. 异常处理与边界
- **加载态**：首屏 `van-skeleton` 模拟头像卡 + 账号信息 + 模块入口。
- **空数据**：头像为空显示默认 `user-o` 占位；邮箱/手机号未绑定显示「去绑定」。
- **错误态**：查询失败 `showToast` 「加载失败」+ 重试按钮；保存失败 `showToast` 「保存失败」+ 重试；`van-pull-refresh` 下拉刷新。
- **权限控制**：Buyer 可见；未登录跳 `/login?redirect=/profile`。
- **并发与乐观锁**：「保存」按钮点击后立即 disabled + loading 直至响应返回；`Idempotency-Key` 头防重复保存；头像上传与保存串行（先上传得 URL 再保存）。
- **危险操作确认**：不涉及（资料修改可逆）。
