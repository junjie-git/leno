# 支付结果 - 用户 APP

## 1. 页面定位
- **所属端**：用户 APP
- **所属模块**：07-payment 支付
- **页面类型**：流程页
- **目标用户**：买家（Buyer）
- **核心目标**：买家在第三方支付完成后返回本端，查看支付结果（成功/失败/处理中），成功后引导查看订单或继续购物，失败后提供重试入口。
- **访问入口**：支付发起页支付完成跳转；第三方支付返回本端自动跳转。
- **实现状态**：✅ 已实现

## 2. 页面布局与信息架构
- **整体布局**：顶部 `van-nav-bar`（返回+标题「支付结果」）+ 可滚动主体（结果图标+结果文案+订单摘要+操作按钮），无 Tabbar。
- **关键区域**：
  - 区域 A（结果图标与文案）：成功展示绿色 `checked` 图标+「支付成功」；失败展示红色 `close` 图标+「支付失败」+失败原因；处理中展示主色 `clock-o` 图标+「支付处理中」。
  - 区域 B（订单摘要）：`van-cell-group` 展示订单号+支付方式+支付时间+应付金额。
  - 区域 C（操作按钮）：成功显示「查看订单」「继续购物」；失败显示「重新支付」「返回订单」；处理中显示「刷新状态」「返回订单」。
- **响应式断点**：375px 基准；≥768px 居中最大 480px。
- **首屏内容**：导航栏、结果图标与文案、订单摘要、操作按钮。
- **线框图描述**：

## 3. 数据模型与 API 对接
- **主要 API**：

| 方法 | 端点 | 用途 | 鉴权 |
|-|-|-|-|
| GET | `/api/orders/{id}` | 查询订单详情（含支付状态） | Buyer |
| GET | `/api/payments/{orderId}` | 查询支付结果（含渠道信息） | Buyer |

- **请求参数**：`orderId` 路径参数。
- **响应字段**：`OrderDto` 含 `id`、`orderNo`、`status`、`totalAmount`、`paymentMethod`、`paidAt`、`tradeNo`；`PaymentOrderDto` 含 `paymentId`、`orderId`、`amount`、`channel`、`channelTradeNo`、`status`、`paidAt`、`failReason`。
- **数据加载策略**：进入页面调用 `GET /api/payments/{orderId}` 获取支付结果；处理中状态每 3 秒轮询，最多 10 次。
- **缓存策略**：不缓存，每次进入重新拉取；轮询期间不重复请求。
- **支付状态补偿查询端点（后端预留）**：后端 `PaymentsController` 另提供 `GET /api/payments/{paymentId}/status` 端点（Buyer 鉴权），主动查询渠道支付状态，若已支付则补偿更新支付单。当订单状态长时间停留在「处理中」且 `GET /api/payments/{orderId}` 未返回终态时，前端可改用此端点按 `paymentId` 主动查询渠道，触发服务端补偿更新。当前 buyer-app 默认使用 `GET /api/payments/{orderId}` 轮询即可满足多数场景，`GET /api/payments/{paymentId}/status` 作为补偿查询能力保留观察，待支付回调丢失场景增多时启用。

## 4. 交互流程
- **主流程**：
  1. 进入页面读取 `orderId` → `GET /api/payments/{orderId}` → 渲染结果图标与文案。
  2. 支付成功 → 展示绿色图标+「支付成功」+订单摘要+「查看订单」「继续购物」按钮。
  3. 支付失败 → 展示红色图标+「支付失败」+失败原因+「重新支付」「返回订单」按钮。
  4. 支付处理中 → 展示主色图标+「支付处理中」+每 3 秒轮询，状态变更后更新结果。
  5. 点击「查看订单」→ 跳 `/order/:id`。
  6. 点击「继续购物」→ 跳首页。
  7. 点击「重新支付」→ 跳 `/payment/initiate/:orderId`。
- **分支流程**：
  - 处理中轮询超时（10 次未变更）：提示「支付结果查询超时，请稍后在订单列表查看」+ 「返回订单」CTA。
  - 订单已取消：展示「订单已取消」+ 「返回订单列表」CTA。
  - 微信支付返回：从微信返回本端自动跳结果页。
- **跨页面流转**：订单详情页、支付发起页、首页。
- **状态机可视化**：处理中(轮询) → 成功(展示成功) / 失败(展示失败) / 超时(提示)。

## 5. 组件清单
- **基础组件**：`van-nav-bar`、`van-cell`、`van-cell-group`、`van-button`、`van-icon`、`van-skeleton`、`van-toast`（showToast）。
- **业务组件**：`PaymentResultHeader` 结果图标与文案；`PaymentOrderSummary` 订单摘要卡；`PaymentResultActions` 操作按钮组。
- **图表组件**：无。
- **图标使用**：返回 `arrow-left`；成功 `checked`；失败 `close`；处理中 `clock-o`。
- **空状态**：订单不存在显示全屏错误 + 「返回订单列表」CTA。

## 6. 视觉规范
- **主色应用**：处理中图标主色 `#1677FF`；「查看订单」按钮主色；链接主色。
- **状态色**：成功 `#52C41A`；失败 `#FF4D4F`；处理中 `#1677FF`；应付金额 `#FF4D4F`；失败原因 `#8C8C8C`。
- **间距**：结果图标区上下间距 32px；卡片内边距 12px；按钮间距 12px。
- **字体**：结果文案 20px semibold；订单号 12px `#8C8C8C`；摘要标签 14px `#595959`；摘要值 14px `#000000D9`；应付金额 18px semibold `#FF4D4F`；按钮 14px。
- **图标尺寸**：返回 20px；结果图标 64px。

## 7. 异常处理与边界
- **加载态**：首屏 `van-skeleton` 模拟结果区与摘要布局。
- **空数据**：订单不存在显示全屏错误 + 「返回订单列表」CTA。
- **错误态**：接口失败 `showToast` 「查询失败」+ 重试按钮；轮询超时提示文案。
- **权限控制**：Buyer 可见；订单归属校验由服务端完成。
- **并发与乐观锁**：轮询期间不重复请求；操作按钮点击后跳转，无并发问题。
- **危险操作确认**：不涉及。
