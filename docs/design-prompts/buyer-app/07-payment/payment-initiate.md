# 支付发起 - 用户 APP

## 1. 页面定位
- **所属端**：用户 APP
- **所属模块**：07-payment 支付
- **页面类型**：流程页
- **目标用户**：买家（Buyer）
- **核心目标**：买家在订单创建后选择支付渠道（支付宝/微信），发起支付并跳转第三方支付页面或调起原生支付，支付完成后跳支付结果页。
- **访问入口**：订单详情页/订单列表「去支付」；下单成功跳转；秒杀下单成功跳转。
- **实现状态**：✅ 已实现

## 2. 页面布局与信息架构
- **整体布局**：顶部 `van-nav-bar`（返回+标题「收银台」）+ 可滚动主体（订单摘要+支付方式+倒计时）+ 底部固定支付按钮，无 Tabbar。
- **关键区域**：
  - 区域 A（订单摘要）：`van-cell-group` 展示订单号+应付金额+支付截止时间倒计时。
  - 区域 B（支付方式）：`van-radio-group` 列出支付宝（H5 跳转）、微信（JSAPI 或 H5 调起）；每项含图标+名称+说明。
  - 区域 C（安全提示）：`van-notice-bar` 提示「支付环境安全加密，请放心支付」。
  - 区域 D（底部支付栏）：「确认支付 ¥{Amount}」主色按钮。
- **响应式断点**：375px 基准；≥768px 居中最大 480px。
- **首屏内容**：导航栏、订单摘要、支付方式、底部支付按钮。

## 3. 数据模型与 API 对接
- **主要 API**：

| 方法 | 端点 | 用途 | 鉴权 |
|-|-|-|-|
| GET | `/api/orders/{id}` | 查询订单详情（含应付金额与截止时间） | Buyer |
| POST | `/api/payments` | 发起支付（body: `{ orderId, channel: "wechat|alipay" }`，发布支付请求集成事件） | Buyer |

- **请求参数**：`PayOrderDto`（orderId、channel: "wechat"|"alipay"）作为 body。
- **响应字段**：`OrderDto` 含 `id`、`orderNo`、`status`、`totalAmount`、`expireAt`；发起支付返回 `ApiResponse`（无 data，支付参数经支付集成域异步返回，前端轮询订单状态或跳转第三方）。
- **数据加载策略**：进入页面调用 `GET /api/orders/{id}` 获取金额与截止时间；倒计时基于 `expireAt` 客户端计算。
- **缓存策略**：不缓存，每次进入重新拉取订单状态。

## 4. 交互流程
- **主流程**：
  1. 进入页面读取 `orderId` → `GET /api/orders/{id}` → 渲染订单摘要与倒计时。
  2. 选择支付方式 → `van-radio-group` change → 更新 `paymentMethod`。
  3. 点击「确认支付」→ 按钮 disabled + loading → `POST /api/payments`（body: `{ orderId, channel }`）→ 跳转第三方支付页面或调起原生支付。
  4. 支付完成后第三方回调通知服务端，前端轮询订单状态或跳 `/payment/result/:orderId`。
  5. 倒计时结束 → 标记「订单已超时」+ 「返回订单」CTA。
- **分支流程**：
  - 支付宝：H5 跳转支付宝页面，支付完成后返回本端跳结果页。
  - 微信：微信内调起 JSAPI 支付，微信外跳 H5 支付。
  - 订单已支付：跳 `/payment/result/:orderId` 显示成功。
  - 订单已取消：提示「订单已取消」+ 「返回订单列表」CTA。
- **跨页面流转**：支付成功跳支付结果页；返回订单详情页。
- **状态机可视化**：待支付(可发起) → 支付中(loading) → 成功(跳结果) / 失败(提示重试) / 超时(已取消)。

## 5. 组件清单
- **基础组件**：`van-nav-bar`、`van-cell`、`van-cell-group`、`van-radio-group`、`van-radio`、`van-button`、`van-count-down`（倒计时）、`van-notice-bar`、`van-skeleton`、`van-toast`（showToast）、`van-dialog`（showConfirmDialog）。
- **业务组件**：`PaymentOrderSummary` 订单摘要卡；`PaymentMethodRadio` 支付方式选项；`PaymentActionBar` 底部支付栏。
- **图表组件**：无。
- **图标使用**：返回 `arrow-left`；支付宝图标；微信图标；锁 `lock`。
- **空状态**：订单不存在或已取消显示全屏错误 + 「返回订单列表」CTA。

## 6. 视觉规范
- **主色应用**：确认支付按钮主色 `#1677FF`；选中的支付方式主色；倒计时主色。
- **状态色**：应付金额 `#FF4D4F`；倒计时警告 `#FAAD14`（剩余 < 5 分钟）；倒计时危险 `#FF4D4F`（剩余 < 1 分钟）；安全提示 `#52C41A`。
- **间距**：区域间距 12px；卡片内边距 12px；底部支付栏高 54px。
- **字体**：应付金额 24px semibold `#FF4D4F`；订单号 12px `#8C8C8C`；支付方式名 16px `#000000D9`；支付方式说明 12px `#8C8C8C`；确认支付按钮 16px semibold `#FFFFFF`。
- **图标尺寸**：返回 20px；支付方式图标 24px；锁 16px。

## 7. 异常处理与边界
- **加载态**：首屏 `van-skeleton` 模拟订单摘要与支付方式布局。
- **空数据**：订单不存在显示全屏错误 + 「返回订单列表」CTA。
- **错误态**：接口失败 `showToast` 「加载失败」+ 重试按钮；发起支付失败显示后端错误信息 3s。
- **权限控制**：Buyer 可见；订单归属校验由服务端完成。
- **并发与乐观锁**：支付按钮点击后立即 disabled + loading 直至响应返回；`Idempotency-Key` 头防重复发起；订单状态以服务端校验为准。
- **危险操作确认**：不涉及（支付非危险操作，但需防重复点击）。

## 8. 验收要点
- [ ] 订单摘要展示订单号、应付金额、支付截止倒计时。
- [ ] 支付方式可选择，默认选中支付宝。
- [ ] 确认支付按钮防重复点击（loading + Idempotency-Key）。
- [ ] 支付宝跳转 H5 支付页，微信调起 JSAPI 或 H5。
- [ ] 倒计时结束标记订单超时。
- [ ] 支付完成后跳支付结果页。
- **性能要求**：首屏 < 1s；发起支付响应 < 1.5s；倒计时每秒更新不卡顿。
- **可访问性**：倒计时 `aria-label`；支付方式 `role="radiogroup"`；按钮 `aria-label`。
