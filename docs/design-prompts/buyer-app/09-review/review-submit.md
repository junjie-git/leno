# 评价提交 - 用户 APP

## 1. 页面定位
- **所属端**：用户 APP
- **所属模块**：09-review 评价
- **页面类型**：表单页
- **目标用户**：买家（Buyer）
- **核心目标**：买家对已完成订单的订单行提交评价（评分+文字+图片），提交后进入审核流程，审核通过后展示在商品评价列表。
- **访问入口**：订单详情已完成订单点击「评价」；订单列表待评价入口。
- **实现状态**：✅ 已实现

## 2. 页面布局与信息架构
- **整体布局**：顶部 `van-nav-bar`（返回+标题「发表评价」）+ 可滚动主体（商品卡+评分+评价内容+图片上传+匿名开关）+ 底部固定提交按钮，无 Tabbar。
- **关键区域**：
  - 区域 A（商品卡）：`van-card` 展示商品图+标题+规格，确认评价对象。
  - 区域 B（评分区）：`van-rate` 5 星评分，默认 5 星，支持半星；评分下方文案随分数变化（1-2「差评」、3「中评」、4-5「好评」）。
  - 区域 C（评价内容）：`van-field` textarea 类型，placeholder「说说商品体验吧～」，最少 5 字，最多 500 字，带字数统计。
  - 区域 D（图片上传）：`van-uploader` 多图上传，最多 6 张，每张 < 5MB，支持预览与删除。
  - 区域 E（匿名开关）：`van-cell` + `van-switch` 匿名评价，默认关闭。
  - 区域 F（底部提交栏）：「提交评价」主色按钮。
- **响应式断点**：375px 基准；≥768px 居中最大 480px。
- **首屏内容**：导航栏、商品卡、评分区、评价内容输入框、底部提交按钮。
- **线框图描述**：

## 3. 数据模型与 API 对接
- **服务归属**：Review 域（评价端点 `/api/reviews/*`、`/api/products/{spuId}/reviews`；旧域 ReviewAfterSales 双轨兜底，端点路径不变）；订单查询 `/api/orders/{orderId}` 跨域属 Order BC
- **主要 API**：

| 方法 | 端点 | 用途 | 鉴权 |
|-|-|-|-|
| GET | `/api/orders/{orderId}` | 查询订单详情（含订单行） | Buyer |
| POST | `/api/orders/{orderId}/reviews` | 提交评价 | Buyer |

- **请求参数**：`orderId` 路径参数；提交评价 body `{ orderLineId, productId, skuId, rating, content, images, isAnonymous }`；rating 1-5 整数；content 5-500 字符；images URL 数组最多 6 张。
- **响应字段**：`{ reviewId, status }` 含评价标识与状态（PendingReview 待审核）。
- **数据加载策略**：进入页面调用 `GET /api/orders/{orderId}` 获取订单行信息；图片上传后返回 URL 填入表单。
- **缓存策略**：不缓存；草稿暂存 localStorage（防止误退出丢失内容）。

## 4. 交互流程
- **主流程**：
  1. 进入页面读取 `orderId` 与 `orderLineId` → `GET /api/orders/{orderId}` → 渲染商品卡。
  2. 选择评分 → `van-rate` change → 更新评分文案。
  3. 输入评价内容 → `van-field` input → 实时字数统计，5 字以下提交时校验。
  4. 上传图片 → `van-uploader` after-read → 调用图片上传接口 → 返回 URL 填入 images 数组。
  5. 切换匿名开关 → 更新 `isAnonymous`。
  6. 点击「提交评价」→ 表单校验（评分必填、内容 ≥5 字）→ 按钮 disabled + loading → `POST /api/orders/{orderId}/reviews` → 成功 `showToast` 「提交成功，等待审核」→ 返回订单详情页。
- **分支流程**：
  - 已评价：提示「该商品已评价」+ 「返回订单」CTA。
  - 订单未完成：提示「订单完成后才能评价」+ 「返回订单」CTA。
  - 图片上传失败：`showToast` 「图片上传失败」+ 重试。
- **跨页面流转**：提交成功返回订单详情页；跳「我的评价」页查看。
- **状态机可视化**：填写中 → 提交中(loading) → 成功(返回) / 失败(提示)。

## 5. 组件清单
- **基础组件**：`van-nav-bar`、`van-card`、`van-rate`、`van-field`、`van-uploader`、`van-cell`、`van-switch`、`van-button`、`van-image`（lazy-load + preview）、`van-skeleton`、`van-toast`（showToast）。
- **业务组件**：`ReviewProductCard` 商品卡；`RatingInput` 评分输入（含文案映射）；`ReviewImageUploader` 图片上传；`AnonymousToggle` 匿名开关。
- **图表组件**：无。
- **图标使用**：返回 `arrow-left`；图片上传 `photograph`；删除 `cross-o`。
- **空状态**：订单不存在显示全屏错误 + 「返回订单」CTA。

## 6. 视觉规范
- **主色应用**：提交评价按钮主色 `#1677FF`；评分激活态主色；上传按钮主色边框。
- **状态色**：好评 `#52C41A`；中评 `#FAAD14`；差评 `#FF4D4F`；字数统计 `#8C8C8C`。
- **间距**：区域间距 12px；卡片内边距 12px；底部提交栏高 50px。
- **字体**：商品标题 14px `#000000D9`（2 行省略）；规格 12px `#8C8C8C`；评分文案 16px medium；评价内容 14px `#000000D9`；字数统计 12px `#8C8C8C`；按钮 16px semibold `#FFFFFF`。
- **图标尺寸**：返回 20px；评分星 24px；上传图标 24px。

## 7. 异常处理与边界
- **加载态**：首屏 `van-skeleton` 模拟商品卡与评分区布局。
- **空数据**：订单不存在显示全屏错误 + 「返回订单」CTA。
- **错误态**：接口失败 `showToast` 「提交失败」+ 重试按钮；图片上传失败单独提示。
- **权限控制**：Buyer 可见；订单归属校验由服务端完成；只能评价已完成订单。
- **并发与乐观锁**：提交按钮点击后立即 disabled + loading 直至响应返回；`Idempotency-Key` 头防重复提交。
- **危险操作确认**：不涉及（提交评价非危险操作）。

## 8. 验收要点
- [ ] 评分默认 5 星，文案随分数变化。
- [ ] 评价内容最少 5 字，最多 500 字，带字数统计。
- [ ] 图片最多 6 张，每张 < 5MB，支持预览删除。
- [ ] 匿名开关可切换。
- [ ] 提交成功提示「等待审核」并返回订单详情。
- [ ] 防重复提交（按钮 loading + Idempotency-Key）。
- **性能要求**：首屏 < 1s；图片压缩上传；提交响应 < 1.5s。
- **可访问性**：评分 `role="radiogroup"`；输入框 `aria-label`；按钮 `aria-label`。
