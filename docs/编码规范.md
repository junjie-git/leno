# 电商平台编码规范

**文档版本**：V1.0
**技术栈基准**：.NET 10、ASP.NET Core 10 Web API、EF Core 10、DDD、CQRS、RabbitMQ + MassTransit、Redis、Elasticsearch 8.x、JWT + OAuth2
**创建日期**：2026-07-10
**适用范围**：电商平台全部 11 个限界上下文（BC1-BC11）及共享内核项目

## 1 文档概述

### 1.1 目的

本规范为电商平台全体开发人员提供统一的编码标准，确保代码在结构、风格、命名、安全与可维护性层面保持一致。本规范基于电商平台需求文档集（00-12 共 13 篇文档，覆盖 11 个限界上下文）提取的技术决策与架构约束整理而成，旨在达成以下目标：

- 统一 DDD 分层架构的编码实践，避免层间职责越界。
- 统一聚合设计、事件驱动、CQRS 读写分离等关键技术模式的实现方式。
- 统一命名、API 设计、安全、日志与配置的编码约定，降低团队协作与代码审查成本。
- 为新成员提供可执行的编码参考，缩短上手周期。

### 1.2 适用范围

本规范适用于电商平台所有 .NET 项目，包括 11 个限界上下文各自的 `{BC}.Domain`、`{BC}.Application`、`{BC}.Infrastructure`、`{BC}.Presentation` 四层项目，以及 `SharedKernel` 共享内核项目。所有 C# 源代码、配置文件、数据库迁移脚本、测试代码均须遵守本规范。

### 1.3 术语约定

| 术语 | 英文 | 定义 |
|-|-|-|
| 限界上下文 | Bounded Context (BC) | 领域模型的显式边界，拥有独立的聚合、统一语言与持久化模型 |
| 聚合根 | Aggregate Root | 聚合的对外入口，唯一持有外部引用权 |
| 领域事件 | Domain Event | 上下文内部已发生的重要业务事实 |
| 集成事件 | Integration Event | 跨上下文传递的事件，经事件总线发布订阅 |
| 命令 | Command | CQRS 写侧的意图对象，表达一个状态变更请求 |
| 查询 | Query | CQRS 读侧的查询对象，表达一个数据读取请求 |
| 发件箱模式 | Outbox Pattern | 聚合保存与事件记录在同一事务写入，后台进程轮询发布 |
| 防腐层 | Anti-Corruption Layer (ACL) | 隔离外部上下文或遗留系统的翻译层 |
| 统一语言 | Ubiquitous Language | 贯穿代码、文档与沟通的领域术语 |
| 工作单元 | Unit of Work (UoW) | 管理事务边界与变更提交的抽象 |

### 2.2 项目命名与依赖关系

| 项目 | 命名规则 | 依赖方向 |
|-|-|-|
| 领域层 | `{BC}.Domain` | 仅依赖 `SharedKernel`，不依赖任何技术框架 |
| 应用层 | `{BC}.Application` | 依赖 `{BC}.Domain` 与 `SharedKernel`，引用 MediatR（如使用） |
| 基础设施层 | `{BC}.Infrastructure` | 依赖 `{BC}.Domain` 与 `{BC}.Application`，引用 EF Core、Redis、MQ 等技术包 |
| 表现层 | `{BC}.Presentation` | 依赖 `{BC}.Application`，引用 ASP.NET Core |
| 共享内核 | `SharedKernel` | 不依赖任何业务上下文项目 |

依赖关系严格遵循依赖倒置原则：编译时依赖从外向内指向领域核心，领域层不引用任何外层项目。

```
Presentation → Application → Domain → SharedKernel
                    ↑                ↑
              Infrastructure ────────┘
```

## 3 DDD 分层编码规范

### 3.1 领域层编码规范

领域层是系统心脏，封装核心业务规则、不变量与领域事件，独立于任何技术细节。

**核心规范：**

1. 领域层不引用基础设施层、应用层、表现层的任何类型，也不引用 EF Core、Redis、MQ 等技术框架。
2. 仓储接口以 `I{聚合根名}Repository` 命名并定义在本层，不在基础设施层定义。
3. 领域对象方法应是行为意图明确的，避免 get/set 式贫血模型。
4. 聚合根通过构造函数或工厂方法保证创建时即处于有效状态。
5. 领域异常继承自定义基类 `DomainException`，携带业务语义而非技术语义。

**代码示例 — 聚合根（行为意图明确的方法）：**

```csharp
namespace Ordering.Domain.Aggregates.Orders;

/// <summary>
/// 订单聚合根，封装订单状态机与金额不变量。
/// 所有状态流转通过行为意图明确的方法完成，禁止外部直接 set 字段。
/// </summary>
public class Order : AggregateRoot
{
    public Guid OrderId { get; private set; }
    public string OrderNo { get; private set; } = default!;
    public Guid UserId { get; private set; }
    public Guid? SellerId { get; private set; }
    public OrderType OrderType { get; private set; }
    public OrderStatus Status { get; private set; }

    private readonly List<OrderItem> _items = new();
    public IReadOnlyCollection<OrderItem> Items => _items.AsReadOnly();

    public Money ItemsAmount { get; private set; } = default!;
    public Money DiscountAmount { get; private set; } = default!;
    public Money PointsOffsetAmount { get; private set; } = default!;
    public Money FreightAmount { get; private set; } = default!;
    public Money TotalAmount { get; private set; } = default!;

    public AddressSnapshot AddressSnapshot { get; private set; } = default!;
    public DateTime ExpireAt { get; private set; }
    public DateTime? PaidAt { get; private set; }
    public Guid? PaymentId { get; private set; }
    public string? TradeNo { get; private set; }
    public DateTime? CompletedAt { get; private set; }
    public DateTime? CancelledAt { get; private set; }
    public string? CancelReason { get; private set; }
    public int Version { get; private set; }

    // EF Core 无参构造函数
    private Order() { }

    /// <summary>
    /// 工厂方法，校验订单行与金额恒等式，生成订单号，置状态为待支付。
    /// </summary>
    public static Order Create(
        Guid orderId,
        string orderNo,
        Guid userId,
        Guid? sellerId,
        OrderType orderType,
        List<OrderItem> items,
        AddressSnapshot addressSnapshot,
        Money freightAmount,
        DateTime expireAt)
    {
        // 领域校验
        if (items == null || items.Count == 0)
            throw new OrderDomainException("订单至少包含一个订单行");
        if (expireAt <= DateTime.UtcNow)
            throw new OrderDomainException("支付截止时间必须晚于当前时间");

        var order = new Order
        {
            OrderId = orderId,
            OrderNo = orderNo,
            UserId = userId,
            SellerId = sellerId,
            OrderType = orderType,
            Status = OrderStatus.PendingPayment,
            AddressSnapshot = addressSnapshot,
            FreightAmount = freightAmount,
            ExpireAt = expireAt
        };

        order._items.AddRange(items);
        order.RecalculateAmounts();
        order.AddDomainEvent(new OrderCreatedEvent(order.OrderId, order.OrderNo, order.UserId));

        return order;
    }

    /// <summary>
    /// 标记已支付，仅待支付态可调用。
    /// </summary>
    public void MarkAsPaid(Guid paymentId, PaymentMethod channel, DateTime paidAt, string tradeNo)
    {
        if (Status != OrderStatus.PendingPayment)
            throw new OrderDomainException($"订单当前状态为 {Status}，不可标记为已支付");

        Status = OrderStatus.Paid;
        PaymentId = paymentId;
        PaymentMethod = channel;
        PaidAt = paidAt;
        TradeNo = tradeNo;

        AddDomainEvent(new OrderPaidEvent(OrderId, OrderNo, UserId, paymentId, tradeNo));
    }

    /// <summary>
    /// 取消订单，仅待支付态可调用。
    /// </summary>
    public void Cancel(string reason, string cancelledBy)
    {
        if (Status != OrderStatus.PendingPayment)
            throw new OrderDomainException($"订单当前状态为 {Status}，不可取消。已支付订单退款须走售后域");

        Status = OrderStatus.Cancelled;
        CancelledAt = DateTime.UtcNow;
        CancelReason = reason;

        AddDomainEvent(new OrderCancelledEvent(OrderId, OrderNo, UserId, reason, cancelledBy));
    }

    /// <summary>
    /// 确认收货，仅已发货态可调用。
    /// </summary>
    public void ConfirmReceipt()
    {
        if (Status != OrderStatus.Shipped)
            throw new OrderDomainException($"订单当前状态为 {Status}，不可确认收货");

        Status = OrderStatus.Completed;
        CompletedAt = DateTime.UtcNow;
        var afterSalesWindowEndsAt = CompletedAt.Value.AddDays(7);

        AddDomainEvent(new OrderCompletedEvent(OrderId, OrderNo, UserId, CompletedAt.Value, afterSalesWindowEndsAt));
    }

    private void RecalculateAmounts()
    {
        ItemsAmount = Money.Sum(_items.Select(i => i.UnitPrice.Multiply(i.Quantity)));
        TotalAmount = ItemsAmount
            .Subtract(DiscountAmount)
            .Subtract(PointsOffsetAmount)
            .Add(FreightAmount);
    }
}
```

### 3.2 应用层编码规范

应用层协调领域对象完成用户用例，本身很薄，不含业务规则，只做任务编排、事务管理、输入验证、安全认证、事件发布。

**核心规范：**

1. 应用服务方法名体现用例，如 `PlaceOrderAsync`、`CancelOrderAsync`。
2. 事务边界由应用服务通过 `IUnitOfWork` 控制，一个用例方法对应一个事务边界。
3. 禁止将领域实体直接暴露给表现层，必须通过 DTO 转换。
4. 输入验证在应用层入口完成，校验不通过直接返回，不进入领域层。
5. 外部副作用（发邮件、推送、发起支付）依赖基础设施层抽象接口而非具体实现。

**代码示例 — 应用服务：**

```csharp
namespace Ordering.Application.Services;

public class OrderAppService : IOrderAppService
{
    private readonly IOrderRepository _orderRepository;
    private readonly IStockReservationRepository _stockRepository;
    private readonly IOrderNumberGenerator _orderNumberGenerator;
    private readonly IUnitOfWork _unitOfWork;
    private readonly IEventBus _eventBus;
    private readonly ILogger<OrderAppService> _logger;

    public OrderAppService(
        IOrderRepository orderRepository,
        IStockReservationRepository stockRepository,
        IOrderNumberGenerator orderNumberGenerator,
        IUnitOfWork unitOfWork,
        IEventBus eventBus,
        ILogger<OrderAppService> logger)
    {
        _orderRepository = orderRepository;
        _stockRepository = stockRepository;
        _orderNumberGenerator = orderNumberGenerator;
        _unitOfWork = unitOfWork;
        _eventBus = eventBus;
        _logger = logger;
    }

    /// <summary>
    /// 下单用例：编排库存预占、订单创建、事件发布，控制事务边界。
    /// </summary>
    public async Task<PlaceOrderResponseDto> PlaceOrderAsync(
        PlaceOrderCommand command, CancellationToken ct = default)
    {
        // 1. 生成订单号
        var orderNo = await _orderNumberGenerator.GenerateAsync(ct);
        var orderId = Guid.NewGuid();

        // 2. 构建订单行与商品快照
        var items = command.Items.Select(i => OrderItem.Create(
            Guid.NewGuid(),
            i.SkuId,
            ProductSnapshot.Create(i.SkuName, i.Spec, i.ImageUrl),
            Money.Create(i.UnitPrice, "CNY"),
            i.Quantity)).ToList();

        // 3. 构建地址快照
        var addressSnapshot = AddressSnapshot.Create(
            command.Address.Recipient, command.Address.Phone,
            command.Address.Province, command.Address.City,
            command.Address.District, command.Address.Detail);

        // 4. 计算运费
        var freight = Money.Create(command.FreightAmount, "CNY");

        // 5. 创建订单聚合（工厂方法内校验不变量并附加领域事件）
        var order = Order.Create(
            orderId, orderNo, command.UserId, command.SellerId,
            OrderType.ProductOrder, items, addressSnapshot, freight,
            DateTime.UtcNow.AddMinutes(30));

        // 6. 库存预占（Redis Lua 原子操作在基础设施层完成）
        foreach (var item in items)
        {
            var stock = await _stockRepository.GetBySkuIdAsync(item.SkuId, ct);
            if (stock == null)
                throw new OrderDomainException($"SKU {item.SkuId} 库存记录不存在");
            stock.ReserveStock(orderId, item.Quantity);
        }

        // 7. 持久化（聚合保存与发件箱事件在同一事务）
        _orderRepository.Add(order);
        await _unitOfWork.SaveChangesAsync(ct);

        _logger.LogInformation("订单创建成功 OrderId={OrderId} OrderNo={OrderNo}", orderId, orderNo);

        return new PlaceOrderResponseDto(orderId, orderNo, order.TotalAmount.Amount);
    }
}
```

### 3.3 基础设施层编码规范

基础设施层实现领域层定义的抽象接口，提供具体技术能力，按子目录组织。

**核心规范：**

1. 按 `Persistence`、`Messaging`、`Caching`、`Storage`、`Payment`、`Notification` 子目录组织。
2. `DbContext`、渠道客户端等实现细节仅在本层可见，不泄露到应用层或领域层。
3. 仓储实现继承领域层定义的仓储接口，不定义新接口。
4. EF Core 配置使用 Fluent API，不使用 Data Annotation。

**代码示例 — DbContext：**

```csharp
namespace Ordering.Infrastructure.Persistence;

public class OrderingDbContext : DbContext
{
    public DbSet<Order> Orders => Set<Order>();
    public DbSet<OrderItem> OrderItems => Set<OrderItem>();
    public DbSet<StockReservation> StockReservations => Set<StockReservation>();
    public DbSet<OutboxMessage> OutboxMessages => Set<OutboxMessage>();

    public OrderingDbContext(DbContextOptions<OrderingDbContext> options) : base(options) { }

    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        modelBuilder.ApplyConfigurationsFromAssembly(typeof(OrderingDbContext).Assembly);
        base.OnModelCreating(modelBuilder);
    }

    public override async Task<int> SaveChangesAsync(CancellationToken ct = default)
    {
        // 审计字段统一填充
        foreach (var entry in ChangeTracker.Entries<IAuditable>())
        {
            switch (entry.State)
            {
                case EntityState.Added:
                    entry.Entity.CreatedAt = DateTime.UtcNow;
                    entry.Entity.UpdatedAt = DateTime.UtcNow;
                    break;
                case EntityState.Modified:
                    entry.Entity.UpdatedAt = DateTime.UtcNow;
                    break;
            }
        }
        return await base.SaveChangesAsync(ct);
    }
}
```

### 3.4 表现层编码规范

**核心规范：**

1. 控制器不包含业务逻辑或数据访问代码，只做接收请求、调用应用服务、返回结果。
2. 接口采用 RESTful 风格，资源以名词复数命名。
3. 输入输出一律使用 DTO，禁止将领域实体直接序列化返回。
4. 按角色拆分为独立部署单元（买家端、卖家端、运营端、系统管理端）。

**代码示例 — 控制器：**

```csharp
namespace Ordering.Presentation.Controllers;

[ApiController]
[Route("api/orders")]
[Authorize]
public class OrdersController : ControllerBase
{
    private readonly IOrderAppService _orderAppService;

    public OrdersController(IOrderAppService orderAppService)
    {
        _orderAppService = orderAppService;
    }

    /// <summary>
    /// 创建订单
    /// </summary>
    [HttpPost]
    [ProducesResponseType(typeof(ApiResponse<PlaceOrderResponseDto>), StatusCodes.Status201Created)]
    public async Task<IActionResult> PlaceOrder(
        [FromBody] PlaceOrderRequestDto request,
```

## 4 聚合设计规范

### 4.1 聚合根编码规范

**核心原则：**

1. 聚合边界以一致性为依据：单次事务只修改一个聚合。
2. 聚合根是唯一入口，外部对象只能持有聚合根引用，不可直接引用内部实体。
3. 聚合内不变量由聚合根方法保证，避免在应用层散落校验逻辑。
4. 大聚合应拆分，将高频独立变更的部分独立为聚合。
5. 所有状态变更通过行为意图明确的方法完成，字段以 `private set` 修饰，外部不可直接赋值。

**代码示例 — 聚合基类：**

```csharp
namespace SharedKernel.Domain;

/// <summary>
/// 聚合根基类，管理领域事件集合与乐观锁版本号。
/// </summary>
public abstract class AggregateRoot : Entity
{
    private readonly List<IDomainEvent> _domainEvents = new();

    public IReadOnlyCollection<IDomainEvent> DomainEvents => _domainEvents.AsReadOnly();

    public void ClearDomainEvents() => _domainEvents.Clear();

    protected void AddDomainEvent(IDomainEvent domainEvent) => _domainEvents.Add(domainEvent);
}

/// <summary>
/// 实体基类，提供标识与审计字段。
/// </summary>
public abstract class Entity : IAuditable
{
    public DateTime CreatedAt { get; set; }
    public DateTime UpdatedAt { get; set; }
    public string? CreatedBy { get; set; }
    public string? UpdatedBy { get; set; }
}

public interface IAuditable
{
    DateTime CreatedAt { get; set; }
    DateTime UpdatedAt { get; set; }
    string? CreatedBy { get; set; }
    string? UpdatedBy { get; set; }
}
```

**代码示例 — 库存预占聚合根（高频独立聚合拆分）：**

```csharp
namespace Ordering.Domain.Aggregates.StockReservations;

/// <summary>
/// 库存预占聚合根，按 SKU 独立，承载高频预占/扣减/释放台账。
/// 不变量：AvailableQty = 基线 - ReservedQty - DeductedQty，且 AvailableQty >= 0
/// </summary>
public class StockReservation : AggregateRoot
{
    public Guid SkuId { get; private set; }
    public int AvailableQty { get; private set; }
    public int ReservedQty { get; private set; }
    public int DeductedQty { get; private set; }
    public int Version { get; private set; }

    private StockReservation() { }

    public static StockReservation Create(Guid skuId, int baseLineQty)
    {
        if (baseLineQty < 0)
            throw new DomainException("库存基线不可为负");

        return new StockReservation
        {
            SkuId = skuId,
            AvailableQty = baseLineQty,
            ReservedQty = 0,
            DeductedQty = 0
        };
    }

    /// <summary>
    /// 预占库存
    /// </summary>
    public void ReserveStock(Guid orderId, int quantity)
    {
        if (quantity <= 0)
            throw new DomainException("预占数量必须大于 0");
        if (AvailableQty < quantity)
            throw new DomainException($"SKU {SkuId} 可售库存不足，当前可用 {AvailableQty}，请求 {quantity}");

        AvailableQty -= quantity;
        ReservedQty += quantity;

        AddDomainEvent(new StockReservedEvent(SkuId, orderId, quantity));
    }

    /// <summary>
    /// 确认扣减（支付成功后调用）
    /// </summary>
    public void ConfirmStockDeduction(Guid orderId, int quantity)
    {
        if (ReservedQty < quantity)
            throw new DomainException($"SKU {SkuId} 预占库存不足");

        ReservedQty -= quantity;
        DeductedQty += quantity;

        AddDomainEvent(new StockConfirmedEvent(SkuId, orderId, quantity));
    }

    /// <summary>
    /// 释放预占（订单取消时调用）
    /// </summary>
    public void ReleaseStock(Guid orderId, int quantity)
    {
        if (ReservedQty < quantity)
            throw new DomainException($"SKU {SkuId} 预占库存不足，无法释放");

        ReservedQty -= quantity;
        AvailableQty += quantity;

        AddDomainEvent(new StockReleasedEvent(SkuId, orderId, quantity));
    }

    /// <summary>
    /// 补货（商品域补货事件驱动）
    /// </summary>
    public void Replenish(int delta)
    {
        if (delta <= 0)
            throw new DomainException("补货数量必须大于 0");

        AvailableQty += delta;
    }
}
```

### 4.2 实体编码规范

实体是聚合内部有标识的对象，外部不直接引用，只能经聚合根访问。

**核心规范：**

1. 实体标识在聚合内唯一，以 GUID 类型表示。
2. 实体的状态变更通过聚合根方法间接触发，不暴露 public set。
3. 实体不持有对其他聚合根的直接对象引用，只持有 ID 引用。

**代码示例 — 订单行实体：**

```csharp
namespace Ordering.Domain.Aggregates.Orders;

/// <summary>
/// 订单行实体，持有下单瞬间的价格与商品快照。
/// 外部不直接引用，只能经 Order 聚合根访问。
/// </summary>
public class OrderItem : Entity
{
    public Guid OrderItemId { get; private set; }
    public Guid SkuId { get; private set; }
    public ProductSnapshot ProductSnapshot { get; private set; } = default!;
    public Money UnitPrice { get; private set; } = default!;
    public int Quantity { get; private set; }
    public Money DiscountAllocation { get; private set; } = default!;
    public Money Subtotal { get; private set; } = default!;
    public Guid? SourceCartItemId { get; private set; }

    private OrderItem() { }

    public static OrderItem Create(
        Guid orderItemId, Guid skuId, ProductSnapshot snapshot,
        Money unitPrice, int quantity, Guid? sourceCartItemId = null)
    {
        if (quantity < 1 || quantity > 99)
            throw new OrderDomainException("购买数量必须在 1-99 之间");
        if (unitPrice.Amount <= 0)
            throw new OrderDomainException("单价必须大于 0");

        var item = new OrderItem
        {
            OrderItemId = orderItemId,
            SkuId = skuId,
            ProductSnapshot = snapshot,
            UnitPrice = unitPrice,
            Quantity = quantity,
            DiscountAllocation = Money.Zero(unitPrice.Currency),
            SourceCartItemId = sourceCartItemId
        };
        item.Subtotal = unitPrice.Multiply(quantity);
        return item;
    }

    /// <summary>
    /// 分摊优惠金额，由 Order 聚合根调用
    /// </summary>
    internal void ApplyDiscountAllocation(Money allocation)
    {
        if (allocation.Amount < 0)
            throw new OrderDomainException("优惠分摊不可为负");
        if (allocation.Amount > Subtotal.Amount)
            throw new OrderDomainException("优惠分摊不可超过行小计");

        DiscountAllocation = allocation;
        Subtotal = UnitPrice.Multiply(Quantity).Subtract(allocation);
    }
}
```

### 4.3 值对象编码规范

值对象是不可变的、通过属性值判断相等性的领域对象。

**核心规范：**

1. 值对象不可变，创建后不可修改属性值。
2. 通过全部属性值判断相等性，重写 `Equals` 和 `GetHashCode`。
3. 使用 `record` 或包含只读属性的 `class` 实现。
4. 值对象不持有标识，不参与聚合根引用关系。

**代码示例 — Money 值对象（共享内核）：**

```csharp
namespace SharedKernel.ValueObjects;

/// <summary>
/// 金额值对象，金额与币种，四舍五入到两位小数。
/// 所有上下文统一货币运算。
/// </summary>
public sealed record Money
{
    public decimal Amount { get; }
    public string Currency { get; }

    private Money(decimal amount, string currency)
    {
        Amount = Math.Round(amount, 2, MidpointRounding.AwayFromZero);
        Currency = currency;
    }

    public static Money Create(decimal amount, string currency)
    {
        if (string.IsNullOrWhiteSpace(currency))
            throw new ArgumentException("币种不可为空", nameof(currency));
        if (amount < 0)
            throw new ArgumentException("金额不可为负", nameof(amount));

        return new Money(amount, currency);
    }

    public static Money Zero(string currency) => new(0, currency);

    public Money Add(Money other)
    {
        AssertSameCurrency(other);
        return new Money(Amount + other.Amount, Currency);
    }

    public Money Subtract(Money other)
    {
        AssertSameCurrency(other);
        return new Money(Amount - other.Amount, Currency);
    }

    public Money Multiply(int factor) => new(Amount * factor, Currency);

    public static Money Sum(IEnumerable<Money> source)
    {
        var list = source.ToList();
        if (list.Count == 0)
            throw new ArgumentException("集合不可为空");

        var currency = list[0].Currency;
        var total = 0m;
        foreach (var money in list)
        {
            money.AssertSameCurrency(new Money(total, currency));
            total += money.Amount;
        }
        return new Money(total, currency);
    }

    private void AssertSameCurrency(Money other)
    {
        if (Currency != other.Currency)
            throw new InvalidOperationException($"币种不匹配: {Currency} vs {other.Currency}");
    }
}
```

## 5 仓储与持久化规范

### 5.1 仓储接口定义

仓储接口定义在领域层，以 `I{聚合根名}Repository` 命名，只暴露聚合根级别的操作，不暴露内部实体。

**核心规范：**

1. 仓储接口定义在领域层，实现在基础设施层。
2. 仓储只操作聚合根，不直接操作内部实体。
3. 查询方法返回聚合根或聚合根集合，不返回 DTO（DTO 转换在应用层完成）。
4. 写操作（Add/Update）不立即持久化，由 `IUnitOfWork` 统一提交。

### 5.2 EF Core 配置规范

使用 Fluent API 进行实体映射配置，不使用 Data Annotation，每个聚合根一个配置类。

**核心规范：**

1. 每个聚合根/实体一个 `IEntityTypeConfiguration<T>` 配置类。
2. 字段映射使用 Fluent API，列名、类型、约束显式声明。
3. 值对象使用 `OwnsOne` 或 `OwnsMany` 映射。
4. 乐观锁字段使用 `IsRowVersion()` 配置。
5. 审计字段由 `SaveChangesAsync` 统一填充。

**代码示例 — EF Core 配置：**

```csharp
namespace Ordering.Infrastructure.Persistence.Configurations;

public class OrderConfiguration : IEntityTypeConfiguration<Order>
{
    public void Configure(EntityTypeBuilder<Order> builder)
    {
        builder.ToTable("Orders");
        builder.HasKey(o => o.OrderId);

        builder.Property(o => o.OrderNo)
            .HasMaxLength(32)
            .IsRequired();

        builder.Property(o => o.OrderType)
            .HasConversion<string>()
            .HasMaxLength(20);

        builder.Property(o => o.Status)
            .HasConversion<string>()
            .HasMaxLength(20);

        builder.Property(o => o.UserId).IsRequired();
        builder.Property(o => o.SellerId).IsRequired(false);

        // 金额值对象映射
        builder.OwnsOne(o => o.ItemsAmount, money =>
        {
            money.Property(m => m.Amount).HasColumnName("ItemsAmount").HasPrecision(18, 2);
            money.Property(m => m.Currency).HasColumnName("ItemsAmountCurrency").HasMaxLength(3);
        });

        builder.OwnsOne(o => o.DiscountAmount, money =>
        {
            money.Property(m => m.Amount).HasColumnName("DiscountAmount").HasPrecision(18, 2);
            money.Property(m => m.Currency).HasColumnName("DiscountAmountCurrency").HasMaxLength(3);
        });

        builder.OwnsOne(o => o.TotalAmount, money =>
        {
            money.Property(m => m.Amount).HasColumnName("TotalAmount").HasPrecision(18, 2);
            money.Property(m => m.Currency).HasColumnName("TotalAmountCurrency").HasMaxLength(3);
        });

        // 地址快照值对象映射
        builder.OwnsOne(o => o.AddressSnapshot, addr =>
        {
            addr.Property(a => a.Recipient).HasMaxLength(50).IsRequired();
            addr.Property(a => a.Phone).HasMaxLength(20).IsRequired();
            addr.Property(a => a.Province).HasMaxLength(50);
            addr.Property(a => a.City).HasMaxLength(50);
            addr.Property(a => a.District).HasMaxLength(50);
            addr.Property(a => a.Detail).HasMaxLength(200).IsRequired();
        });

        // 订单行集合（内部实体）
        builder.HasMany(o => o.Items)
            .WithOne()
            .HasForeignKey(i => i.OrderId) // 假设 OrderItem 有 OrderId
            .OnDelete(DeleteBehavior.Cascade);

        // 领域事件不持久化（Transient 字段）
        builder.Ignore(o => o.DomainEvents);

        // 乐观锁
        builder.Property(o => o.Version).IsRowVersion();

        // 审计字段
        builder.Property(o => o.CreatedAt).IsRequired();
        builder.Property(o => o.UpdatedAt).IsRequired();

        // 索引
        builder.HasIndex(o => o.OrderNo).IsUnique();
        builder.HasIndex(o => new { o.UserId, o.Status });
    }
}
```

### 5.4 工作单元（Unit of Work）

工作单元管理事务边界与变更提交，应用服务通过它控制事务边界。

```csharp
// 领域层 - 工作单元接口
namespace SharedKernel.Domain;

public interface IUnitOfWork : IDisposable
{
    Task<int> SaveChangesAsync(CancellationToken ct = default);
    Task<bool> SaveEntitiesAsync(CancellationToken ct = default);
}

// 基础设施层 - 工作单元实现
namespace Ordering.Infrastructure.Persistence.UnitOfWork;

public class UnitOfWork : IUnitOfWork
{
    private readonly OrderingDbContext _context;
    private readonly IDomainEventDispatcher _domainEventDispatcher;

    public UnitOfWork(OrderingDbContext context, IDomainEventDispatcher domainEventDispatcher)
    {
        _context = context;
        _domainEventDispatcher = domainEventDispatcher;
    }

    /// <summary>
    /// 保存变更并派发领域事件。
    /// 聚合保存与发件箱事件记录在同一事务写入，
    /// 领域事件在事务提交后异步派发到事件总线。
    /// </summary>
    public async Task<bool> SaveEntitiesAsync(CancellationToken ct = default)
    {
        // 1. 收集所有聚合的领域事件
        var domainEvents = _context.ChangeTracker
            .Entries<AggregateRoot>()
            .SelectMany(e => e.Entity.DomainEvents)
            .ToList();

        // 2. 将集成事件写入发件箱表（与聚合保存在同一事务）
        foreach (var domainEvent in domainEvents)
        {
            if (domainEvent is IIntegrationEvent integrationEvent)
            {
                _context.OutboxMessages.Add(OutboxMessage.Create(integrationEvent));
            }
        }

        // 3. 保存聚合变更与发件箱记录（同一事务）
        await _context.SaveChangesAsync(ct);

        // 4. 清除已处理的领域事件
        foreach (var entry in _context.ChangeTracker.Entries<AggregateRoot>())
        {
            entry.Entity.ClearDomainEvents();
        }

        // 5. 派发本地领域事件（当前上下文内同步消费）
        await _domainEventDispatcher.DispatchAsync(domainEvents, ct);

        return true;
    }

    public async Task<int> SaveChangesAsync(CancellationToken ct = default)
    {
        return await _context.SaveChangesAsync(ct);
    }

    public void Dispose() => _context.Dispose();
}
```

## 6 事件编码规范

### 6.1 领域事件

领域事件在聚合方法中产生、在当前上下文内消费，用于解耦聚合内部逻辑。

**核心规范：**

1. 事件命名统一为过去时，如 `OrderCreatedEvent`、`OrderPaidEvent`。
2. 领域事件携带事件发生时的关键业务数据，不携带聚合根完整对象。
3. 领域事件通过聚合根的 `AddDomainEvent` 方法附加，由工作单元在事务提交后派发。
4. 领域事件在当前上下文内消费，不跨上下文传递。

### 6.2 集成事件

集成事件跨上下文传递，经事件总线发布订阅。集成事件定义在共享内核或各上下文的 Application 层。

**核心规范：**

1. 集成事件命名统一为过去时，与领域事件命名一致。
2. 集成事件契约（命名与字段约定）定义在共享层，变更需所有消费方协商。
3. 集成事件携带跨上下文必需的最小字段集，以 ID 引用而非对象引用。
4. 集成事件通过发件箱模式发布，保证本地事务与事件发布的原子性。

**代码示例 — 集成事件定义：**

```csharp
// 共享内核 - 集成事件接口
namespace SharedKernel.Events;

public interface IIntegrationEvent
{
    Guid EventId { get; }
    DateTime OccurredOn { get; }
}

// 共享内核 - 跨上下文集成事件契约
namespace SharedKernel.IntegrationEvents;

/// <summary>
/// 支付成功集成事件，支付集成域发布，订单域消费。
/// </summary>
public record PaymentSucceededIntegrationEvent(
    Guid EventId,
    DateTime OccurredOn,
    Guid PaymentOrderId,
    string PaymentNo,
    Guid OrderId,
    string BusinessOrderNo,
    Guid UserId,
    string Channel,
    string TradeNo,
    decimal Amount,
```

### 6.3 发件箱模式（Outbox Pattern）

发件箱模式保证聚合保存与事件记录在同一事务写入，后台进程轮询发件箱表并发布到消息队列。

**代码示例 — 发件箱实体与发布器：**

```csharp
// 基础设施层 - 发件箱消息实体
namespace Ordering.Infrastructure.Messaging.Outbox;

public class OutboxMessage
{
    public Guid Id { get; private set; }
    public string EventType { get; private set; } = default!;
    public string EventData { get; private set; } = default!;
    public DateTime OccurredOn { get; private set; }
    public DateTime? ProcessedOn { get; private set; }
    public int RetryCount { get; private set; }
    public string? Error { get; private set; }
    public OutboxStatus Status { get; private set; }

    private OutboxMessage() { }

    public static OutboxMessage Create(IIntegrationEvent integrationEvent)
    {
        return new OutboxMessage
        {
            Id = Guid.NewGuid(),
            EventType = integrationEvent.GetType().FullName!,
            EventData = JsonSerializer.Serialize(integrationEvent, integrationEvent.GetType()),
            OccurredOn = integrationEvent.OccurredOn,
            Status = OutboxStatus.Pending
        };
    }

    public void MarkAsProcessed()
    {
        Status = OutboxStatus.Processed;
        ProcessedOn = DateTime.UtcNow;
    }

    public void MarkAsFailed(string error, int maxRetryCount)
    {
        RetryCount++;
        Error = error;
        Status = RetryCount >= maxRetryCount ? OutboxStatus.DeadLetter : OutboxStatus.Pending;
    }
}

public enum OutboxStatus { Pending, Processed, DeadLetter }

// 基础设施层 - 发件箱后台发布器
namespace Ordering.Infrastructure.Messaging.Outbox;

public class OutboxPublisher : BackgroundService
{
    private readonly IServiceProvider _serviceProvider;
    private readonly IEventBus _eventBus;
    private readonly ILogger<OutboxPublisher> _logger;
    private const int BatchSize = 50;
    private const int MaxRetryCount = 5;
    private static readonly TimeSpan PollingInterval = TimeSpan.FromSeconds(5);

    public OutboxPublisher(
        IServiceProvider serviceProvider,
        IEventBus eventBus,
        ILogger<OutboxPublisher> logger)
    {
        _serviceProvider = serviceProvider;
        _eventBus = eventBus;
        _logger = logger;
    }

    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        while (!stoppingToken.IsCancellationRequested)
        {
            try
            {
                using var scope = _serviceProvider.CreateScope();
                var context = scope.ServiceProvider.GetRequiredService<OrderingDbContext>();

                var pendingMessages = await context.OutboxMessages
                    .Where(m => m.Status == OutboxStatus.Pending)
                    .OrderBy(m => m.OccurredOn)
                    .Take(BatchSize)
                    .ToListAsync(stoppingToken);

                foreach (var message in pendingMessages)
                {
                    try
                    {
                        var eventType = Type.GetType(message.EventType)!;
                        var integrationEvent = JsonSerializer.Deserialize(message.EventData, eventType)
                            as IIntegrationEvent;

                        await _eventBus.PublishAsync(integrationEvent!, stoppingToken);
                        message.MarkAsProcessed();
                    }
                    catch (Exception ex)
                    {
                        _logger.LogError(ex, "发件箱消息发布失败 Id={MessageId}", message.Id);
                        message.MarkAsFailed(ex.Message, MaxRetryCount);
                    }
                }

                await context.SaveChangesAsync(stoppingToken);
            }
            catch (Exception ex)
            {
                _logger.LogError(ex, "发件箱轮询异常");
            }

            await Task.Delay(PollingInterval, stoppingToken);
        }
    }
}
```

### 6.4 事件处理器

**核心规范：**

1. 领域事件处理器在应用层实现，消费当前上下文内的领域事件。
2. 集成事件消费者在基础设施层实现，消费跨上下文的集成事件。
3. 消费失败进入死信队列并重试，重试次数耗尽后转人工处理。
4. 事件处理器必须幂等，同一事件重复消费不产生副作用。

```csharp
    private readonly IUnitOfWork _unitOfWork;
```

## 7 CQRS 编码规范

### 7.1 CQRS 总体规范

Command 侧使用 EF Core 写库保证 ACID，Query 侧直接查询 Elasticsearch 读库并辅以 Redis 缓存。写库变更通过事件总线同步到读库。

**核心规范：**

1. Command 对象以 `{动作}{资源名}Command` 命名，如 `PlaceOrderCommand`。
2. Query 对象以 `{资源名}Query` 命名，如 `OrderQuery`。
3. Command 处理器走写库（EF Core），Query 处理器走读库（ES）或缓存（Redis）。
4. Command 与 Query 物理分离，可独立扩缩容。

### 7.2 Command 编码规范

**代码示例 — 命令对象与处理器：**


### 7.3 Query 编码规范

**代码示例 — 查询对象与处理器（ES 读库 + Redis 缓存）：**

```csharp
// 应用层 - 查询对象
namespace Ordering.Application.Queries;

/// <summary>
/// 订单列表查询
/// </summary>
public record OrderQuery(
    Guid? UserId,
    OrderStatus? Status,
    string? Keyword,
    int Page = 1,
    int PageSize = 20) : IRequest<PagedResult<OrderDto>>;

// 应用层 - 查询处理器（走 ES 读库）
namespace Ordering.Application.Queries.Handlers;

public class OrderQueryHandler : IRequestHandler<OrderQuery, PagedResult<OrderDto>>
{
    private readonly IElasticClient _elasticClient;
    private readonly ICacheService _cacheService;
    private const string IndexName = "orders";

    public OrderQueryHandler(IElasticClient elasticClient, ICacheService cacheService)
    {
        _elasticClient = elasticClient;
        _cacheService = cacheService;
    }

    public async Task<PagedResult<OrderDto>> Handle(OrderQuery request, CancellationToken ct)
    {
        // 缓存键
        var cacheKey = $"orders:list:{request.UserId}:{request.Status}:{request.Keyword}:{request.Page}:{request.PageSize}";

        // 尝试从缓存读取
        var cached = await _cacheService.GetAsync<PagedResult<OrderDto>>(cacheKey, ct);
        if (cached != null)
            return cached;

        // 构建 ES 查询
        var mustClauses = new List<Func<QueryContainerDescriptor<OrderDocument>, QueryContainer>>();

        if (request.UserId.HasValue)
            mustClauses.Add(q => q.Term(t => t.Field(f => f.UserId).Value(request.UserId.Value)));

        if (request.Status.HasValue)
            mustClauses.Add(q => q.Term(t => t.Field(f => f.Status).Value(request.Status.Value.ToString())));

        if (!string.IsNullOrWhiteSpace(request.Keyword))
            mustClauses.Add(q => q.Match(m => m.Field(f => f.OrderNo).Query(request.Keyword)));

        var searchResponse = await _elasticClient.SearchAsync<OrderDocument>(s => s
            .Index(IndexName)
            .From((request.Page - 1) * request.PageSize)
            .Size(request.PageSize)
            .Sort(ss => ss.Descending(f => f.CreatedAt))
            .Query(q => q.Bool(b => b.Must(mustClauses.ToArray()))), ct);

        var items = searchResponse.Documents
            .Select(doc => new OrderDto(doc.OrderId, doc.OrderNo, doc.Status,
                doc.TotalAmount, doc.CreatedAt))
            .ToList();

        var result = new PagedResult<OrderDto>(items, (int)searchResponse.Total, request.Page, request.PageSize);

        // 写入缓存（随机过期时间防雪崩）
        var expiry = TimeSpan.FromSeconds(Random.Shared.Next(60, 120));
        await _cacheService.SetAsync(cacheKey, result, expiry, ct);

        return result;
    }
}
```

### 8.5 幂等性处理

写操作通过 `Idempotency-Key` 头支持重复请求安全，支付回调与通知发送强制要求幂等键。

```csharp
namespace Ordering.Presentation.Middleware;

/// <summary>
/// 幂等性中间件：基于 Idempotency-Key 头与 Redis 缓存实现。
/// </summary>
public class IdempotencyMiddleware
{
    private readonly RequestDelegate _next;
    private readonly ICacheService _cacheService;

    public IdempotencyMiddleware(RequestDelegate next, ICacheService cacheService)
    {
        _next = next;
        _cacheService = cacheService;
    }

    public async Task InvokeAsync(HttpContext context)
    {
        // 仅对写操作生效
        if (!IsWriteMethod(context.Request.Method))
        {
            await _next(context);
            return;
        }

        var idempotencyKey = context.Request.Headers["Idempotency-Key"].FirstOrDefault();
        if (string.IsNullOrEmpty(idempotencyKey))
        {
            // 非强制场景放行，强制场景（支付回调）由 Action 过滤器校验
            await _next(context);
            return;
        }

        var cacheKey = $"idempotency:{idempotencyKey}";
        var cachedResponse = await _cacheService.GetAsync<string>(cacheKey, context.RequestAborted);

        if (cachedResponse != null)
        {
            // 幂等返回缓存结果
            context.Response.ContentType = "application/json";
            context.Response.StatusCode = StatusCodes.Status200OK;
            await context.Response.WriteAsync(cachedResponse, context.RequestAborted);
            return;
        }

        // 缓存请求路径标记（防止并发重复执行）
        await _cacheService.SetAsync(cacheKey, "processing", TimeSpan.FromMinutes(30), context.RequestAborted);

        // 捕获响应体
        var originalBodyStream = context.Response.Body;
        using var responseBody = new MemoryStream();
        context.Response.Body = responseBody;

        await _next(context);

        context.Response.Body = originalBodyStream;
        responseBody.Seek(0, SeekOrigin.Begin);
        var responseText = await new StreamReader(responseBody).ReadToEndAsync(context.RequestAborted);

        // 更新缓存为最终响应
        await _cacheService.SetAsync(cacheKey, responseText, TimeSpan.FromMinutes(30), context.RequestAborted);

        responseBody.Seek(0, SeekOrigin.Begin);
        await responseBody.CopyToAsync(originalBodyStream, context.RequestAborted);
    }

    private static bool IsWriteMethod(string method)
        => method is "POST" or "PUT" or "PATCH" or "DELETE";
}
```

### 8.6 异常处理

全局异常过滤器统一捕获并转换为标准响应结构。

```csharp
namespace Ordering.Presentation.Filters;

/// <summary>
/// 全局异常过滤器：将领域异常、验证异常、未处理异常统一转换为 API 响应。
/// </summary>
public class GlobalExceptionFilter : IExceptionFilter
{
    private readonly ILogger<GlobalExceptionFilter> _logger;

    public GlobalExceptionFilter(ILogger<GlobalExceptionFilter> logger)
    {
        _logger = logger;
    }

    public void OnException(ExceptionContext context)
    {
        var traceId = Activity.Current?.Id ?? context.HttpContext.TraceIdentifier;

        switch (context.Exception)
        {
            case DomainException domainEx:
                _logger.LogWarning(domainEx,
                    "领域异常 ErrorCode={Code} TraceId={TraceId}", domainEx.ErrorCode, traceId);
                context.Result = new BadRequestObjectResult(ApiResponse<object>.Fail(400, domainEx.Message));
                context.HttpContext.Response.Headers["X-Trace-Id"] = traceId;
                break;

            case ValidationException validationEx:
                context.Result = new BadRequestObjectResult(
                    ApiResponse<object>.Fail(422, validationEx.Message));
                break;

            case UnauthorizedAccessException:
                context.Result = new UnauthorizedObjectResult(
                    ApiResponse<object>.Fail(401, "未授权"));
                break;

            default:
                _logger.LogError(context.Exception,
                    "未处理异常 TraceId={TraceId}", traceId);
                context.Result = new ObjectResult(
                    ApiResponse<object>.Fail(500, "服务器内部错误"))
                {
                    StatusCode = 500
                };
                break;
        }

        context.ExceptionHandled = true;
    }
}
```

### 10.4 限流规范

```csharp
/// <summary>
/// Redis 滑动窗口限流服务
/// </summary>
public class SlidingWindowRateLimiter
{
    private readonly IConnectionMultiplexer _redis;
    private const string LuaScript = @"
        local key = KEYS[1]
        local window = tonumber(ARGV[1])
        local limit = tonumber(ARGV[2])
        local now = tonumber(ARGV[3])
        local clearBefore = now - window
        redis.call('ZREMRANGEBYSCORE', key, 0, clearBefore)
        local count = redis.call('ZCARD', key)
        if count < limit then
            redis.call('ZADD', key, now, now)
            redis.call('EXPIRE', key, window)
            return 1
        end
        return 0
    ";

    private readonly LoadedLuaScript _loadedScript;

    public SlidingWindowRateLimiter(IConnectionMultiplexer redis)
    {
        _redis = redis;
        var server = redis.GetServer(redis.GetEndPoints()[0]);
        _loadedScript = LuaScript.Prepare(LuaScript);
    }

    public async Task<bool> TryAcquireAsync(string key, int limit, TimeSpan window, CancellationToken ct = default)
    {
        var db = _redis.GetDatabase();
        var now = DateTimeOffset.UtcNow.ToUnixTimeMilliseconds();
        var parameters = new { key = key, window = (long)window.TotalMilliseconds, limit = limit, now = now };
        var result = (int)await _loadedScript.EvaluateAsync(db, parameters);
```

### 10.5 支付金额强校验

支付回调与主动查询补偿在标记订单成功前，必须校验渠道返回的实付金额与 `PaymentOrder.Amount` 一致，不一致一律拒绝并返回 FAIL，禁止标记成功。本规则覆盖所有支付渠道（WeChatPay / Alipay / 主动查询补偿）。

**核心规范：**

1. 所有支付渠道 `NotifyHandler.HandlePaymentNotifyAsync` 必须从渠道回调原始报文中解析实付金额（`ChannelNotifyResult.Amount`），并在调用 `PaymentOrder.MarkSucceeded` 前传入校验。
2. `PaymentOrder.MarkSucceeded(amount)` 内部校验 `amount == Amount`，不一致抛 `PaymentDomainException`，订单保持原状态。
3. 主动查询补偿（`PaymentAppService.QueryPaymentStatusAsync`）在标记成功前同样校验金额，不一致记录告警并进入人工对账队列，不调用 `MarkSucceeded`。
4. 金额不一致一律返回 FAIL 给渠道让渠道重试，禁止标记成功；同时记录安全告警结构化日志（含 OrderId、Expected、Actual）。
5. 金额解析必须从渠道签名保护的字段中提取，禁止信任未签名字段（防伪造金额）。

**代码示例 — 回调金额校验：**

```csharp
public async Task<NotifyResult> HandlePaymentNotifyAsync(
    string rawBody, IReadOnlyDictionary<string, string> headers, CancellationToken ct)
{
    // 1. 验签 + 解析（含金额）
    var channelResult = await _channel.ParseNotifyAsync(rawBody, headers, ct);
    if (!channelResult.Success)
        return NotifyResult.Fail("验签失败");

    // 2. 加载订单
    var paymentOrder = await _repository.GetByIdAsync(channelResult.PaymentOrderId, ct)
        ?? throw new PaymentDomainException("支付订单不存在");

    // 3. 金额强校验（关键）
    if (channelResult.Amount != paymentOrder.Amount.Amount)
    {
        _logger.LogWarning(
            "支付回调金额不一致 OrderId={OrderId} Expected={Expected} Actual={Actual}",
            paymentOrder.Id, paymentOrder.Amount.Amount, channelResult.Amount);
        return NotifyResult.Fail("金额不一致");  // 返回 FAIL，不调用 MarkSucceeded
    }

    // 4. 金额一致才标记成功（聚合内部再次校验兜底）
    paymentOrder.MarkSucceeded(channelResult.Amount, channelResult.TradeNo, ct);
    await _unitOfWork.SaveEntitiesAsync(ct);
    return NotifyResult.Success();
}
```

**反例（禁止写法）：**

```csharp

```

### 10.6 优惠券锁定流程

下单选中优惠券时，应用层必须通过 `IPromotionAntiCorruptionService.LockCouponAsync(userId, couponId, orderId)` 在订单创建事务内锁定选定券；支付成功核销、订单取消释放，形成完整闭环。并发锁定由 `UserCoupon` 聚合根状态机保证互斥。

**核心规范：**

1. 下单选用优惠券时，应用层必须在 `CalculateDiscountAsync` 之后立即调用 `LockCouponAsync(userId, couponId, orderId)`，将券由 `Unused` 锁定为 `Locked` 并记录 `LockedOrderId`。
2. 锁定调用失败（远程异常 / 非 2xx / 超时）必须抛领域异常并回滚订单创建，禁止吞异常继续创建订单。
3. `UserCoupon` 聚合根状态机保证并发互斥：仅 `Unused` 状态可锁定为 `Locked`，并发锁定仅一个成功，另一个抛"优惠券已被占用"。
4. 支付成功由 `OrderPaidEventConsumer` 通过 `GetByLockedOrderIdAsync(orderId)` 命中券并核销为 `Used`。
5. 订单取消由防腐层 `ReleaseCouponsAsync` 释放为 `Unused`，失败抛异常或写入"待释放券"补偿表由后台任务重试。
6. 历史数据迁移：扫描 `Unused` 但已关联订单的券，回填 `LockedOrderId`（脚本：`scripts/migrations/promotion-usercoupon-unique-index-backfill.sql`）。

**代码示例 — 下单锁定 + 状态机：**

```csharp

    {
        await _promotionAcl.LockCouponAsync(cmd.UserId, cmd.CouponId.Value, orderId, ct);
    }

    var order = Order.Create(...);
    // ... 库存预占、保存 ...
}

// 领域层 - UserCoupon 聚合状态机

        throw new PromotionDomainException("优惠券已被占用", "COUPON_ALREADY_LOCKED");
    Status = UserCouponStatus.Locked;
    LockedOrderId = orderId;
```

### 10.7 InternalApiKey 安全默认

`InternalAuth:ApiKey` 必须在生产环境（非 Development）启动时校验非空，为空直接抛异常阻止启动（fail-closed）；ApiKey 比较使用 timing-safe 常数时间比较；internal 路由匹配精确到 `/internal` 或 `/internal/` 前缀。

**核心规范：**

1. 生产环境（`!hostEnvironment.IsDevelopment()`）启动时若 `InternalAuth:ApiKey` 为空，必须抛 `InvalidOperationException` 阻止启动，禁止 fail-open 默认放行。
2. 各 BC `Program.cs` 启动时调用 `EnsureInternalApiKeyConfigured(hostEnvironment, configuration)` 扩展方法校验配置。
3. ApiKey 比较使用 `CryptographicOperations.FixedTimeEquals` 常数时间比较，禁止 `==` 或 `string.Equals` 字符串比较（防时序攻击）。
4. internal 路由匹配必须精确：`path == "/internal" || path.StartsWith("/internal/", StringComparison.OrdinalIgnoreCase)`，禁止 `StartsWith("/internal")`（会误匹配 `/internalinfo` 等业务路径）。
5. 中间件层运行时兜底：ApiKey 缺失时返回 500，不泄露内部端点细节。

**代码示例 — 启动校验 + timing-safe + 路由匹配：**

```csharp
// 启动校验（fail-closed）
public static void EnsureInternalApiKeyConfigured(
    IHostEnvironment env, IConfiguration config)
{
    if (!env.IsDevelopment() && string.IsNullOrWhiteSpace(config["InternalAuth:ApiKey"]))
    {
        throw new InvalidOperationException(
            "生产环境必须配置 InternalAuth:ApiKey，服务拒绝启动");
    }
}

// 中间件 - 路由精确匹配 + timing-safe 比较
public async Task InvokeAsync(HttpContext context)
{
    var path = context.Request.Path.Value!;
    const string prefix = "/internal";

    // 精确前缀匹配（禁止 StartsWith("/internal")）
    var isInternal = path == prefix
        || path.StartsWith(prefix + "/", StringComparison.OrdinalIgnoreCase);
    if (!isInternal) { await _next(context); return; }

    // timing-safe 比较
    var expected = Encoding.UTF8.GetBytes(_options.ApiKey);
    var provided = Encoding.UTF8.GetBytes(context.Request.Headers["X-Internal-Api-Key"].ToString());
    if (provided.Length == 0 || !CryptographicOperations.FixedTimeEquals(expected, provided))
    {
        context.Response.StatusCode = 500;
        return;
    }
    await _next(context);
}
```

### 10.8 Outbox 两阶段标记

Outbox 发布必须采用两阶段标记（`Pending → Publishing → Processed`）防止重复发布；重启扫描 `Publishing` 超时消息依赖下游幂等兜底；下游消费者必须幂等。

**核心规范：**

1. `OutboxMessage` 状态枚举必须包含 `Pending`、`Publishing`、`Processed` 三态，禁止直接 `Pending → Processed` 跳跃。
2. 发布流程：事务内置 `MarkAsPublishing()` 提交 → 发布到 MQ → `MarkAsProcessed()` 提交，两阶段分离。
3. MQ 发布失败：消息回退 `Pending` 并 `RetryCount++`，下次轮询重试；超 `MaxRetryCount` 转入 `DeadLetter`。
4. 重启扫描 `Publishing` 超时消息（默认 5 分钟 `StalePublishingTimeout`），回退为 `Pending` 重新发布。
5. 下游消费者必须幂等，依赖 `IIdempotencyStore` 兜底重复消息（应对 Outbox 重发场景）。
6. 类型解析使用 `FullName` + 自定义 `IOutboxEventTypeResolver`，兼容 BC 版本升级（旧 AQN 失效时按 FullName 跨程序集解析）。

**代码示例 — 两阶段发布：**

```csharp
public async Task PublishSingleAsync(Guid messageId, CancellationToken ct)
{
    // 阶段一：标记 Publishing 并提交（独立事务）
    using (var tx1 = await _db.Database.BeginTransactionAsync(ct))
    {
        var msg = await _db.OutboxMessages.FindAsync(messageId);
        msg.MarkAsPublishing();  // Pending → Publishing
        await _db.SaveChangesAsync(ct);
        await tx1.CommitAsync(ct);
    }

    // 阶段二：发布到 MQ
    try
    {
        var evt = DeserializeEvent(msg);
        await _eventBus.PublishAsync(evt, ct);

        msg.MarkAsProcessed();  // Publishing → Processed
        await _db.SaveChangesAsync(ct);
    }
    catch (Exception ex)
    {
        msg.ResetToPending();   // Publishing → Pending
        msg.IncrementRetry();
        await _db.SaveChangesAsync(ct);
        throw;
    }
}

// 重启扫描超时 Publishing
public async Task RecoverStalePublishingAsync(CancellationToken ct)
{
    var stale = await _db.OutboxMessages
        .Where(m => m.Status == OutboxStatus.Publishing
                 && m.PublishingStartedAt < DateTime.UtcNow.Subtract(_staleTimeout))
        .ToListAsync(ct);
    foreach (var msg in stale) msg.ResetToPending();
    await _db.SaveChangesAsync(ct);
}
```

**反例（禁止写法）：**

```csharp

await _db.SaveChangesAsync(ct);
// 若 PublishAsync 后、SaveChangesAsync 前崩溃 → 状态丢失，重启后重复发布且无幂等兜底
```

### 10.9 防腐层显式错误传播

防腐层（ACL）服务在远程调用失败时必须显式抛领域异常，禁止静默吞异常返回默认值掩盖数据不一致；`CartPriceService` 失败必须标记"价格加载失败"而非返回 0 元。

**核心规范：**

1. 防腐层（积分冻结/确认/释放、优惠券释放、促销计算等）远程调用失败必须显式抛领域异常（如 `OrderDomainException`）或返回显式失败结果，禁止 `catch` 吞异常返回默认值。
2. 关键操作失败必须阻断业务流程：积分冻结失败阻止下单、优惠券释放失败抛异常或写补偿表、促销计算失败不下单（不按 0 优惠兜底）。
3. `CartPriceService` 失败必须抛 `CartDomainException` 或在购物车项标记 `PriceUnavailable=true` 并禁用结算，禁止返回空集合掩盖失败或展示 0 元价格。
4. 调用方（应用层）捕获领域异常后按 spec 处理：单组下单回滚已预占库存、多组下单触发 Saga 补偿。
5. 防腐层降级时除抛异常外，记录 Prometheus 指标（`anticorruption_failure_total{service,operation}`）与结构化日志，便于监控发现下游故障。
6. 用户主动取消（`OperationCanceledException`）必须向上传播，不得包装为业务异常。

**代码示例 — 显式抛异常 + 指标记录：**

```csharp
public async Task FreezeAsync(Guid userId, decimal amount, Guid orderId, CancellationToken ct)
{
    try
    {
        var resp = await _httpClient.PostAsJsonAsync(
            "/api/points/freeze", new { userId, amount, orderId }, ct);

    }

    catch (Exception ex)

        throw new OrderDomainException($"积分冻结失败: {ex.Message}", "POINTS_FREEZE_FAILED");
    }
}

// CartPriceService 失败标记

    {
        return new CartItemDto(item.Id, item.SkuId, item.Name,
            UnitPrice: null, PriceUnavailable: true);  // 禁用结算，不展示 0 元
    }
```

### 10.10 集成事件消费幂等强制

`IntegrationEventConsumerBase` 的幂等方法必须为 `abstract`，所有 Consumer 子类必须注入 `IIdempotencyStore` 实现去重；新增 Consumer 未注入者 PR 不得合并。

**核心规范：**

1. `IntegrationEventConsumerBase` 的幂等抽象方法（`IsProcessedAsync` / `MarkAsProcessedAsync`）必须为 `abstract`，禁止提供空默认实现（virtual + return false）。
2. 所有 Consumer 子类必须通过构造函数注入 `IIdempotencyStore`，将 base 构造函数首位传入，不得省略。
3. 消费流程严格三步：`IsProcessedAsync(eventId)` 命中跳过 → `HandleAsync` 业务处理 → `MarkAsProcessedAsync(eventId)` 标记完成。
4. `RedisIdempotencyStore` 使用 `SET NX + 24h TTL`（key 前缀 `evt:processed`）保证原子性与自动过期。
5. 新增 Consumer 时强制审计：未注入 `IIdempotencyStore` 的子类 PR 不得合并；既有 `RedisIntegrationEventConsumerBase` 已合并入基类，禁止再分裂。
6. 业务幂等（如订单状态机校验"已支付"）与事件幂等（`IIdempotencyStore`）双保险，任一命中即跳过。

**代码示例 — 强制注入 + 三步消费：**

```csharp
public abstract class IntegrationEventConsumerBase<TEvent>
{
    private readonly IIdempotencyStore _idempotencyStore;

    protected IntegrationEventConsumerBase(
        IIdempotencyStore idempotencyStore,  // 强制注入
        ILogger logger)
    {
        _idempotencyStore = idempotencyStore;
        _logger = logger;
    }

    public async Task Consume(ConsumeContext<TEvent> context)
    {
        var evt = context.Message;

        // 步骤 1：幂等去重
        if (await _idempotencyStore.IsProcessedAsync(evt.EventId, context.CancellationToken))
        {
            _logger.LogDebug("重复事件已处理 EventId={EventId}", evt.EventId);
            return;
        }

        // 步骤 2：业务处理
        await HandleAsync(evt, context.CancellationToken);

        // 步骤 3：标记完成
        await _idempotencyStore.MarkAsProcessedAsync(evt.EventId, context.CancellationToken);
    }

    protected abstract Task HandleAsync(TEvent evt, CancellationToken ct);
}

// 具体实现
public class PaymentSucceededConsumer : IntegrationEventConsumerBase<PaymentSucceededIntegrationEvent>
{
    public PaymentSucceededConsumer(
        IIdempotencyStore idempotencyStore,  // 强制注入
        IOrderRepository orderRepository,
        IUnitOfWork unitOfWork,
        ILogger<PaymentSucceededConsumer> logger)
        : base(idempotencyStore, logger) { }

    protected override async Task HandleAsync(
        PaymentSucceededIntegrationEvent evt, CancellationToken ct)
    {
        var order = await _orderRepository.GetByOrderNoAsync(evt.BusinessOrderNo, ct)
            ?? throw new OrderDomainException("订单不存在");
        order.MarkAsPaid(evt.PaymentOrderId, ...);  // 业务幂等兜底
        await _unitOfWork.SaveEntitiesAsync(ct);
    }
}
```

**反例（禁止写法）：**

```csharp
// 禁止：幂等方法为 virtual 提供空实现，子类不强制实现
public virtual Task<bool> IsProcessedAsync(Guid eventId)
    => Task.FromResult(false);  // 重复事件重复执行业务

// 禁止：Consumer 不注入 IIdempotencyStore
public class MyConsumer : IntegrationEventConsumerBase<MyEvent>
{
    public MyConsumer(IOrderRepository repo) : base(???) { }  // 编译错误或 null 注入
    // 重复事件导致重复扣库存、重复核销券
}

// 禁止：仅业务幂等无事件幂等（事件 ID 变更或事件重发场景失效）
```

### 11.4 文件存储适配

```csharp
// 共享内核 - 文件存储抽象
namespace SharedKernel.Storage;

public interface IFileStorageService
{
    Task<FileUploadResult> UploadAsync(Stream stream, string fileName,
        string contentType, string category, CancellationToken ct = default);
    Task<Stream> DownloadAsync(string fileUrl, CancellationToken ct = default);
    Task DeleteAsync(string fileUrl, CancellationToken ct = default);
    bool ValidateUrl(string fileUrl);
    Task<bool> ExistsAsync(string fileUrl, CancellationToken ct = default);
}

public record FileUploadResult(string Url, long Size, string ContentType);

// 基础设施层 - 本地文件存储实现
namespace Ordering.Infrastructure.Storage;

public class LocalFileStorageService : IFileStorageService
{
    private readonly LocalStorageOptions _options;
    private readonly ILogger<LocalFileStorageService> _logger;

    public LocalFileStorageService(IOptions<LocalStorageOptions> options,
        ILogger<LocalFileStorageService> logger)
    {
        _options = options.Value;
        _logger = logger;
    }

    public async Task<FileUploadResult> UploadAsync(Stream stream, string fileName,
        string contentType, string category, CancellationToken ct = default)
    {
        if (stream.Length > _options.MaxFileSize)
            throw new DomainException($"文件大小超过上限 {_options.MaxFileSize} 字节");

        var safeCategory = SanitizeCategory(category);
        var ext = Path.GetExtension(fileName);
        var storedName = $"{safeCategory}/{Guid.NewGuid()}{ext}";
        var fullPath = Path.Combine(_options.BasePath, storedName);

        Directory.CreateDirectory(Path.GetDirectoryName(fullPath)!);

        using var fs = File.Create(fullPath);
        await stream.CopyToAsync(fs, ct);

        var url = $"{_options.BaseUrl}/{storedName}";
        _logger.LogInformation("文件上传成功 Url={Url} Size={Size}", url, stream.Length);

        return new FileUploadResult(url, stream.Length, contentType);
    }

    public Task<Stream> DownloadAsync(string fileUrl, CancellationToken ct = default)
    {
        if (!ValidateUrl(fileUrl))
            throw new DomainException("非法的文件 URL");

        var relativePath = fileUrl.Replace(_options.BaseUrl + "/", "");
        var fullPath = Path.Combine(_options.BasePath, relativePath);

        if (!File.Exists(fullPath))
            throw new DomainException("文件不存在");

        return Task.FromResult<Stream>(File.OpenRead(fullPath));
    }

    public Task DeleteAsync(string fileUrl, CancellationToken ct = default)
    {
        if (!ValidateUrl(fileUrl))
            return Task.CompletedTask;

        var relativePath = fileUrl.Replace(_options.BaseUrl + "/", "");
        var fullPath = Path.Combine(_options.BasePath, relativePath);

        if (File.Exists(fullPath))
            File.Delete(fullPath);

        return Task.CompletedTask;
    }

    public bool ValidateUrl(string fileUrl)
        => fileUrl.StartsWith(_options.BaseUrl);

    public Task<bool> ExistsAsync(string fileUrl, CancellationToken ct = default)
    {
        if (!ValidateUrl(fileUrl))
            return Task.FromResult(false);

        var relativePath = fileUrl.Replace(_options.BaseUrl + "/", "");
        var fullPath = Path.Combine(_options.BasePath, relativePath);
        return Task.FromResult(File.Exists(fullPath));
    }

    private static string SanitizeCategory(string category)
    {
        var allowed = new[] { "avatar", "product", "review", "aftersales", "credential" };
        return allowed.Contains(category) ? category : "misc";
    }
}
```

### 12.4 Redis 缓存与防穿透/防雪崩

**核心规范：**

1. Redis 缓存热点数据（商品详情、库存预占、积分余额）。
2. 布隆过滤器防缓存穿透。
3. 随机过期时间防雪崩。

```csharp
namespace SharedKernel.Caching;

public class CacheService : ICacheService
{
    private readonly IDatabase _redis;
    private readonly IBloomFilter _bloomFilter;

    public CacheService(IConnectionMultiplexer redis, IBloomFilter bloomFilter)
    {
        _redis = redis.GetDatabase();
        _bloomFilter = bloomFilter;
    }

    /// <summary>
    /// 获取缓存，带布隆过滤器防穿透与随机过期防雪崩
    /// </summary>
    public async Task<T?> GetOrSetAsync<T>(
        string key, Func<Task<T?>> factory,
        TimeSpan? expiry = null, CancellationToken ct = default) where T : class
    {
        // 1. 尝试从缓存读取
        var cached = await _redis.StringGetAsync(key);
        if (cached.HasValue)
            return JsonSerializer.Deserialize<T>(cached!);

        // 2. 布隆过滤器校验，防穿透
        if (!_bloomFilter.MightContain(key))
            return null; // 不存在的 key 直接返回

        // 3. 从数据源加载
        var value = await factory();
        if (value == null)
        {
            // 缓存空值，短过期
            await _redis.StringSetAsync(key, "", TimeSpan.FromMinutes(2));
            return null;
        }

        // 4. 写入缓存，随机过期时间防雪崩
        var actualExpiry = expiry ?? TimeSpan.FromMinutes(10);
        var jitter = TimeSpan.FromSeconds(Random.Shared.Next(30, 120));
        await _redis.StringSetAsync(key, JsonSerializer.Serialize(value), actualExpiry + jitter);

        return value;
    }

    public async Task<T?> GetAsync<T>(string key, CancellationToken ct = default) where T : class
    {
        var value = await _redis.StringGetAsync(key);
        return value.HasValue ? JsonSerializer.Deserialize<T>(value!) : null;
    }

    public async Task SetAsync<T>(string key, T value, TimeSpan? expiry = null, CancellationToken ct = default)
    {
        var actualExpiry = expiry ?? TimeSpan.FromMinutes(10);
        var jitter = TimeSpan.FromSeconds(Random.Shared.Next(30, 120));
        await _redis.StringSetAsync(key, JsonSerializer.Serialize(value), actualExpiry + jitter);
    }

    public async Task RemoveAsync(string key, CancellationToken ct = default)
    {
        await _redis.KeyDeleteAsync(key);
    }
}
```

### 12.5 Redis Lua 脚本原子操作

库存预占、积分余额等强一致操作使用 Redis Lua 脚本原子完成。

```csharp
namespace Ordering.Infrastructure.Caching;

/// <summary>
/// 库存预占缓存服务，使用 Redis Lua 脚本保证"判余量 + 扣减 + 记录预占"原子性。
/// </summary>
public class StockReservationCacheService
{
    private readonly IDatabase _redis;
    private const string ReserveLuaScript = @"
        local stockKey = KEYS[1]
        local reservationKey = KEYS[2]
        local orderId = ARGV[1]
        local quantity = tonumber(ARGV[2])

        local available = tonumber(redis.call('GET', stockKey) or '0')
        if available < quantity then
            return 0
        end

        redis.call('DECRBY', stockKey, quantity)
        redis.call('HSET', reservationKey, orderId, quantity)
        return 1
    ";

    private readonly LoadedLuaScript _loadedScript;

    public StockReservationCacheService(IConnectionMultiplexer redis)
    {
        _redis = redis.GetDatabase();
        var server = redis.GetServer(redis.GetEndPoints()[0]);
        _loadedScript = LuaScript.Prepare(ReserveLuaScript);
    }

    /// <summary>
    /// 原子预占库存
    /// </summary>
    public async Task<bool> ReserveStockAsync(Guid skuId, Guid orderId, int quantity, CancellationToken ct = default)
    {
        var stockKey = $"stock:available:{skuId}";
        var reservationKey = $"stock:reserved:{skuId}";

        var parameters = new
        {
            stockKey = stockKey,
            reservationKey = reservationKey,
            orderId = orderId.ToString(),
            quantity = quantity
        };

        var result = (long)await _loadedScript.EvaluateAsync(_redis, parameters);
        return result == 1;
    }
}
```

## 13 测试编码规范

### 13.1 单元测试规范

**核心规范：**

1. 测试项目命名为 `{BC}.{层}.Tests`，如 `Ordering.Domain.Tests`。
2. 测试方法命名采用 `Method_Scenario_ExpectedResult` 模式。
3. 领域层单元测试不依赖任何外部资源（数据库、缓存、MQ）。
4. 使用 xUnit + Moq + FluentAssertions 技术栈。
5. 每个聚合根方法至少覆盖正常路径、边界条件、异常路径三种场景。

**代码示例 — 领域层单元测试：**

```csharp
namespace Ordering.Domain.Tests.Aggregates;

public class OrderTests
{
    private static Order CreateValidOrder()
    {
        var items = new List<OrderItem>
        {
            OrderItem.Create(Guid.NewGuid(), Guid.NewGuid(),
                ProductSnapshot.Create("测试商品", "规格A", "http://img.example.com/1.jpg"),
                Money.Create(99.00m, "CNY"), 2)
        };

        var address = AddressSnapshot.Create("张三", "13800138000",
            "广东省", "深圳市", "南山区", "科技园路1号");

        return Order.Create(Guid.NewGuid(), "ORD202607100001",
            Guid.NewGuid(), Guid.NewGuid(), OrderType.ProductOrder,
            items, address, Money.Create(10.00m, "CNY"),
            DateTime.UtcNow.AddMinutes(30));
    }

    [Fact]
    public void Create_WithValidItems_ReturnsOrderInPendingPaymentStatus()
    {
        // Arrange & Act
        var order = CreateValidOrder();

        // Assert
        order.Status.Should().Be(OrderStatus.PendingPayment);
        order.Items.Should().HaveCount(1);
        order.TotalAmount.Amount.Should().Be(208.00m); // 99*2 + 10 freight
        order.DomainEvents.Should().ContainSingle(e => e is OrderCreatedEvent);
    }

    [Fact]
    public void Create_WithEmptyItems_ThrowsDomainException()
    {
        // Arrange
        var items = new List<OrderItem>();
        var address = AddressSnapshot.Create("张三", "13800138000",
            "广东省", "深圳市", "南山区", "科技园路1号");

        // Act
        var act = () => Order.Create(Guid.NewGuid(), "ORD001",
            Guid.NewGuid(), Guid.NewGuid(), OrderType.ProductOrder,
            items, address, Money.Create(10.00m, "CNY"),
            DateTime.UtcNow.AddMinutes(30));

        // Assert
        act.Should().Throw<OrderDomainException>()
            .WithMessage("*至少包含一个订单行*");
    }

    [Fact]
    public void MarkAsPaid_WhenStatusIsPendingPayment_TransitionsToPaidStatus()
    {
        // Arrange
        var order = CreateValidOrder();
        var paymentId = Guid.NewGuid();
        var paidAt = DateTime.UtcNow;
        var tradeNo = "TRADE001";

        // Act
        order.MarkAsPaid(paymentId, PaymentMethod.WeChat, paidAt, tradeNo);

        // Assert
        order.Status.Should().Be(OrderStatus.Paid);
        order.PaymentId.Should().Be(paymentId);
        order.PaidAt.Should().Be(paidAt);
        order.TradeNo.Should().Be(tradeNo);
        order.DomainEvents.Should().ContainSingle(e => e is OrderPaidEvent);
    }

    [Fact]
    public void MarkAsPaid_WhenStatusIsAlreadyPaid_ThrowsDomainException()
    {
        // Arrange
        var order = CreateValidOrder();
        order.MarkAsPaid(Guid.NewGuid(), PaymentMethod.WeChat, DateTime.UtcNow, "TRADE001");

        // Act
        var act = () => order.MarkAsPaid(Guid.NewGuid(), PaymentMethod.Alipay, DateTime.UtcNow, "TRADE002");

        // Assert
        act.Should().Throw<OrderDomainException>()
            .WithMessage("*不可标记为已支付*");
    }

    [Fact]
    public void Cancel_WhenStatusIsPaid_ThrowsDomainException()
    {
        // Arrange
        var order = CreateValidOrder();
        order.MarkAsPaid(Guid.NewGuid(), PaymentMethod.WeChat, DateTime.UtcNow, "TRADE001");

        // Act
        var act = () => order.Cancel("用户取消", "user");

        // Assert
        act.Should().Throw<OrderDomainException>()
            .WithMessage("*不可取消*");
    }
}
```

### 13.2 集成测试规范

**核心规范：**

1. 集成测试使用 Testcontainers 启动真实数据库、Redis、RabbitMQ 容器。

## 14 Git 提交规范

### 14.1 提交消息格式

采用 Conventional Commits 规范，格式为：

```
<type>(<scope>): <subject>

<body>

<footer>
```

### 14.2 提交类型（type）

| 类型 | 说明 | 示例 |
|-|-|-|
| `feat` | 新功能 | `feat(order): 新增订单超时自动取消功能` |
| `fix` | Bug 修复 | `fix(payment): 修复支付回调验签失败问题` |
| `refactor` | 重构（不改变功能） | `refactor(order): 提取订单金额计算逻辑到领域服务` |
| `perf` | 性能优化 | `perf(product): 优化商品搜索 ES 查询性能` |
| `docs` | 文档变更 | `docs: 更新编码规范文档` |
| `test` | 测试相关 | `test(order): 新增订单聚合根单元测试` |
| `chore` | 构建/工具/依赖 | `chore: 升级 EF Core 至 10.0.0` |
| `ci` | CI/CD 配置 | `ci: 添加 Docker 镜像构建流水线` |
| `style` | 代码格式（不影响逻辑） | `style: 统一缩进为 4 空格` |
| `build` | 构建系统或依赖变更 | `build: 添加 SharedKernel 项目引用` |

### 14.3 作用域（scope）

作用域对应限界上下文或共享模块，使用小写英文：

| 作用域 | 对应上下文 |
|-|-|
| `user` | 用户与认证授权域（BC1） |
| `product` | 商品域（BC2） |
| `cart` | 购物车域（BC3） |
| `order` | 订单与交易域（BC4） |
| `promotion` | 促销域（BC5） |
| `review` | 评价与售后域（BC6） |
| `points` | 积分与会员域（BC7） |
| `payment` | 支付集成域（BC8） |
| `notification` | 消息通知域（BC9） |
| `seller` | 卖家与店铺管理域（BC10） |
| `system` | 系统管理域（BC11） |
| `shared` | 共享内核 |
| `infra` | 基础设施跨上下文 |

### 14.4 提交消息规范

**核心规范：**

1. `subject` 以中文描述，简明扼要，不超过 50 个字符，结尾不加句号。
2. `body` 说明"为什么"而非"做了什么"，每行不超过 72 个字符。
3. `footer` 用于标记 Breaking Change（`BREAKING CHANGE:`）或关联 Issue（`Closes #123`）。
4. 一个提交只做一件事，不混合多个无关变更。

**示例：**

```
feat(order): 新增订单超时自动取消功能

通过 MQ 延迟消息驱动订单超时取消，订单创建时投递 30 分钟
延迟消息，消息到达后检查订单状态并调用 Cancel 方法。

Closes #142
```

```
fix(payment): 修复支付宝回调验签失败问题

支付宝回调签名编码与预期不一致导致验签失败，
统一使用 UTF-8 编码处理回调报文。

BREAKING CHANGE: 回调验签接口签名变更，消费方需同步更新
```

```
refactor(shared): 将 Money 值对象运算方法统一为实例方法

原静态方法调用方式不一致，统一为实例方法链式调用，
提升可读性与一致性。
```

### 14.5 分支命名规范

| 分支类型 | 命名规则 | 示例 |
|-|-|-|
| 主分支 | `main` | `main` |
| 开发分支 | `develop` | `develop` |
| 功能分支 | `feat/{scope}-{description}` | `feat/order-timeout-cancel` |
| 修复分支 | `fix/{scope}-{description}` | `fix/payment-sign-verify` |
| 发布分支 | `release/{version}` | `release/v2.4.0` |
| 热修复分支 | `hotfix/{scope}-{description}` | `hotfix/order-amount-calc` |

### 14.6 分支策略与合并规范

1. `main` 分支始终可部署，合并须经过代码审查与 CI 通过。
2. 功能分支从 `develop` 拉出，完成后提交 Pull Request 合并回 `develop`。
3. 发布时从 `develop` 拉出 `release` 分支，验证通过后合并到 `main` 并打标签。
4. 热修复从 `main` 拉出，修复后同时合并到 `main` 和 `develop`。
5. Pull Request 须关联 Issue，描述变更内容与测试方案。
6. 合并前须确保全部单元测试与集成测试通过。
